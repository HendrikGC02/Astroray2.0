# Blender integration: sync, viewport, node semantics, passes, settings

Distilled from the v1 research notes. v1 was a Blender render addon over a C++/CUDA engine. Everything below is
written so it can be read without v1. "Cycles" is cited as the source of Blender semantics and as a reference
algorithm set (Apache-2.0 unless stated), not as a parity target. Where the v1 notes were thin, this file says so.

## Established findings

### Process, packaging and threading (host-side lessons)

- **A stale loaded module looks like a missing symbol.** A cluster of "attribute missing on the engine module" errors was a module Blender had loaded and locked before the reinstall; the installed binary and Python files were byte-identical to the build (matching SHA-256 prefix), and shadow directories named like `.~stale~NNNN` showed Blender had held the old binary open. Remedy is process: quit Blender before reinstalling, and stamp the build into the module so register-time can detect a mismatch. Make build identity observable at runtime.
- **"Presented" is not "functional".** Many UI controls were wired to dead branches (a hard-coded `if False`), to setters that were stored but never read, or to enum values the setter rejected. The audit found 31 of 37 engine bindings called from the addon, 6 not. Rule: every UI-visible control needs a test that moving it changes a render (or is greyed out with an INFO line); a control that is wired but ignored is an error, unwired is info.
- **Five irreducible failure primitives** came out of reducing 17 symptoms / 9 root causes: (1) build/process integrity not observable; (2) the sync contract pushes device state but never re-parses Blender state; (3) UI features wired to dead paths; (4) camera re-derived instead of taken from Blender; (5) GPU path not equivalent to CPU. A guard for (1) is cheap (~0.5 day); (3)+(4) next; (2) next.
- **Camera: take it from Blender, do not re-derive it.** A hard-coded 32 mm sensor versus the datablock's 36 mm gave a wrong field of view; viewport FOV must come from the region's `rv3d.window_matrix`, F12 from the camera datablock. A regression test comparing against Blender's own projection is the durable fix. Orthographic: origin on the image plane with constant direction (PBRT v4); Blender's view plane spans `ortho_scale` along the sensor-fit axis (AUTO = the larger image dimension) and `shift` is multiplied by `ortho_scale`; thin lens focuses at the focus distance along the view axis; Cycles' ortho aperture radius is 1/(2*fstop). Acceptance data: Blender's `world_to_camera_view` / `calc_matrix_camera` for landscape and portrait grids.
- **OpenMP-style worker threads that call back into Python deadlock.** The addon "OpenMP hangs Blender" rule was not a toolchain defect: a progress callback acquired the GIL from a worker thread while the master held it in a barrier (circular wait). Fix: release the GIL around the whole native CPU render. Forcing single-core CPU rendering to dodge it cost ~6x. The test suite never hit it because it passed no callback; test with the real callback installed. Open: a GUI F12 spot-check (headless ran 400 tiles cleanly).
- **Shipped native module must carry its runtime.** A module built against an OpenMP runtime Blender does not bundle needs that DLL copied next to it at install time.
- **Cancellation needs a checkpoint, not a thread.** The progress callback's return value was being discarded; the GPU path had no cancel argument at all; viewport frames passed no callback, so cancel could land only at frame boundaries. The cancel full-stop floor equals the cost of one native render call, so cancel latency is set by the length of the longest uninterruptible unit. Fix: callback returns a bool, a host-side atomic cancel flag polled between bounded GPU work units (a per-frame sub-pass budget, default 4), and honour Blender's `test_break()`. Ordinary completion must stay bit-identical when no callback/flag is supplied. The accumulator must discard a chunk when the render key changes and keep it when refining under the same key.
- **Release of the GIL alone does not decouple the UI** while the main thread sits inside a synchronous render call. The Cycles-style fix is a worker thread; the Blender API stays on the main thread.

### Depsgraph sync and viewport

- **Dispatch on depsgraph updates per datablock domain** (Object transform vs geometry, Mesh, Material, NodeTree, Image, World, Light, Scene), as Cycles' BlenderSync does. Material-only edits skip geometry and BVH work; idle frames cost ~nothing; final render stays a full export. The depsgraph is datablock-grained (Blender issue #121019), so per-property incremental granularity is a non-goal.
- **Update order is fixed, not iteration order:** environment, materials, lights, geometry, transforms. Image cache keys should include size, depth, colour space and a reload counter. World importance-CDF rebuild should be gated on image/strength/rotation changes only.
- **BVH policy (from Cycles geometry.cpp:274-280):** transform-only edit means refit; topology change means rebuild the bottom-level structure; object add/remove means rebuild the top level; OptiX/Metal forbid refit when offsets change; a layout change rebuilds everything. Refit quality degrades when objects move far from their build position.
- **Sync order for viewport updates in v1 phases:** instrument first (no behaviour change), then split upload into geometry/materials/lights/environment, then depsgraph-driven dispatch. Proposed acceptance gates: idle <= 5 ms; material drag <= 30% of baseline; transform drag <= 50% of baseline.
- **Real bottlenecks of conversion** were per-triangle host-binding calls (estimate ~150-400 ms per 100k triangles, never measured) and a whole-scene structure rebuild on every transform edit. Fixes proposed: batched NumPy geometry upload, two-level instancing (shared bottom-level structures), an exporter with per-domain caches and change bit-flags, non-mesh geometry converted to mesh.
- **The Blender node tree should be the source of truth.** v1 reinvented coordinate spaces and procedurals the shared node tree already defines; recommendation was to inherit node-tree semantics and evaluate in the kernel, with project-specific nodes additive.
- **Colour management: output linear and let Blender apply the view transform;** no in-engine tonemapper (LuxCore deviates). The GPU `view_draw` colour-management API needed checking against the current `gpu` module.
- **Cycles' viewport model (reference):** `view_draw` blits; scene sync runs under a scene mutex; a new reset supersedes the running session rather than joining it; `try_lock` skip is the fallback.

### Viewport threading and presentation (design that converged after four reviewed revisions)

- **Direction:** a Python worker thread drives the (GIL-released) native render; the Blender API never leaves the main thread. Chosen over a native session thread on spike evidence.
- **Skip-upload does not make render a reader.** "Skip upload" only skipped acceleration-structure building; the render still re-uploaded GPU scene state, so render is a writer of process-global device state. Hence one process-wide admission token must cover every renderer mutation, not just render. (Rewrite note: process-global device state is itself the root problem; see Design ideas.)
- **Commit on the main thread under the token, then the worker renders** and extracts passes only. Results pass through an immutable-buffer reference swap, pumped by a main-thread `bpy.app.timers` timer. Frames go through a bounded latest-frame mailbox of depth 1; control and error notifications use a separate queue and are never dropped. Every notification carries a generation tag; frames validate against the current desired generation, idle/exited against the in-flight generation, errors always for the current epoch.
- **Non-blocking edits** with deferred commit of the newest generation only; coalesce dirty domains; world node-tree edits classify as environment.
- **Shutdown must wait for acknowledged worker exit,** with strong-reference quarantine for workers that never ack. A daemon thread with a timeout is unsafe to release; a timed join blocks the UI for its timeout.
- **F12 pause gate:** raise gate, drain all viewports, take the token before final-render construction, release in `finally`. If any viewport fails to drain in 5 s, F12 does not render.
- **Denoise is settled-only and runs on the accumulated image;** denoising a fresh single chunk throws the accumulation away. Recommended: a native denoise over the accumulated colour/albedo/normal buffers rather than a full re-render at settle.
- **Accumulate under a render key.** Camera, size and material generation change the key; refinement under the same key accumulates. Latch the sync/async path per exporter and only re-read it with no worker render in flight.
- **Present before refinement commit; start coarse** when the first full-resolution unit exceeds roughly half the latency budget; re-aim a same-size camera instead of reconstructing it (112 ms down to 0.02 ms per commit).
- **Copy path matters:** converting a flat array to a Python list for texture upload cost ~195 ms tail; using `gpu.types.Buffer` cut it to ~0 with a byte-identical texture.
- **Orphan hygiene:** an orphaned worker held the global token because the exporter strong-referenced its engine so the finaliser never fired; fixed with a dead-session reaper. A scene switch that ran two workers into the same device context caused illegal memory access; drain on file load and at exit.
- **Cancel of a long GPU pass is not fixed by a smaller Python chunk;** it needs a poll between bounded GPU work units.
- **Portable principles:** main-thread-only Blender API, immutable publication, generation-tagged handoff, acknowledged shutdown.

### Shader node semantics and per-texel evaluation

- **v1 constant-folded shader graphs.** Any per-texel node after a texture (Color Ramp, MixRGB, Math, Map Range, HSV...) collapsed to a flat value (e.g. grey), because the engine only accepted image textures as per-texel inputs. Unsupported cases must raise a visible degradation entry, never a silent grey.
- **Architecture conclusion after several rounds:** a bounded op-VM (static register file, flat bytecode, compile-time refusal on overflow, Color Ramp baked to a 256-entry table) was a staged compromise because a full Cycles-style SVM interpreter inline in the shade kernel risked register spill. The later decision (lead, 2026-10) was a **shared per-hit graph interpreter in its own graph-eval kernel (never inlined into shade)**, op-VM kept as a small-program lowering, NVRTC JIT possible later on the same IR. Rationale: raising VM bounds does not fix the real causes (per-hit inputs and closure composition). Rejected: inserting Cycles' stack directly in shade (stack traffic dominated), JIT-first, copying Cycles' local-stack memory strategy.
- **Closure composition rules** (graph closures): Mix(A,B,f) propagates weights (1-f) and f, nested multiplicatively; Add passes weight unchanged to both children; physical weights kept separate from sampling probabilities; evaluate spectral closures before summation; Principled kept monolithic. Removing legacy normalisation globally reopens energy failures.
- **Proceduals: evaluate once, for CPU and GPU.** One header shared by host and device; GPU per-hit evaluation, with the baked 3D grid kept only for types without a per-hit path. Bake is lossy: Cycles checker, scale 5, warp sin(k x): pixel mismatch at 64^3 was 3.98/9.39/14.21/25.64% for k = 2/6/12/24 and 1.86/4.62/7.07/15.04% at 128^3; region-mean error stays within 0.6% so region-mean tests do not catch edge aliasing.
- **Bit-exactness caveat:** MSVC `/arch:AVX2 /fp:fast` fuses `100 + hash*100`; 4 of 15 random offsets differ by one ulp, and fractal octaves amplify one ulp to ~1e-4. `-ffast-math` builds are not bit-stable under refactor.
- **Coordinate semantics (Cycles / Blender):** - Mapping POINT: out = location + Rotate_euler(scale * v). Compose the 4x4 on the Blender side (`mathutils.Matrix.LocRotScale`) rather than re-deriving Euler angles in C++. - UV mode passes (u, v, 0) as the 3D point. Normal is signed object-space, no remap. An unconnected Vector input defaults to Generated (Image Texture uses UV). Generated = bbox mapped to [0,1], a per-object affine; zero-size axes forced to 1; Cycles does not clamp Generated. - Object coordinates are the object-local position (inverse of `matrix_world` per hit/vertex); instanced meshes with Object-coordinate materials have to be flattened or carry per-instance transforms. - Affine coordinate chains (Add/Subtract/Multiply/Scale with at most one varying vector, constant Rotate modes, Mapping order) can be folded on the host; non-affine (Sin in the coordinate chain) cannot be baked faithfully and needs a coordinate-side program evaluated per texel.
- **Procedural fixes found against Cycles' kernels:** Musgrave was removed in Blender 4.1 and folded into Noise (roughness = lacunarity^(-dimension), detail = old detail - 1). 1D/2D/4D noise use their own hashes and are not the 3D function evaluated at a point (3D-for-all gave r = 0.003 / -0.12 / 0.09 against Cycles). Fac into a colour socket yields the colour triple. Spherical gradient inversion, radial gradient half-turn offset, Magic outputs RGB, Brick is 3D with per-brick tint, Wave phase density 20/pi (~6.37x). Multifractal and ridged exceed albedo 1 in Cycles; v1 clamped diffuse albedo on purpose (physics over look-matching). Voronoi 1D/2D/4D: 1D hashes the float cell, 2D/4D use PCG2D/PCG4D; F1 uses a distance bound; Distance to Edge has its own fractal wrapper; N-Sphere Radius is not fractal; Distance and Radius are unclamped.
- **Op math tables.** Per-enum formulas for Math, Vector Math (all 30 ops; dot/distance/length broadcast; only used operands read), Mix (modern Mix obeys clamp_factor, legacy MixRGB always clamps), Color Ramp (Ease, Cardinal fc=0.71, B-Spline compile-time only), Separate/Combine, Invert, Gamma, Bright/Contrast, HSV, Map Range, Clamp, Vector Rotate (Euler inverse is the transposed XYZ matrix; negating all angles is wrong; zero axis returns input; axis-angle and single-axis invert negate the angle) were transcribed from Cycles; safe-math helpers (safe_divide, safe_pow, floored modulo, wrap, pingpong, smoothmin) matter at zero/edge inputs. Linked RGBA to scalar uses luminance; VECTOR to scalar uses dot with (1/3,1/3,1/3) per Cycles convert. Minimum useful opcode set ~18.
- **Per-hit inputs (Layer Weight, Fresnel, Geometry Backfacing):** Fresnel and Layer Weight Fresnel use `fresnel_dielectric_cos(dot(wi,N), eta)` with eta flipped on backfacing; Layer Weight Facing is abs(dot) with a blend remap (2b for b<0.5, 0.5/(1-b) otherwise) and f = 1 - pow(f, blend). These cannot run in a texture-only pre-pass, so evaluation needs two contexts (texture-time and hit-time).
- **Attributes:** FLOAT/FLOAT2/FLOAT3/FLOAT4 map to Color/Fac/Alpha in fixed ways (Fac = average(rgb) for RGBA); POINT and CORNER interpolate linearly, FACE is constant, missing gives 0. Object Info Random = random_id * (1/0xFFFFFFFF), random_id = hash_uint2(hash_string(name), 0) for non-instanced objects (hash_string = i*37 + c, lookup3 final); a Cycles 5.2 render of Object Info > Random for three objects gave 0.2948239, 0.1035135, 0.8790834, matching the hash exactly.
- **Light Path node:** Is Camera/Shadow/Diffuse/Glossy/Transmission/Volume read ray visibility; Is Singular/Reflection read path flags; Ray Depth gets +1 for shadow and emission evaluation. Surface bounces clear REFLECT/SINGULAR and set type bits; transparent bounces keep flags; only a material with a transparent lobe counts as transparent, so a dielectric's refraction stays a singular transmission. Mix Shader with a boolean Fac acts as a per-ray closure switch. Camera Ray Length is measured from the near clip. Pointiness: weld colocated vertices, welded normal = normalise(sum of vertex normals), accumulate unit edge directions, raw = acos(clamp(dot(n, mean dir)))/pi, one blur pass, copy to duplicates, interpolate linearly per triangle; a port matched a Cycles 5.2 bake to ~1e-5.
- **Bump and normal maps:** - Cycles bump copies the Height subgraph three times (centre, dx, dy), offsetting the coordinate before Mapping; slope by finite difference; Filter Width default 0.1 of pixel footprint. Formula: Rx = cross(dP.dy, N), Ry = cross(N, dP.dx), det = dot(dP.dx, Rx), surfgrad = (h_x - h_c) Rx + (h_y - h_c) Ry, N' = safe_normalize(filter_width*|det|*N - scale*sign(det)*surfgrad), blended by strength; zero returns N. Coat and sheen use the lifted normal; Output Displacement is converted to bump so they follow it. - An engine without ray differentials has no pixel footprint: use a UV-aligned tangent frame scaled by Distance; it loses derivative-driven antialiasing and keeps sharper slopes on minified textures. NEE using the unperturbed normal means the bumped normal only enters lobe evaluation. - Normal map: n_ts = 2*rgb - 1 (mid-grey zero vector skipped); the frame must be UV-aligned or relief rotates per surface; B = sign * cross(N, T) (green = +B, OpenGL); sign is UV-winding handedness (MikkTSpace); strength = normalise(lerp(N_geom, mapped, clamp(s,0,1))); fallback tangent Lengyel. The normal-map texture is read Linear. - Cycles' bump-terminator correction (Material.cycles.use_bump_map_correction, default True): lift glossy closures toward the shading normal, a microfacet shadowing term on NEE and BSDF samples, and diffuse softening. Measured (Cycles 5.2.0, CPU, 1024 spp): scene 1 0.3979 corrected vs 0.0 off; scene 2 0.54525 vs 0.58521; sun at -10 deg: 0 both. A heuristic `ensure_valid_specular_reflection` has no paper. - Measured wins in a bump comparison: wrong Mapping scale made relief 3x weak; a nearest 1.5-texel forward difference put relief a texel low; Normal Map nearest vs Linear differs 3-6%; a coat at weight 0 matched Cycles within ~1%, the earlier "2x overshoot" was bump leaking into the coat.
- **Image textures:** Cycles filters in encoded sRGB and decodes after, so interpolation order (encoded vs linear) matters. Extension modes REPEAT/EXTEND/MIRROR/CLIP; Cycles "Smart" equals Cubic; Cubic is a uniform B-spline (not Catmull-Rom), so it smooths and does not reproduce texel values; mip/tiled sampling only runs with the Texture Cache option on (opt-in in 5.2 LTS), otherwise Cycles samples the full image without footprint filtering. Extension mode belongs in the texture cache key; upload linear float RGB with alpha dropped. v1 only reported interpolation to the user and sampled nearest on CPU.
- **Shader-graph transport from Blender:** groups and reroutes get inlined by Blender's `inline_shader_nodes`, which can fold Tiling into Mapping.Scale; do not assume node-group issues when behaviour differs, check what the inlined tree contains. Custom nodes subclass `bpy.types.ShaderNode` (not `ShaderNodeCustomGroup`, which makes orphan node groups); Cycles skips unknown nodes so a tree survives engine switching; settings survive via a PointerProperty on the Material (an ID-property mirror on the node was rejected); `nodeitems_utils` was deprecated in 3.4, use `NODE_MT_add.append()`. Do not nest custom nodes inside groups.
- **Texture-coordinate cache aliasing:** a cache keyed on the Python object address (`id(node)`) silently shared textures across materials when CPython reused freed addresses. Key on material name + node name.

### Spectral nodes (v1 survey and verified faults)

- Verified in headless Blender 5.1.0 CPU renders (48x48, 8 spp): the Spectral Profile node did nothing in the visible band (|delta| 0.00028, noise); NIR/UV renders were black for any profile because the multiwavelength integrator had no light sampling; the IR/UV Response node discarded the wired BSDF and ignored the band enum; Sellmeier manual B/C were exported but read by nothing; lamp SPDs and blackbody reachable only partly.
- Design conclusion: one currency (an authored Spectrum with declared semantics); true SPD bypasses the RGB round trip (upsampling is lossy); layering non-destructive; fix transport before UI. Node family proposed: Spectrum Preset, Blackbody, Gaussian/Bandpass, Drawn Spectrum (CurveMapping in a hidden helper group exported at 5 nm), SPD File, Spectrum Math, Spectral Reflectance (Replace), Spectral Filter, IR/UV, Sellmeier Glass, Spectral Emission; a light Spectrum-mode enum (Native / Lamp preset / Custom). No surveyed renderer has a drawn-curve editor, so it is a differentiator.
- Licence verdicts: ship pbrt-v4 embedded spectra, refractiveindex.info (CC0), colour-science (BSD-3-Clause), NIST ASD. Reject LSPDD (CC BY-NC-ND 2.5 CA) and BlendLuxCore lamp data (GPL-3, unclear provenance); avoid direct CIE downloads (no verifiable open licence).

### DCC integration decision (ratified 2026-08)

- **Route 1: native `bpy.types.RenderEngine` is the charter. Route 2: session-boundary discipline is a binding design rule. Route 3: a USD/Hydra delegate is deferred behind triggers.** Triggers: a real second-host user (Houdini/Solaris); a deliverable needing Solaris/Katana/usdview; Blender making Cycles its default Hydra delegate.
- **Erasure argument:** `scene.cycles` settings have no USD transport; native node graphs flatten to MaterialX; spectral and relativistic-lensing differentiators have no MaterialX vocabulary. Hydra now "erases the steering wheel for a user who does not exist".
- **Hard rules from the decision:** no `bpy` below the translation line; session API host-neutral; the settings-mapping table lives translator-side; custom UI retirement must not drop host-neutral values; no standalone C API before a second consumer.
- **Commercial renderers keep native per-DCC plugins** (Arnold, V-Ray, RenderMan, Octane, Redshift); Cycles itself is split into `blender/` (host glue) and `scene/` + `session/` (host-agnostic).
- **Facts (verified 2026-08-07):** Blender 5.1.2 released 2026-05-19; HydraRenderEngine stable since 4.0 (`bl_delegate_id`, `bl_use_materialx`); OpenUSD v25.11 (Hydra 2.0 default, .sdf deprecated); MaterialX 1.39.3 default in USD 25.05+; hdCycles experimental, expects a flattened graph with no groups or reroutes and does not use the Material Output node; light networks unsupported via UsdLux. Blender 5.0 removed some panel classes that render addons re-register.

### Render passes

- **Pass classification (Cycles model):** category is locked at the first surface bounce and those weights reused for later bounces; direct vs indirect by bounce count; emission/background go to their own passes when directly visible. Without per-closure weights, a one-label-per-first-hit approach (diffuse/glossy/transmission from a geometric sign test plus delta/glossy flags) is an approximation; a mixed Principled diffuse component then counts as glossy. Sum-to-beauty holds exactly per sample in spectral space; only a per-channel max(.,0) clamp adds slack. Photon caustics were routed to diffuse indirect.
- **Cryptomatte:** IDs = MurmurHash3 x86_32 seed 0, then hash_to_float with an exponent guard (a smhasher reference: "hello", seed 0 gives 0x248bfa47; the spec has no test vectors). Weight = average(throughput * bsdf_eval) at every shade point (CPU spec); 6 ranks default; normalise at pass-read time. On GPU wavefront, many path slots share a pixel, so rank accumulation needs atomic CAS + atomicAdd; accumulate at bounce 0 only; rank arrays per-pixel and driver-owned, sorted and normalised host-side. A one-thread-per-pixel megakernel was race-free; a path-slot wavefront is not. Bug found: an implicit uint32-to-float conversion of the hash must use hash_to_float. Unnamed objects: CPU left ID none, GPU invented "Unnamed_Triangle_<n>"; make them agree.
- **Motion vectors:** Cycles PASS_MOTION stores prev and next flow (4 channels); the OptiX temporal denoiser consumes prev-to-current only; flow = pixel_prev - pixel_curr; sky and negative-w pixels store (0,0). Camera-only motion suffices for static geometry. Each OptiX denoiser model kind needs its own `optixDenoiserCreate` (no HDR->AOV->TEMPORAL upgrade); internal guide layers round-robin frame to frame; first frame passes the noisy beauty as previousOutput with zero flow; the normal guide must be 3D camera space. Motion blur and temporal denoising are mutually exclusive in Cycles. Animated geometry needs previous object transform through the BVH instance (out of scope in v1).
- **Film transparent:** the engine had never read the transparent-film flags (alpha constant 1.0); first implementation used bounce-0 miss coverage. Open: compositing the world through glass.

### Settings mapping and film/sampling behaviours

- **Seed:** pass a seed; seed 0 is a random sentinel (flake trap, not a fixed seed).
- **Pixel filter:** filter importance sampling (offset drawn from the filter distribution, unit weight; no cross-pixel splat), as Cycles' filter_table. Cycles width scaling: Gaussian pre-scales width by 3 giving f = exp(-8 v^2/w^2), so sigma = w/4 with support +/-1.5 w; Blackman-Harris width x2, support +/-w; Box support +/-0.5 w. A sigma = w/6 mapping was too narrow. Cycles' inverse-CDF table over-samples the outer tail (5.2x in the outer 0.15 px bin of BH 1.5); a forward-CDF table of 1024 midpoint cells with binary search + linear interpolation avoids it. Cycles' 1024-entry table leaves its last entry unwritten (TODO in `filter_table()`). Box needs no table (offset = u).
- **Sampler layout:** Owen-scrambled Sobol-Burley with the index mask 0xFFFFFFFF for progressive/viewport chunks so every chunk reads the same sequence; changing the mask changes values but never stratification. Dimension sets: filter (2D), lens (2D), hero wavelength (1D), per-bounce sets at stride 16, time keeps Halton base 2. Stratifying the hero-wavelength uniform cut sky R/B relative variance ~75x at 64 spp (NumPy model). Lens: concentric disk map preserves 2D stratification. Pixel seed = HashHP(pixel ^ seed_lo ^ seed_hi).
- **Light sampler enum:** uniform/power/light_tree; v1 passed values a setter did not accept (latent crash); "uniform" collapsed to power (marked approximated). Light tree traversal verifiable with a diagnostic define; use_light_tree changed images by mean |dLum| 0.028 (5.1) / 0.037 (5.2).
- **Camera motion blur:** evaluate camera transform at frame and frame+shutter, decompose T/R/S, pass to the engine; acceptance was streaking with SSIM vs Cycles >= 0.95.
- **Caustics toggles:** Cycles drops a closure when the toggle is off AND the path's sticky DIFFUSE-visibility bit is set (set on any diffuse bounce, never cleared); reflective closures gate on the reflective toggle, refraction on the refractive toggle, combined glass on the OR. Needs a sticky "had diffuse ancestor" flag; a per-bounce specular flag does not serve.
- **Filter Glossy (blur_glossy, default 1.0 in Cycles):** accumulator is the min unguided BSDF pdf along the path, not roughness; kernel stores 1/blur_glossy; blur_pdf = filter_glossy * min_ray_pdf; if < 1, blur_roughness = sqrt(1 - blur_pdf) * 0.5 applied as max to alpha_x/alpha_y (widen only). Applies to GGX, Beckmann, Ashikhmin-Shirley, hair; energy terms keep original alpha; blur roughness at least 0.41 after a diffuse bounce. It caused a +2.5% R / +2.1% G / +1.1% B bias on a 100k-sphere grid (Welch tests, 6720 tiles, 8 seeds, 64 spp: 1749 CPU / 1761 GPU rejects with blur on, 0 with blur_glossy = 0; ROI ratios 1.025/1.021/1.011 vs 0.999/0.998/0.998). That bias was Filter Glossy, not the Principled model. Widening must also apply on NEE eval.
- **Settings found inert or wrong in a 29-row audit:** a probe method (scene per family, variant A, A at second seed, variant B changing one input) proves an input is consumed or inert; CPU engine deterministic per seed so an inert input gives d_ab == 0 exactly. Name a degradation entry only when the input is linked or non-default.

### UI conventions (owner directive)

- Native Blender surfaces only, following Cycles conventions; tooltips with units on every property (test-enforced); presets cite their DOI; grey out un-honoured controls with an INFO line; node status lines (INFO unwired, ERROR wired but ignored); UI work must not change renders.

### Other engine-side facts that touched Blender integration

- GPU alpha shadows needed alpha-aware occlusion in the shadow stage; hasUV was only set when UV layers existed, so a UV-less procedural checker vanished on GPU (CPU luminance std 0.4182 vs GPU 0.0330). Lesson: attribute upload gates should be per-consumer, not per-attribute-existence.
- Material emission paths: lamps were spectral; emissive geometry went through an RGB upsample.

## Dead ends and negative results

- Blaming the toolchain (MinGW or MSVC OpenMP) for the Blender hang; holding the GIL in the render hangs under either runtime.
- Treating the stale-module error cluster as a missing symbol; re-deriving FOV from a guessed sensor.
- A parallel GPU AOV/upload path in a megakernel would have duplicated the real fix and been deleted.
- Mirroring BlendLuxCore code (GPL-3.0) or any .blend parser whose licence was unverified; several format sources were unreachable. Rule used: no code mirrored until licence is MIT/BSD/Apache-2.0/MPL-2.0/PD/CC0, otherwise re-implement from the format spec (estimated < ~600 LOC).
- A naive coverage scanner under-reported by missing a compilation file; a "noise problem" was a node-group hypothesis that was wrong (Blender already inlines the group and folds Tiling into Mapping scale; the real fault was clamping to [0,1] with no image extension).
- Procedural-to-image baking for non-affine coordinate math (bake mismatch up to 25% at k = 24, 64^3); per-texel opcode path rejected for register pressure risk; per-node special cases ("reinvent the wheel"); full SVM inline in the shade kernel.
- Threading in Phase 1 (GIL and CUDA context ownership risk); GIL release alone; timed join; daemon thread plus timeout; denoising a fresh chunk; spike per-worker lock (serialised only within one session; scene switch ran two workers into one device context -> illegal memory access and later 0 presents); orphaned worker holding the global token via a strong-ref cycle; a lock-less first-unit full-res start failing the 10k cell (45 ms render + 15-25 ms upload).
- A pixel_filter_type test failing because sigma = width/6 was too narrow (fixed with Cycles' width scaling).
- v1 bump at step 0.1 texel, Filter Width ignored; the procedural bump ~2x stronger than Cycles' pixel-footprint finite difference (reported as degraded, not bound).
- A parity test comparing under the same bias can pass while both are wrong (CPU==GPU is insufficient evidence; compare against an independent reference under transformed instances, attribute seams, shadow tricks, bump footprint).

## Design ideas worth reconsidering in the rewrite

- **Build identity and settings-honour tests as a first-class feature.** Stamp a build ID, verify at register time, fail loudly on mismatch; every UI control paired with a test that moves a render (or is removed/greyed).
- **Keep the Blender API on one thread with immutable, generation-tagged handoff;** consider a native session thread owning device state from the start (v1's process-global device state forced a global admission token and a pause gate). Cancel must be a checkpoint between bounded work units, designed into the render API, not bolted on. Acknowledged shutdown, bounded latest-frame mailbox, present before refinement, coarse first unit.
- **Session-boundary rule:** the engine API host-neutral; no `bpy` below the translation line; the settings mapping table lives in the translator. Route 3 (Hydra) deferred behind triggers; consider cheap MaterialX/OpenPBR import as the neutral material currency (OpenPBR is the internal model here, which also shrinks the node-semantics surface).
- **Shader-graph execution:** a graph evaluated per hit in a dedicated kernel or a bounded VM with compile-time refusal; never silent grey. Evaluate procedurals once, shared host/device source. Mix weight propagation and closure rules (above) are directly reusable. Decide up front whether a coordinate-side program is needed (non-affine coordinate math) instead of baking.
- **Depsgraph sync:** the per-domain dispatch table plus fixed update order; BVH refit policy; no per-property granularity; export hash/key per datablock; cache images by size/depth/colour-space/reload counter.
- **Frequency-weighted node-coverage backlog** (from the 2026-09 audit): Principled advanced inputs (21 sockets), Vector Math, Clamp, MATH/MIX clamp flags, Sky texture, Metallic BSDF, Vector Rotate, Map Range / Image Texture properties, Displacement, AO, SSS node, volume shaders, Gabor texture, RenderSettings. The cheapest wave was opcode extension. Alpha and Specular Tint first within Principled.
- **Coverage tooling:** generate the node/socket coverage matrix from the code itself (AST extraction of the handled sockets), headless in Blender, so there are no hand-typed tables and no scanner blind spots.
- **Probe method for "is this input consumed":** one scene per family, variant A, A at a second seed, variant B changing one input; deterministic CPU gives d_ab == 0 exactly for an inert input.
- **Spectral currency:** an authored Spectrum with declared semantics; drawn-curve editor as a differentiator (drawn CurveMapping exported at 5 nm); physical units for later astrophysical use; fix transport before UI.

## What no longer applies

- Cycles-parity pass/fail bands, Welch-test gates, seed sets, corpus burn-down matrices (judge against physics/OpenPBR).
- Filter Glossy implementation (it is Cycles behaviour that biases results; decide separately whether to emulate).
- Caustic-toggle parity, light-sampler "uniform" collapse, Cycles ray-visibility "Is Singular" edge cases as parity targets (keep as semantics knowledge only).
- Bump-terminator correction port and `ensure_valid_specular_reflection` parity.
- The op-VM sizing (VM_MAX_SLOTS, instruction counts), register-file budgets and kernel register targets (v1 shade kernel structure).
- Per-texel bake-resolution tradeoffs tied to a 64^3 grid.
- The megakernel-versus-wavefront cryptomatte race analysis and path-slot pointer placement.
- v1's single-level BVH, per-triangle binding calls, GIL-held render, OpenMP flag and packaging workarounds.
- Cycles texture-cache mip path and 8-bit fixed-point weights as parity details.
