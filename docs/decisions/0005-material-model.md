# 0005 — Material model, extension lobes and shader-node evaluation

Status: proposed (2026-11-14), revised after review (2026-11-14). The record and register-file layout (items 2 and 3) is ratified only after measurement M-1.

## Context

The integrator needs bounded per-hit material state; Blender users author arbitrary node graphs; the owner wants custom material types beyond OpenPBR (decision 16), diffraction gratings in the first release with the light-tracing path that makes them useful (17), one extension behaviour per material (18), fluorescence for all its use cases (19), a first release that is complete in breadth (7), physics and the OpenPBR specification as the correctness target (1), node behaviour that matches Blender exactly (14), one kernel source (2), and a viewport where a material edit is an upload, not a compile. Most implementation will be done by Sonnet-class agents from small task specs, so adding a node, an opcode or a lobe must be a local change.

The spine fixes the frame: one fixed OpenPBR Surface 1.1.2 record seen by the common shade kernel; spectrum sources for colour and IOR slots; at most one extension behaviour from a closed list, in a separate stage; a bytecode VM that fills the record and never emits closures; stochastic Mix Shader; magenta plus a per-render report for unsupported nodes (SPINE §5). Kernel facts are MEASURED in spike A: the fused N=4 shade+NEE kernel uses 148 registers, 0 spills (128 with `__launch_bounds__(256,2)`, +56% throughput); a VM fused into that kernel costs 150 registers / 304 B stack and is 30% faster than a separate parameter pass (1.59 ms vs 2.256 ms per 2^20 paths). The 304 B are the spike's 176 B record plus its VM register file of 16 scalars and 4 `Spec<4>`, i.e. 32 floats (`spikes/A-kernel-budget/include/stages.h`, `stage_param`). `__noinline__` with by-value records is harmful; by-pointer recovers most of it. The gate is per kernel (0002 D10): at most 168 registers in the probe build, no spills, at most 512 B stack for shade kernels, at most 3 s compile per TU, runtime flags rather than template variants.

v1's failures shape the rest (`v1-lessons/research/materials.md`, `blender.md`, `research/07` F7): a fat shared material struct; a closure graph whose lobe count saturated the shade kernel at 254 registers; a constant-folding translator that turned every texture-driven chain grey (0/8 production materials correct at baseline); a VM bolted on as a second path, with hand-mirrored opcode enums; 340 of 527 sockets dropped silently. Ground truth is weak: the MaterialX reference graph leaves dispersion unwired and Blender's own OpenPBR implementations disagree with each other (`research/05` B6), so analytic and furnace oracles come first.

Spike A omitted texture fetches, spectral upsampling and procedural nodes. Every register or size number that is not from a spike is marked PROVISIONAL and is measured early in the build (Risks).

## Decision

### A. Record, stack budget and lobe stack

1. **Pin OpenPBR Surface 1.1.2** (release 2026-11-05). Lobes are written from the spec text and cross-checked against Adobe's `openpbr-bsdf` (Apache-2.0, targets 1.1.1); the 1.1.2 deltas (squared coat transmittance in layering, #304; thin-walled subsurface colour applied once) are applied by us. OpenPBR 1.2 slots (retroreflectivity, haze) are not added until 1.2 is released.
2. **Three layouts.** (a) `MaterialHeader`, 16 B per material in device memory: `program_offset u32` (the program starts with an entry table, item 32), `const_offset u32`, `ext u32` (= `ext_kind u8 | ext_index u24`), `flags u32` (item 43). (b) A per-material constant block holding all 41 OpenPBR inputs at their authored values (scalars `f32`, colour and IOR inputs as 24 B `SpectrumRef`, item 9). (c) The resolved record `OpenPBRParams`, filled per shading point in thread-local memory and passed by reference, never by value. It holds only what the lobe stack reads after the VM has finished:

| Group | Fields | Type | Bytes at N=4 |
|---|---|---|---|
| Scalars | base_weight, base_diffuse_roughness, base_metalness, specular_weight, specular_roughness, specular_roughness_anisotropy, transmission_weight, transmission_depth, transmission_scatter_anisotropy, subsurface_weight, subsurface_radius, subsurface_scatter_anisotropy, fuzz_weight, fuzz_roughness, coat_weight, coat_roughness, coat_roughness_anisotropy, coat_ior, coat_darkening, thin_film_weight, thin_film_thickness (µm), thin_film_ior, geometry_opacity, closure_weight (item 38) | 24 × f32 | 96 |
| Spectral slots | base_color, specular_color, specular_ior, transmission_color, transmission_scatter, subsurface_color, subsurface_radius_scale, fuzz_color, coat_color | 9 × f32[N] | 144 |
| Frame | geometry_normal, geometry_coat_normal, geometry_tangent, geometry_coat_tangent (world space, after bump and normal maps) | 4 × f32[3] | 48 |
| Complex IOR | `metal_ior`: constant-block offset of the (n, k) `SpectrumRef` pair; 0 = F82 mode (item 12) | u32 | 4 |
| Flags | thin_walled, ior_dispersive | u32 | 4 |
| Total | | | 296, padded to 304 (PROVISIONAL) |

   Not in the record: emission, holdout and shadow transmittance are VM outputs consumed at once (item 38); `transmission_dispersion_scale` and `_abbe_number` are resolved into `specular_ior` per wavelength (item 9); n and k are per-material constants read through `metal_ior`; extension kinds reuse fields they ignore (item 16). Lengths are in scene units (metres), not OpenPBR's centimetre metadata default.
3. **Stack budget.** 0002's limit of 512 B stack per shade kernel (probe build) is split: record ≤ 304 B; VM register file 32 × f32 = 128 B, the size spike A measured (176 B record + 128 B file = 304 B); at least 80 B for everything else (spike A: 32 B of unidentified local in every inlined variant). Both arrays are dynamically indexed (`STORE_SLOT` by slot index, registers by operand), so both live in local memory; the split is enforced by `static_assert` and by the gate. Each kernel declares one `VmRegs` array and passes it by pointer to every interpreter call, so programs run one after another (the surface program, then an emission, light or world program inside NEE) share it; the interpreter never declares its own. Cycles does the same: NEE evaluates the emitter's shader into a separate small `ShaderDataTinyStorage` while the surface `ShaderData` stays live, and the SVM stack is a local of the evaluation call (`kernel/integrator/shade_surface.h`, `svm/svm.h`). Growing either part requires shrinking the other or a 0002 change.
4. **Lobe stack = OpenPBR's nine primitive lobes in the spec's layering tree** (`research/05` B3): fuzz over coat over base substrate = mix(metal, dielectric base); dielectric base = mix(opaque, translucent); opaque = mix(glossy-diffuse, subsurface); top = mix(transparent, surface, opacity); emission under coat and fuzz (attenuation applied where emission is evaluated, item 38). Models: EON diffuse (Portsmouth, Kutz, Hill 2025); GGX with height-correlated Smith (Heitz 2014) and VNDF sampling (Heitz 2018); F82-tint metal (Hoffman 2019; Kutz, Hasan, Edmondson 2021) or exact complex Fresnel (item 12); Walter et al. 2007 dielectric with the spec's `specular_weight` F0 modulation; coat with darkening and the coat-IOR TIR fix as specified; fuzz by Zeltner, Burley, Chiang 2022 (LTC); thin film by the closed-form Airy reflectance of a single film, evaluated per transport wavelength with complex amplitudes for s and p and averaged (Born and Wolf 1999 §1.6; the m → ∞ limit of Belcour and Barla 2017 Eq. 10), no truncation and no RGB sensitivity table. A microfacet lobe whose α is below 1e-3 on both axes is sampled as a delta lobe (pbrt-v4 `TrowbridgeReitzDistribution::EffectivelySmooth`); its sample carries `DELTA`. Subsurface: the shade stage samples the subsurface lobe and hands the path to the random-walk stage (0004) with coefficients from the spec's van de Hulst inversion. Translucent base with `transmission_depth > 0`: refraction pushes a homogeneous interior medium (μt = −ln(T)/depth as specified) onto the medium stack (0006). One lobe-selection function returns the weights used by eval, sample and pdf alike. The stack's result is multiplied by `closure_weight`.
5. **Energy conservation by construction.** Layering is OpenPBR albedo scaling, `f = f_top + T_top² (1 − E_top(ωo)) f_bottom` and its weighted lerp form, with E from tables; inter-layer multiple bounces are ignored and non-reciprocity is accepted, both as the spec states. Single-lobe energy loss is compensated per Turquin 2019 (1/E scaling with the Fresnel-weighted term) for conductor and dielectric reflection, and with a combined reflection+transmission 1/E table for rough dielectrics (the approach of Cycles' `ggx_glass_E`, `v1-lessons/research/materials.md`). Thin film: single-lobe compensation stays film-free (v1), and the base under a filmed specular layer is attenuated with `E_spec(μo, α) · F_film(μo) / F(μo)`, which is exact at α = 0 and an approximation for rough film; before coding it is compared with the thin-film layering in Adobe's `openpbr-bsdf`, and the reference wins if they differ. The Heitz et al. 2016 multiple-scattering random walk is not in the engine; it is the CPU test oracle for rough dielectrics.
6. **Tables**: E_spec(μ, r) 32×32, E_avg(r) 32, E_diel(μ, r, η) 16³ reflection-only (coat and glossy-diffuse layering), E_glass(μ, r, η) 16³ plus its η<1 inverse; the roughness axis is r = (αx αy)^(1/4), which is how anisotropic lobes index them (v1 and Cycles). All E tables are geometric (grey; colour enters through per-wavelength F0) and are generated by one host tool from the engine's own lobe code (CPU build, importance-sampled), because v1 showed tables baked with a different G or sampler leave 12-19% furnace error; they are checked in with a hash, regenerated by a slow-tier test and compared with Adobe's tables. The fuzz LTC fit (32×32×3) is imported from `tizian/ltc-sheen` (Apache-2.0), because the lobe is that fit; its albedo channel is checked against Monte Carlo integration of our fuzz lobe. EON's albedo is analytic.
7. **Spectral semantics**: every spec formula (sqrt, −ln T, powers, F82 terms) is applied per transport wavelength to resolved spectra (`research/05` B4). Agreement with RGB-defined spec numbers is a measured tolerance, not an identity (Verification 4).
8. **Orientation and shading normals**: front-face is a stored hit attribute that survives every instance transform (v1 lesson); reflected samples below the geometric surface are rejected (pbrt-v4); bump and normal maps use the shadowing term of Conty Estevez, Lecocq, Stein 2019, honouring Blender's per-material bump-correction setting. Every lobe and extension kind takes `TransportMode {Radiance, Importance}` (Veach 1997 §5.2-5.3; pbrt-v4), which selects the η² factor and the adjoint shading-normal correction; the light-tracing pass needs it.

### B. Spectrum sources

9. **Slots are resolved at the path's 4 transport wavelengths** (SPINE §3), so the BSDF never sees RGB and never branches on source type. **`SpectrumRef`** (24 B: `kind u8, semantic u8, aux u16, index u32, p[4] f32`). Closed kinds: `CONST`; `RGB` (Jakob and Hanika 2019 sigmoid coefficients c0..c2 plus scale, precomputed on the host for constants); `TABLE` (piecewise-linear spectrum in the scene spectrum arena, times scale); `BLACKBODY` (T, scale; Planck in absolute units, evaluated with an exponent cutoff for float); `CAUCHY_ABBE` (n_d, V_d, dispersion scale: OpenPBR's dispersion law); `SELLMEIER` (six coefficients in the arena); `GAUSSIAN` (centre, width, peak). Spectrum math, SPD files and element-line bakes are host-side compositions into `TABLE`; no device code.
10. **The lift semantic is fixed by the slot**, never chosen by the user or the source:

| Semantic | Colour input | Float input | Slots |
|---|---|---|---|
| REFLECTANCE | clamp each channel to [0,1], then albedo sigmoid | grey | base, specular, transmission, transmission_scatter, subsurface, fuzz, coat colours; medium albedo colours (0006) |
| UNBOUNDED | unbounded form, scale = 2·max | grey | subsurface_radius_scale |
| ILLUMINANT | unbounded form × the working space's illuminant (D65 for Rec.709 and Rec.2020, D60 for ACEScg) | grey × illuminant | emission colour; light, world and medium emission colours (0004, 0006) |
| IOR | refused (compile error) | flat spectrum per shading point; with Dispersion Scale > 0 it is n_d of a per-point `CAUCHY_ABBE` | specular_ior; metal n and k accept no per-point input (item 12) |

   So a float texture linked to Principled IOR is accepted. A constant above 1 in a REFLECTANCE slot is clamped and reported `approximated`; an image bound to such a slot whose decoded range exceeds [0,1] is reported once at load. Outside 360-830 nm an RGB-lifted reflectance holds its edge value, with a warning when a non-visible band is requested (0003).
11. **Textures and lifting**: images are interpreted in the file's working space per `Image.colorspace_settings.interop_id` (`data` means no transform and no lift) and filtered as Blender does (item 34). The lift is applied per shading point to the filtered RGB by the `RGB_LIFT` opcode: one lookup in the 64³ coefficient table, which trilinearly interpolates the table's coefficients (`rgb2spec_fetch`), then the sigmoid per wavelength. Per-texel coefficients are never stored or filtered. One table is resident: the file's working space (Rec.709, Rec.2020 or AP1; AP1 generated with `rgb2spec`, BSD-3), 9.4 MB.
12. **Complex IOR.** n and k accept only `TABLE`, `CONST` or analytic sources (n, k from refractiveindex.info, CC0), never textures, so they are per-material constants: the record holds only their constant-block offset (`metal_ior`), and the metal lobe resolves them at the transport wavelengths when it runs. A non-zero `metal_ior` makes the metal lobe use exact conductor Fresnel (Born and Wolf; pbrt-v4 `FrComplex`). Everything that needs an albedo (energy compensation, coat darkening's E_base, layering) uses the F82-tint fit computed per wavelength from (n, k): F0 exact at normal incidence, tint = F_exact(82°)/F_Schlick(F0, 82°) (Hoffman 2019's parametrisation), so the existing tables apply and the residual is measured (Verification 4). Blender's Metallic "Physical Conductor" mode supplies RGB n and k, possibly textured: the program converts them per channel to (F0, F82 tint) with the same exact formulas, lifts both as REFLECTANCE into base_color/specular_color, uses F82 mode, and reports `approximated`.
13. **Polarisation: none in 2.0.** Fresnel functions compute Rs and Rp and return their mean; nothing else is reserved. A polarised build would re-implement every lobe with Mueller-valued evaluation; that needs its own superseding record.

### C. Extension mechanism

14. **Closed list.** `ext_kind u8`, first release: `0 NONE`, `1 GRATING`, `2 HAIR`, `3 FLUORESCENT`. After the first release, each by an amendment to this record: `4 MULTILAYER` (transfer-matrix thin-film stack), `5 MEASURED`. Anything else (Hapke regolith, glints, pearlescent, scratches, holographic foil, toon, ray portal, retroreflection) needs a superseding record.
15. **Full replacement.** An extension kind replaces the whole OpenPBR lobe stack. From the record it keeps only geometry_opacity, closure_weight, the frame and the fields its field map declares (item 16); emission is evaluated unattenuated (item 38). Coat, fuzz, thin film and all other BSDF inputs of that material are reported `ignored`. Albedo-scaling layering therefore never meets an extension lobe, and no kind has to define E(ωo). Owner decision 18 makes this sufficient.
16. **Parameters.** Per-material constants: a 64 B block (16 × 32-bit, PROVISIONAL) in `ExtParams[]` at `ext_index`; anything larger is a handle into the scene `TableArena` (byte buffer, 16 B aligned, `u32` offsets). Per-point inputs: each kind declares, in one generated table `ext_fields.def`, which record fields it reads and under which name, using fields the OpenPBR stack would have used and the kind ignores (for example HAIR's melanin, melanin redness and random roughness in subsurface scalars; FLUORESCENT's concentration in a fuzz scalar). This costs no storage. Kind and constants are authored on the Material's Astroray property panel (a `PointerProperty` on Material, 0007); per-point inputs come from the node tree (Principled Hair sockets, Curves Info, Attribute).
17. **Stage.** A sort-key bit routes hits on materials with `ext_kind ≠ 0` to 0002's `shade_surface_ext` (`SurfaceKind::Ext`): the same body as `shade_surface`, including the VM and NEE, plus `switch (ext_kind)`; NEE serves the non-delta kinds (HAIR, FLUORESCENT). `shade_surface` contains no extension code. Interface per kind: `sample/eval/pdf(const OpenPBRParams&, const ExtParams&, const ShadeFrame&, wo, wi, TransportMode, const Spec&)`; sample results carry flags `DELTA`, `WL_DEPENDENT_DIR` (terminate secondaries) and `REWRITES_WL` (FLUORESCENT, item 26). The host skips the launch when no synced material has `ext_kind ≠ 0`.
18. **Budget rule.** Extension code is compiled into exactly two kernels: `shade_surface_ext` on camera paths and 0004's `photon_scatter` on light paths (0002 calls it `shade_light_path`; 0004 D21 includes extension lobes in it). Each kernel holds every kind and must meet the 0002 gate; a kind that breaks it first shrinks its live state (tables, recomputation). Each may split once, on measurement only: HAIR into `shade_hair` (it has its own primitive anyway), and extension hits into 0004's `photon_scatter_ext`. Any further kernel carrying extension code needs a superseding record.
19. **No masking in the first release.** An extension material's node tree supplies only the fields of item 15; a Mix Shader cannot combine an extension with an OpenPBR branch inside one material (use material slots). Masked extensions come later by forwarding from `shade_surface` to `shade_surface_ext` after the VM's branch selection (deterministic re-run from the counter-based sampler), as an amendment.
20. **Queues.** Materials add `shade_surface_ext` (and `shade_hair` if HAIR splits). They trigger stages owned elsewhere: random-walk subsurface and the light-tracing pass (0004), the medium stack (0006).

### D. Diffraction grating

21. **Model**: 1D periodic grating with delta diffraction orders, unpolarised (mean of s and p). Directions come from the grating equation in direction-cosine space (Harvey and Vernold 1998). With grooves along the record tangent T and grating vector ĝ = N × T, the tangential projection t of a unit direction obeys, for order m: reflection `t_o = −t_i + m(λ/d) ĝ`; transmission `n_o t_o = −n_i t_i + m(λ/d) ĝ`; an order with |t_o| > 1 is evanescent and absent. Order efficiencies η_m(λ, cosθ_i) come from a table.
22. **Sampling**: order m is chosen with probability p_m = η̄_m / Σ_prop η̄, where η̄_m is η_m averaged over the four transport wavelengths (0 where evanescent). Order 0 in reflection, and in transmission over a non-dispersive substrate, has a wavelength-independent direction: all four lanes continue with throughput η_0(λ_j)/p_0. Any other order has a wavelength-dependent direction: secondaries are terminated (0003's collapse, pbrt-v4 `TerminateSecondary`) and the hero continues with η_m(λ_0)/p_m. Every lane's estimate is unbiased because p_m > 0 wherever η_m(λ_0) > 0. Transmission in Radiance mode also carries (n_i/n_o)². Eval and pdf are zero (delta); no NEE. On a CD most energy is in order 0, which therefore keeps full colour sampling.
23. **Parameters** (`ExtParams`): `pitch_nm f32`, `mode u8` (reflect, transmit), `m_min, m_max i8` (|m| ≤ 8), `table u32` (TableArena handle), substrate IOR `SpectrumRef` for transmission. Groove direction is `geometry_tangent`, so the node tree can drive it (a radial Tangent gives a CD). Table: η over the 0003 wavelength grid at 5 nm (95 samples on 360-830 nm) × 16 bins of cosθ_i × ≤ 17 orders, f32, ≤ 103 KB per grating, linearly interpolated.
24. **Efficiency tables are generated on the host only**, from generator inputs that never reach the device: sinusoidal phase profile with peak-to-peak groove depth `depth_nm`, by scalar thin-phase theory, η_m = J_m²(φ/2) with φ the peak-to-peak phase modulation (Goodman 2005); blazed sawtooth with blaze angle `blaze_deg`, by the scalar sinc² form (Palmer and Loewen 2005); both times the coating reflectance from its complex IOR (reflective) or the substrate transmittance (transmissive); or a user CSV from a rigorous solver or measurement (RCWA, Moharam and Gaylord 1981; not shipped). Scalar theory holds only for d ≫ λ; generating a DVD-class pitch reports "scalar theory out of range". Presets (PROVISIONAL): CD, 1.6 µm, sinusoidal, depth 120 nm (about a quarter wave at 780 nm in polycarbonate); 600 and 1200 lines/mm, blazed for 500 nm in first-order Littrow (8.6° and 17.5°). Every cell satisfies Σ η ≤ 1; clipping is reported. The two scalar formulas, including the phase-depth expression, are re-read from the cited books before coding (CLAUDE.md rule 5).
25. **Reachability and the light-tracing pass.** Area, sphere and sun-disc lights and the environment are reached through a grating by BSDF sampling. Zero-area emitters (point, spot, laser) through a grating onto a diffuse receiver are reached only by the light-tracing pass (0004). Materials give that pass: `sample` in Importance mode for every lobe and kind; delta and `WL_DEPENDENT_DIR` flags; eval at non-delta vertices for the camera connection; emission evaluation for emissive surfaces; light subpaths at the emitter-sampled wavelength (0003), hero only after a non-zero order. A point light seen directly in a grating is a delta-delta configuration of zero measure, unrenderable by any method, as with a mirror. Roughness-broadened orders are not in the first release: no citable model with a usable licence was found (`research/17`; PLTFalcor is CC BY-NC).

### E. Hair and fluorescence (first release), measured BSDFs (after)

26. **FLUORESCENT**: EON diffuse with base_color as elastic albedo, plus reradiation M(λi→λo) = Q · a(λi) · e(λo) (separable form, Glassner 1994; Wilkie et al. 2006), or a measured bispectral matrix (Hullin et al. 2010) as a 2D table. Parameters: quantum yield Q, excitation table a, emission table e; concentration is a per-point field (item 16). On a camera path at λo the kind picks the elastic or inelastic event with the extension sampler dimension (0003), and for the inelastic event calls 0003's `rewrite_lane0` (terminate secondaries, sample λi from the excitation distribution, multiply by M/p, set the lane to λi); NEE and BSDF sampling of the Lambertian reradiation lobe then proceed at the single rewritten wavelength with ordinary MIS, as after dispersion. The film keeps λo (SPINE §3). In the light pass, a fluorescent receiver's camera connection samples λo from e. Sampling follows Mojzík, Fichet, Wilkie 2018. The reradiation function is one file, so a volumetric use can call it later (0006 currently defines none). Brighteners, minerals and pigments are covered by this kind.
27. **HAIR**: Chiang et al. 2016 far-field model with per-wavelength σa from melanin concentrations or from colour (pbrt-v4 `HairBxDF` and `SigmaAFromReflectance`, Apache-2.0). Inputs: base_color (direct colour) and the declared per-point fields (melanin, redness, roughness, random). Principled Hair (Chiang) maps exactly; Principled Hair (Huang) and Hair BSDF map to it and are reported `approximated`. Needs curve primitives with whole-curve self-skip; 0002 (OptiX curves) and 0007 (hair `Curves`) land them before the first release. The Huang, Hullin, Hanika 2022 near-field model comes later as a mode flag.
28. **MEASURED** (after the first release): RGL format (Dupuy and Jakob 2018), spectral, isotropic and anisotropic, evaluated by table interpolation and sampled by the paper's warp (reference: Mitsuba 3 `measured` plugin, BSD-3). Data lives in the TableArena; loader only, no data shipped. MERL is not supported (RGB, non-commercial).

### F. Shader-node evaluation

29. **Pipeline.** (1) The addon (Python, GPL) calls `inline_shader_nodes()` on the evaluated Material, World or Light, walks the inlined tree and translates each Blender node into engine ops; the Blender-to-engine mapping lives in the addon, so the core knows nothing of Blender (SPINE §1). It sends a host-neutral graph (typed op nodes with constant or linked inputs) through the C ABI. (2) The core compiler (C++) does type inference, constant folding, segment splitting (item 38), dead-code elimination per entry, linear-scan register allocation, bytecode emission, constant-block and `SpectrumRef` packing, and returns an error list. A material edit is a recompile and an upload; no kernel is compiled. (3) **Translation cache**: the addon keeps each material's translated graph keyed by the original datablock's `session_uid` and re-translates only materials (or node groups) that 0007's update classification marks changed; materials with animated node values are therefore re-translated once per frame change, and nothing else is. The cost is budgeted by M-8.
30. **One opcode table**, `ops.def` (X-macro), generates the core enum, the interpreter's `switch`, compiler metadata (arity, operand types, cost class), the addon's Python op schema (build step, never hand-mirrored), and the node coverage matrix. Op implementations are kernel-library functions compiled for CPU and GPU; constant folding calls the CPU build of the same functions, so folding cannot disagree with evaluation.
31. **Encoding, registers and control flow.** 32-bit words; an instruction word is `opcode u8 | a u8 | b u8 | c u8` (register operands), immediates follow. Register file: 32 × f32 per thread (item 3); value types `f32`, `f32x3` (colour, vector; colours stay RGB until a `STORE_SLOT` lifts them into a slot), `spec` (N floats, only for spectral-typed values such as Blackbody). A program needing more registers fails to compile: magenta and a report entry, no fallback. Control flow is forward-only, so every program terminates and its length bounds its time:
   - `JMP off`: unconditional forward jump.
   - `BRANCH_MIX ru, rf, off`: with f = clamp(r[rf], 0, 1): if u < 1 − f, set u ← u/(1 − f) and fall through to the first child; else set u ← (u − (1 − f))/f and jump to the second child.
   - `BRANCH_ADD ru, off`: as `BRANCH_MIX` with f = 0.5, and `closure_weight *= 2`.
   - `END`: ends the current entry.
   Heavy ops (Voronoi, Gabor, Sky) are called `__noinline__` with the register file by pointer, the form spike A measured cheaper than noinline by value.
32. **Entry points and the kernels that run them.** Each program begins with an entry table of four `u32` offsets (0 = absent or constant); World and Light trees compile to programs with their own single entry.

| Entry | Evaluates | Run by | Produces |
|---|---|---|---|
| `surface` | emission segment, selection, the selected child's BSDF block (item 38) | `shade_surface`, `shade_surface_ext`, 0004 `photon_scatter` (and `_ext`) | record, Le, holdout |
| `opacity` | opacity subgraph of every child | `shade_shadow` (0002 D8), including the light pass's camera connections | T(λ) |
| `emission` | emission segment only | NEE on an emissive triangle in `shade_surface`/`_ext`; 0004 `photon_generate` | Le |
| `light` | Light node tree and IES, emission only (0004 D8) | lamp hits and lamp NEE in `shade_surface`/`_ext`; `photon_generate` | Le |
| `world` | World node tree | `shade_background`; environment NEE in `shade_surface`/`_ext`; `photon_generate` | Le |
| `volume` | Volume socket, procedural cases only (item 39) | `shade_volume` (0006) | medium record |

   A constant entry (flag in item 43) runs no interpreter. Every kernel in the table counts as a shade kernel for 0002's stack classes and holds one register file.
33. **Context**: evaluation is hit-time only, with no texture-time pre-pass. The context holds P, Ng, N, front-face, wo (for an emission entry inside NEE, the direction toward the shading point), UV sets by index, tangents, dP/dx and dP/dy from the ray cone (0003), object and instance ids, random_id, attribute accessors, ray-type flags and depths (Light Path), ray length and the transport wavelengths. Layer Weight, Fresnel, Backfacing, Light Path and Ray Length read it.
34. **Texture lookups.** `TEX_IMAGE` covers Closest, Linear, Cubic (uniform B-spline, as Blender) and Smart (= Cubic); Repeat, Extend, Clip, Mirror; Flat, Box, Sphere, Tube projection; UDIM; per-image alpha mode (0007). Filtering is software in kernel code, identical on CPU and GPU. Texels are filtered in their stored encoding and decoded afterwards, as Cycles does for 8-bit sRGB images, so node values match Blender (owner decision 14); half and float images are linear. Storage keeps the authored bit depth (8-bit, half, float). Linear is trilinear over a mip pyramid with LOD from the ray cone (Akenine-Möller et al. 2021); Cubic samples the ray-cone LOD level; Closest uses level 0. Mips are an antialiasing prefilter that Cycles lacks; at LOD 0 the filters equal Blender's. Hardware filtering only if a measurement shows a win and CPU/GPU agreement holds. A missing image gives magenta texels and a report entry. Environment Texture uses the same op.
35. **Constant folding**: a node folds only if all its inputs are constants and it reads nothing from the context, so folding never crosses a texture or context read. A surface program that folds to constant stores becomes length 0: the interpreter loop is skipped and only the slot-resolution pass runs (scalars copied from the constant block, each `SpectrumRef` evaluated at the 4 transport wavelengths).
36. **Procedurals and colour nodes** are ported from Cycles `kernel/svm/` (Apache-2.0; `noise.h` BSD-3) into the kernel library with their licence headers. Sky Texture lowers to a `SKY` op whose model belongs to the sky/world record (0004 or 0006). Blackbody produces a `spec` value (`BLACKBODY`) and Wavelength a line source (0003's line-aware sampler) when every consumer is spectral-capable; the spectral type propagates only through linear colour ops (Mix in Mix/Add/Multiply modes, Multiply, Add) into record slots; any other consumer receives Blender's RGB result. Until 0003's line sampler exists, Wavelength uses the RGB form and is reported `approximated`.
37. **Bump, normal maps, displacement.** Bump: the compiler emits the Height subgraph three times under `BUMP_ENTER k` (centre, +dx, +dy), which offsets context P and UVs by the ray-cone footprint times Filter Width (Blender default 0.1); the normal comes from the surface-gradient formula (Mikkelsen 2008, as Cycles `svm/bump.h`). Normal Map: tangent, object and world space, tangent space with MikkTSpace per-corner tangents and sign computed natively at sync (0007). The Displacement output, Displacement node and Vector Displacement become bump from finite differences of the displaced position (as Cycles `svm/displace.h`). True displacement comes after the first release (geometry, 0007); materials set to "Displacement Only" or "Displacement and Bump" are reported `approximated`.
38. **Closures and segments.** Lowering turns the closure tree into BSDF-carrying children with weights w_i (products of mix factors along the tree) and three per-point outputs. The compiler lays out the `surface` entry as: (a) the **emission segment**: every node feeding any child's emission, holdout and mix factors, plus the coat and fuzz inputs of emissive children; it accumulates `Le = Σ_i w_i · Le_i · A_i(ωo)` and `holdout = Σ_i w_i h_i` over all children, deterministically, where A_i is the child's coat-and-fuzz attenuation computed by the same layer function the lobe stack uses (A = 1 for Emission shaders and extension kinds); (b) the **selection**: a `BRANCH_MIX`/`BRANCH_ADD` tree over the BSDF-carrying children with one sampler dimension per shading point, nested mixes reusing the uniform by rescaling (pbrt-v4 `SampleDiscrete`; `MixMaterial`); (c) one **BSDF block** per child, writing its record slots and ending in `JMP` to `END`. A value used by both (a) and (c) is computed in (a) and kept live. The `emission` entry is (a) alone; the `opacity` entry is the dead-code-eliminated graph of `T(λ) = Σ_i w_i (1 − a_i)`, with a_i each child's geometry_opacity. Rules:
   - NEE and BSDF sampling at the vertex use the same selected child. A camera path takes the null event with the selected child's 1 − a_i, an unbiased estimate of T; the shadow stage multiplies by T exactly.
   - A child without a BSDF (Emission, Holdout) is pruned from the selection, and the surviving child's closure_weight is multiplied by its weight. A Transparent child folds into geometry_opacity (Mix(Transparent, S, a) is S with opacity a × S's opacity, OpenPBR's top-level mix); a non-white Transparent colour folds by its mean and is reported `approximated`.
   - **Add Shader**: `BRANCH_ADD`, an unbiased estimator of the sum; emission and holdout are summed exactly; reported `info: not energy-conserving` when the BSDF weights can sum above 1.
   - Mix(Principled, Principled) is selected, never lerped (v1: lerping averages sharp and blurred highlights).
39. **Volume shader hand-off.** The Volume socket compiles to the `volume` entry. Constant or grid-attribute-driven volumes fold into the medium record at compile time, with no VM in the medium stage. Procedurally driven volumes run the volume program in the medium stage with a volume context (P, object coordinates, attributes; reading a surface-only input is a compile error); majorant policy belongs to 0006. Semantics follow item 10: scattering and absorption colours REFLECTANCE, emission ILLUMINANT, Blackbody analytic.
40. **Unsupported-node policy** (owner default). Any node, setting or linked socket without a lowering makes the whole material diffuse magenta (base_color (1,0,1) as reflectance, nothing else), and the per-render report lists material, node name, node type, socket or setting, and reason. Dispositions: `unsupported` (magenta), `approximated` (rendered with the documented approximation in item 42), `ignored` (no effect by design, such as EEVEE-only settings). One entry per (material, node, socket) per render. The coverage matrix is generated from `ops.def` plus the addon's lowering table and has a row for every `ShaderNode` type, so nothing drops silently.
41. **First-release coverage target**: every node in `research/07`'s W1 set; Principled Volume, Volume Absorption, Scatter, Coefficients, Info; Subsurface Scattering, Sheen BSDF, Metallic BSDF; Principled Hair, Hair BSDF, Hair Info (HAIR); IES, Magic, Brick, Gabor, Radial Tiling textures; Light Falloff, Wireframe, Combine/Separate Cylindrical and Spherical, Vector Displacement (as bump), AOV Output (0008). **Approximated** in the first release: Ambient Occlusion (outputs the unoccluded result: Color passed through, AO = 1), Bevel (passes the input normal through, as Blender's own MaterialX export does, `research/07` F2) and Raycast (reports a miss). They need ray queries from inside shading; in Cycles they run in `shade_surface_raytrace`, an OptiX raygen kernel (`__SHADER_RAYTRACE__`, `research/07` F2), and 0002 D11 forbids VM code in OptiX programs, so real support needs a 0002 amendment and an owner decision (Risks). Magenta: Toon, Ray Portal, Script (OSL), and the EEVEE-only Specular BSDF and Shader to RGB. Metric over the 0009 asset corpus, frequency-weighted as in v1: at least 95% of node uses `supported`, the rest `approximated` or `unsupported`, zero silent.

## Alternatives considered

- **General closure graph** (Cycles SVM closures, v1). Rejected: v1's lobe-count spills (254 registers) and unbounded per-hit state; OpenPBR's fixed nine lobes cover Principled, and stochastic Mix/Add covers the closure combinations Blender files use.
- **Per-material code generation** (NVRTC, EEVEE-style). Rejected for the first release: every edit becomes a compile (spike A: about 1.1 s edit-to-launch per kernel against a 16.7 ms frame at 60 updates/s), a CPU JIT would be needed for the one-source rule, plus a cache layer. Re-examined only if Measurement M-3 shows the VM is the bottleneck.
- **Separate parameter-evaluation kernel** writing the record to memory. Rejected on spike A: 2.256 ms versus 1.59 ms fused.
- **64-entry register file** (v1; Cycles uses 255). Rejected: with the record it exceeds 0002's 512 B stack limit; 32 entries is the measured configuration (item 3).
- **A second register file for emission programs inside NEE.** Rejected: programs run one after another, so one kernel-owned file serves both (item 3).
- **MaterialX or OSL runtime.** Rejected: Blender's MaterialX export has no hook for about 30 of 100 node files, OSL on GPU is OptiX-only with documented limits, large dependencies against the build budget (`research/07` F3).
- **Per-lobe replacement by extension kinds** (`research/17`). Rejected: the extension stage would carry all OpenPBR lobes plus every kind, and layering needs E(ωo) that several kinds cannot define.
- **Complex IOR in the base/specular colour slots** (`research/17`). Rejected: colour slots are bounded and filtered.
- **Thin film by Airy summation truncated at m = 3** (Belcour and Barla 2017, v1). Rejected: truncation exists for spectral-sensitivity integration; per wavelength the closed form is exact and no more expensive, while the truncation residual over conductors is of order (r12 r23)^4.
- **Stochastic emission per selected child.** Rejected: Mix(Emission, Diffuse) seen directly would carry selection noise; the deterministic emission segment costs only the emission subgraphs.
- **Linear-space filtering of 8-bit sRGB textures.** Rejected: it departs from Blender's node values (owner decision 14).
- **Ray-query shading variant as an OptiX raygen kernel** (Cycles `shade_surface_raytrace`). Not adopted: it conflicts with 0002 D11; left to the owner and a 0002 amendment (Risks).
- **Heitz random walk for rough dielectrics in the engine.** Rejected for the device path: CPU-only in v1, register risk; Turquin albedo scaling meets the furnace target; the walk stays a test oracle.
- **Hardware texture filtering.** Deferred: 8-bit fixed-point weights break CPU/GPU agreement; adopted only with a measured win.
- **Spectral and extension authoring by custom nodes.** Deferred until the inliner question is answered (Measurement M-7); the Material panel works either way.

## Consequences

- Easy: adding an opcode is one `ops.def` line, one kernel function and one test; adding a node lowering is one addon table entry and a test; adding a spectrum is data; an extension kind's inputs are one `ext_fields.def` entry. These are small task specs.
- Easy: a material edit is a compile in the core plus an upload of words; constant materials skip the interpreter.
- Easy: correctness tests run on the CPU build of the same lobe and op functions in seconds (spike A: 0.35 µs per BSDF evaluation).
- Hard: 32 VM registers is tight for the heaviest procedural graphs; those fail to compile (magenta, reported) until M-4 decides.
- Hard: per-material extension masking, coated gratings and glossy fluorescent plastics are not expressible in the first release.
- Hard: AO, Bevel and Raycast are approximations until in-shader ray queries exist.
- Cost when unused: `shade_surface_ext` launch skipped by the host; `metal_ior` and `closure_weight` are 8 B of thread-local stack; the 9.4 MB upsampling table is resident in every scene; mips add a third to texture memory; an opaque material never runs the `opacity` entry.
