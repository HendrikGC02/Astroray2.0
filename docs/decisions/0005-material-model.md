# 0005 — Material model, extension lobes and shader-node evaluation

Status: proposed (2026-11-14), revised after review (2026-11-14), reconciled with `RULINGS.md` (2026-11-14). The record and register-file layout (items 2 and 3) is ratified only after measurement M-1.

## Context

The integrator needs bounded per-hit material state; Blender users author arbitrary node graphs; the owner wants custom material types beyond OpenPBR (decision 16), diffraction gratings with the light-tracing path that makes them useful (17), one extension behaviour per material (18), fluorescence for all its use cases (19), complete breadth (7), physics and the OpenPBR specification as the correctness target (1), node behaviour that matches Blender exactly (14), one kernel source (2), and a viewport where a material edit is an upload, not a compile. Most implementation will be done by Sonnet-class agents from small task specs, so adding a node, an opcode or a lobe must be a local change.

The spine fixes the frame: one fixed OpenPBR Surface 1.1.2 record seen by the common shade kernel; spectrum sources for colour and IOR slots; at most one extension behaviour from a closed list, in a separate stage; a bytecode VM that fills the record and never emits closures; stochastic Mix Shader; magenta plus a per-render report for unsupported nodes (SPINE §5). Kernel facts are MEASURED in spike A: the fused N=4 shade+NEE kernel uses 148 registers, 0 spills (128 with `__launch_bounds__(256,2)`, +56% throughput); a VM fused into that kernel costs 150 registers / 304 B stack and is 30% faster than a separate parameter pass (1.59 ms vs 2.256 ms per 2^20 paths). The 304 B are the spike's 176 B record plus its VM register file of 16 scalars and 4 `Spec<4>`, i.e. 32 floats (`spikes/A-kernel-budget/include/stages.h`, `stage_param`). `__noinline__` with by-value records is harmful; by-pointer recovers most of it. The kernel gate is 0002 D10's, as amended by ruling 17 (spills and stack in the shipping capped build against recorded allowances; the uncapped register count is a `check full` warning); runtime flags rather than template variants.

v1's failures shape the rest (`v1-lessons/research/materials.md`, `blender.md`, `research/07` F7): a fat shared material struct; a closure graph whose lobe count saturated the shade kernel at 254 registers; a constant-folding translator that turned every texture-driven chain grey (0/8 production materials correct at baseline); a VM bolted on as a second path, with hand-mirrored opcode enums; 340 of 527 sockets dropped silently. Ground truth is weak: the MaterialX reference graph leaves dispersion unwired and Blender's own OpenPBR implementations disagree with each other (`research/05` B6), so analytic and furnace oracles come first.

Spike A omitted texture fetches, spectral upsampling and procedural nodes. Every register or size number that is not from a spike is marked PROVISIONAL and is measured early in the build (Risks).

## Decision

### A. Record, stack budget and lobe stack

1. **Pin OpenPBR Surface 1.1.2** (release 2026-11-05). Lobes are written from the spec text and cross-checked against Adobe's `openpbr-bsdf` (Apache-2.0, targets 1.1.1); the 1.1.2 deltas (squared coat transmittance in layering, #304; thin-walled subsurface colour applied once) are applied by us. OpenPBR 1.2 slots (retroreflectivity, haze) are not added until 1.2 is released.
2. **Three layouts.** (a) `MaterialHeader`, 16 B per material in device memory: `program_offset u32` (the program starts with an entry table, item 32), `const_offset u32`, `ext u32` (= `ext_kind u8 | ext_index u24`), `flags u32` (item 43). (b) A per-material constant block holding all 41 OpenPBR inputs at their authored values (scalars `f32`, colour and IOR inputs as 24 B `SpectrumRef`, item 9). (c) The resolved record `OpenPBRParams`, filled per shading point in thread-local memory and passed by reference, never by value. It holds only what the lobe stack reads after the VM has finished:

| Group | Fields | Type | Bytes at N=4 |
|---|---|---|---|
| Scalars | base_weight, base_diffuse_roughness, base_metalness, specular_weight, specular_roughness, specular_roughness_anisotropy, transmission_weight, transmission_depth, transmission_scatter_anisotropy, subsurface_weight, subsurface_radius, subsurface_scatter_anisotropy, fuzz_weight, fuzz_roughness, coat_weight, coat_roughness, coat_roughness_anisotropy, coat_ior, coat_darkening, thin_film_weight, thin_film_thickness (µm), thin_film_ior, geometry_opacity, closure_weight (item 38) | 24 × f32 | 96 |
| Spectral slots | base_color, specular_color, specular_ior, transmission_color, transmission_scatter, subsurface_color, subsurface_radius_scale, fuzz_color, coat_color | 9 × f32[N] | 144 |
| Frame | geometry_normal, geometry_coat_normal, geometry_tangent, geometry_coat_tangent (world space, after bump and normal maps) | 4 × f32[3] | 48 |
| Complex IOR | `metal_ior`: constant-block offset of the (n, k) `SpectrumRef` pair; 0 = F82 mode (item 12) | u32 | 4 |
| Flags | thin_walled, ior_dispersive | u32 | 4 |
| Total | | | 296, padded to 304 (PROVISIONAL) |

   Not in the record: emission, holdout and shadow transmittance are VM outputs consumed at once (item 38); `transmission_dispersion_scale` and `_abbe_number` are resolved into `specular_ior` per wavelength (item 9); n and k are per-material constants read through `metal_ior`; extension kinds reuse fields they ignore (item 16). Lengths are in scene units (metres), not OpenPBR's centimetre metadata default.
2a. **Interior medium fields** (ruling 28). Each material's constant block also holds `interior_ior`, the constant spectral source (CONST, CAUCHY_ABBE, SELLMEIER or TABLE) of its `specular_ior` (a textured IOR contributes its constant fallback and is reported `approximated`), and `medium_priority` (u8, default 0), authored on the Material's Astroray panel (0007). The medium stack reads both without running the VM (0006 D16-D17).
3. **Stack budget.** 0002 D10's stack limit for VM kernels, checked in the shipping capped build (ruling 17), is split: record ≤ 304 B; VM register file 32 × f32 = 128 B, the size spike A measured (176 B record + 128 B file = 304 B); the remainder for everything else (spike A: 32 B of unidentified local in every inlined variant). Both arrays are dynamically indexed (`STORE_SLOT` by slot index, registers by operand), so both live in local memory; the split is enforced by `static_assert` and by the gate. Each kernel declares one `VmRegs` array and passes it by pointer to every interpreter call, so programs run one after another (the surface program, then an emission, light or world program inside NEE) share it; the interpreter never declares its own. Cycles does the same: NEE evaluates the emitter's shader into a separate small `ShaderDataTinyStorage` while the surface `ShaderData` stays live, and the SVM stack is a local of the evaluation call (`kernel/integrator/shade_surface.h`, `svm/svm.h`). Growing either part requires shrinking the other or a 0002 change.
4. **Lobe stack = OpenPBR's nine primitive lobes in the spec's layering tree** (`research/05` B3): fuzz over coat over base substrate = mix(metal, dielectric base); dielectric base = mix(opaque, translucent); opaque = mix(glossy-diffuse, subsurface); top = mix(transparent, surface, opacity); emission under coat and fuzz (attenuation applied where emission is evaluated, item 38). Models: EON diffuse (Portsmouth, Kutz, Hill 2025); GGX with height-correlated Smith (Heitz 2014) and VNDF sampling (Heitz 2018); F82-tint metal (Hoffman 2019; Kutz, Hasan, Edmondson 2021) or exact complex Fresnel (item 12); Walter et al. 2007 dielectric with the spec's `specular_weight` F0 modulation; coat with darkening and the coat-IOR TIR fix as specified; fuzz by Zeltner, Burley, Chiang 2022 (LTC); thin film by the closed-form Airy reflectance of a single film, evaluated per transport wavelength with complex amplitudes for s and p and averaged (Born and Wolf 1999 §1.6; the m → ∞ limit of Belcour and Barla 2017 Eq. 10), no truncation and no RGB sensitivity table. A microfacet lobe whose α is below 1e-3 on both axes is sampled as a delta lobe (pbrt-v4 `TrowbridgeReitzDistribution::EffectivelySmooth`); its sample carries `DELTA`. This test is the single predicate `lobe_is_delta` in the lobe library that 0004 D19 calls. Subsurface: the shade stage samples the subsurface lobe and hands the path to the random walk (item 4a). Translucent base with `transmission_depth > 0` (ruling 28): the compiler lowers `transmission_color`, `transmission_depth`, `transmission_scatter` and `transmission_scatter_anisotropy` to a constant `volume` program filling 0006 D2's coefficient-level `MediumSample` (μt = −ln(T)/depth per wavelength and the scattering part from `transmission_scatter`, both as specified; HG phase with that anisotropy), and refraction pushes that medium onto the medium stack with the material's `medium_priority` (item 2a; 0006 D16-D17). One lobe-selection function returns the weights used by eval, sample and pdf alike. The stack's result is multiplied by `closure_weight`.
4a. **Random-walk subsurface: model and record** (this record owns both, ruling 27). The interior is a homogeneous medium per shading point with σ_t and single-scatter albedo per transport wavelength from the specification's parameterisation (mean free path `subsurface_radius` × `subsurface_radius_scale`, albedo by the spec's van de Hulst inversion of `subsurface_color`) and an HG phase with `subsurface_scatter_anisotropy`. Free-flight distance and event choice use the path's hero lane with r_u/r_l rescaling, as media do (0003 decision 6, 0004 D1; rulings 4-5); random numbers come from 0003's stream 3. `shade_subsurface` takes a step and `intersect_subsurface` traces its local ray against the hit instance's GAS (0002 D8, D11). **Walk**, as Cycles' random walk (`kernel/integrator/subsurface_random_walk.h`, Apache-2.0; re-read before coding): the path enters through the surface by a cosine-weighted sample about the inward normal; each step traces its free-flight distance as a local ray; if that ray reaches the instance's surface first, the walk exits at the hit and the path continues from it with a Lambertian lobe facing out of the surface (NEE included), otherwise the walk scatters by the HG phase and steps again. A walk still inside after 256 steps (Cycles' `BSSRDF_MAX_BOUNCES`, SOURCE, PROVISIONAL) ends the path with 0003's `VOLUME_LIMIT`, counted and reported (0001 `MEDIUM_PATH_LIMIT`). **Record**, a per-path side buffer that 0003 decision 20 allocates: σ_t `Spec`, single-scatter albedo `Spec`, anisotropy Real, step counter u32, 40 B (PROVISIONAL).
5. **Energy conservation by construction.** Layering is OpenPBR albedo scaling, `f = f_top + T_top² (1 − E_top(ωo)) f_bottom` and its weighted lerp form, with E from tables; inter-layer multiple bounces are ignored and non-reciprocity is accepted, both as the spec states. Single-lobe energy loss is compensated per Turquin 2019 (1/E scaling with the Fresnel-weighted term) for conductor and dielectric reflection, and with a combined reflection+transmission 1/E table for rough dielectrics (the approach of Cycles' `ggx_glass_E`, `v1-lessons/research/materials.md`). Thin film: single-lobe compensation stays film-free (v1), and the base under a filmed specular layer is attenuated with `E_spec(μo, α) · F_film(μo) / F(μo)`, which is exact at α = 0 and an approximation for rough film; before coding it is compared with the thin-film layering in Adobe's `openpbr-bsdf`, and the reference wins if they differ. The Heitz et al. 2016 multiple-scattering random walk is not in the engine; it is the CPU test oracle for rough dielectrics.
6. **Tables**: E_spec(μ, r) 32×32, E_avg(r) 32, E_diel(μ, r, η) 16³ reflection-only (coat and glossy-diffuse layering), E_glass(μ, r, η) 16³ plus its η<1 inverse; the roughness axis is r = (αx αy)^(1/4), which is how anisotropic lobes index them (v1 and Cycles). All E tables are geometric (grey; colour enters through per-wavelength F0) and are generated by one host tool from the engine's own lobe code (CPU build, importance-sampled), because v1 showed tables baked with a different G or sampler leave 12-19% furnace error; they are checked in with a hash, regenerated and compared with Adobe's tables by `check full`, run on demand. The fuzz LTC fit (32×32×3) is imported from `tizian/ltc-sheen` (Apache-2.0), because the lobe is that fit; its albedo channel is checked against Monte Carlo integration of our fuzz lobe. EON's albedo is analytic.
7. **Spectral semantics**: every spec formula (sqrt, −ln T, powers, F82 terms) is applied per transport wavelength to resolved spectra (`research/05` B4). Agreement with RGB-defined spec numbers is a measured tolerance, not an identity (Verification 4).
8. **Orientation and shading normals**: front-face is a stored hit attribute (0003 flag `FRONT_FACE`) that survives every instance transform (v1 lesson); reflected samples below the geometric surface are rejected (pbrt-v4); bump and normal maps use the shadowing term of Conty Estevez, Lecocq, Stein 2019, honouring Blender's per-material bump-correction setting. Every lobe and extension kind takes `TransportMode {Radiance, Importance}` (Veach 1997 §5.2-5.3; pbrt-v4), which selects the η² factor and the adjoint shading-normal correction; the light-tracing pass needs it.

### B. Spectrum sources

9. **Slots are resolved at the path's 4 transport wavelengths** (SPINE §3), so the BSDF never sees RGB and never branches on source type. **`SpectrumRef`** (24 B: `kind u8, semantic u8, aux u16, index u32, p[4] f32`). Closed kinds: `CONST`; `RGB` (Jakob and Hanika 2019 sigmoid coefficients c0..c2 plus scale, precomputed on the host for constants); `TABLE` (piecewise-linear spectrum in the scene spectrum arena, times scale); `BLACKBODY` (T, scale; Planck per 0003 decision 25); `CAUCHY_ABBE` (n_d, V_d, dispersion scale: OpenPBR's dispersion law); `SELLMEIER` (six coefficients in the arena); `GAUSSIAN` (centre, width, peak). Spectrum math, SPD files and element-line bakes are host-side compositions into `TABLE`; no device code. **`BLACKBODY` and `CAUCHY_ABBE` resolve in M1b** (ruling 87), each from one kernel function that `resolve()` and the opcode of the same name both call: `blackbody_spec(T, scale, lambda)` = `scale` x `planck_radiance` (0003 decision 25) per lane, with `p[1]` = the Blackbody node's scale x `blackbody_y_normalised(T)` set on the host, so the display Y of the stored colour is the node's scale and the emission strength multiplies it (0003 decision 11); a `BLACKBODY` ref is analytic (item 39) and skips the illuminant multiply that an `ILLUMINANT` slot applies to every other kind. `cauchy_abbe_ior(n_d, V_d, s, lambda)` is the Cauchy law n(lambda) = A + B / lambda^2 of OpenPBR 1.1.2 (dispersion section) with the Fraunhofer lines d 587.6, C 656.3, F 486.1 nm: B = s (n_d - 1) / (V_d (lambda_F^-2 - lambda_C^-2)), A = n_d - B / lambda_d^2, so the medium's Abbe number is V_d / s (s = 0 is flat n_d), n(lambda_d) = n_d exactly, and lambda is clamped to [360, 830] nm (0003 decision 8). The compiler accepts exactly the pairs (`BLACKBODY`, ILLUMINANT slot) and (`CAUCHY_ABBE`, IOR slot), and only from constant parameters: a Blackbody node feeding the material's only emission with a constant strength, a Cauchy-Abbe node feeding `specular_ior`. Every other shape (several emissions, a Blackbody or Cauchy-Abbe in another slot, a linked parameter, T not finite and positive, V_d not positive) is `PROGRAM_REJECTED` naming the node. Per-point temperature or n_d is the M2 dispersion work.
10. **The lift semantic is fixed by the slot**, never chosen by the user or the source (spine amendment accepted, ruling 23):

| Semantic | Colour input | Float input | Slots |
|---|---|---|---|
| REFLECTANCE | clamp each channel to [0,1], then albedo sigmoid | grey | base, specular, transmission, transmission_scatter, subsurface, fuzz, coat colours; medium albedo colours (0006) |
| UNBOUNDED | unbounded form, scale = 2·max | grey | subsurface_radius_scale |
| ILLUMINANT | unbounded form × the working space's illuminant (0003 decisions 15-16); a `BLACKBODY` source is analytic and takes no illuminant factor (item 9) | grey × illuminant | emission colour; light, world and medium emission colours (0004, 0006) |
| IOR | refused (compile error) | flat spectrum per shading point; with Dispersion Scale > 0 it is n_d of a constant `CAUCHY_ABBE` (item 9; per-point n_d is M2) | specular_ior; metal n and k accept no per-point input (item 12) |

   So a float texture linked to Principled IOR is accepted. A constant above 1 in a REFLECTANCE slot is clamped and reported `approximated`; an image bound to such a slot whose decoded range exceeds [0,1] is reported once at load. Out-of-range evaluation follows 0003 decision 8.
11. **Textures and lifting**: images are decoded and interpreted in the file's working space by 0007 per `Image.colorspace_settings.interop_id` (`data` means no transform and no lift; decoding libraries must be on 0001's dependency list, ruling 20) and filtered as Blender does (item 34). The lift is applied per shading point to the filtered RGB by the `RGB_LIFT` opcode: one lookup in the coefficient table, which trilinearly interpolates the table's coefficients (`rgb2spec_fetch`), then the sigmoid per wavelength. Per-texel coefficients are never stored or filtered. One table is resident, the working space's (0003 decision 16).
12. **Complex IOR.** n and k accept only `TABLE`, `CONST` or analytic sources (n, k from refractiveindex.info, CC0), never textures, so they are per-material constants: the record holds only their constant-block offset (`metal_ior`), and the metal lobe resolves them at the transport wavelengths when it runs. A non-zero `metal_ior` makes the metal lobe use exact conductor Fresnel (Born and Wolf; pbrt-v4 `FrComplex`). Everything that needs an albedo (energy compensation, coat darkening's E_base, layering) uses the F82-tint fit computed per wavelength from (n, k): F0 exact at normal incidence, tint = F_exact(82°)/F_Schlick(F0, 82°) (Hoffman 2019's parametrisation), so the existing tables apply and the residual is measured (Verification 4). Blender's Metallic "Physical Conductor" mode supplies RGB n and k, possibly textured: the program converts them per channel to (F0, F82 tint) with the same exact formulas, lifts both as REFLECTANCE into base_color/specular_color, uses F82 mode, and reports `approximated`.
13. **Polarisation: none in 2.0.** Fresnel functions compute Rs and Rp and return their mean; nothing is reserved. A polarised build would re-implement every lobe with Mueller-valued evaluation; that needs its own superseding record.

### C. Extension mechanism

14. **Closed list.** `ext_kind u8`: `0 NONE`, `1 GRATING`, `2 HAIR`, `3 FLUORESCENT`, `4 MULTILAYER`, `5 MEASURED`. Values 4 and 5 are enum values only (item 28, ruling 36). Anything else (Hapke regolith, glints, pearlescent, scratches, holographic foil, toon, ray portal, retroreflection) needs a superseding record.
15. **Full replacement.** An extension kind replaces the whole OpenPBR lobe stack. From the record it keeps only geometry_opacity, closure_weight, the frame and the fields its field map declares (item 16); emission is evaluated unattenuated (item 38). Coat, fuzz, thin film and all other BSDF inputs of that material are reported `ignored`. Albedo-scaling layering therefore never meets an extension lobe, and no kind has to define E(ωo). Owner decision 18 makes this sufficient.
16. **Parameters.** Per-material constants: a 64 B block (16 × 32-bit, PROVISIONAL) in `ExtParams[]` at `ext_index`; anything larger is a handle into the scene `TableArena` (byte buffer, 16 B aligned, `u32` offsets). Per-point inputs: each kind declares, in one hand-written table `ext_fields.def` (validated by opsgen, see below), which record fields it reads and under which name, using fields the OpenPBR stack would have used and the kind ignores (for example HAIR's melanin, melanin redness and random roughness in subsurface scalars; FLUORESCENT's concentration in a fuzz scalar). This costs no storage. Kind and constants are authored on the Material's Astroray property panel (a `PointerProperty` on Material, 0007); per-point inputs come from the node tree (Principled Hair sockets, Curves Info, Attribute).
   *Write-back (ruling 87, task 168).* `ExtParams` is one `struct` of 16 `u32` words (`src/kernel/material/ext_params.h`, `static_assert` 64 B); `ar_material_desc::ext_constants[64]` is that block byte for byte, and each kind lays out its own words (the grating's is item 23's). The host compiler (`compile_extension`) copies it into the compile result and runs the kind's validity check; it does not interpret the words itself. The kind list and the per-point fields live once in `src/kernel/material/ext_fields.def`, hand-written like `ops.def`: rows `AR_EXT_KIND(name, id)` (`id` the `ext_kind` byte, unique, at most 255) and `AR_EXT_FIELD(kind, record_slot)` (a `RecordSlot` enumerator the kind keeps). A kind always keeps `geometry_opacity` and the frame (closure weight is the selection's and no graph stores it); any other BSDF slot stored in its graph has its STORE_SLOT removed before the graph compiles (so a slot-level refusal there, a SpectrumRef kind, a clamp or an image, no longer reaches the program; an unsupported or invalid node still rejects the material, as for OpenPBR) and is reported `INPUT_IGNORED`, once per slot. GRATING has a kind row and no field rows. `tools/opsgen.py` validates the file (unknown kind or `RecordSlot`, duplicate row or id, id above 255, with file and line) and emits `EXT_KINDS` and `EXT_FIELDS` into `_ops.py`; it does not generate the file. The `ExtKind` enum and the compiler's tables are built from it with the X-macros.
17. **Stage.** A material with `ext_kind ≠ 0` carries a material flag that 0002's `route_hit` (D11) reads to send its hits to the extension identity of `shade_surface`, `shade_surface_ext` (`ShadeKind::Ext`), or on a light path to `shade_light_path_ext` (`ShadeKind::LightExt`; 0004 D21). `shade_surface_ext` has the same body as `shade_surface`, including the VM and NEE, plus `switch (ext_kind)`; NEE serves the non-delta kinds (HAIR, FLUORESCENT). `shade_surface` and `shade_light_path` contain no extension code. Interface per kind: `sample/eval/pdf(const OpenPBRParams&, const ExtParams&, const ShadeFrame&, wo, wi, TransportMode, const Spec&)`; sample results carry flags `DELTA`, `WL_DEPENDENT_DIR` (terminate secondaries) and `REWRITES_WL` (FLUORESCENT, item 26). An empty segment is not launched (0002 D7).
18. **Budget rule.** Extension code is compiled into exactly two kernels, `shade_surface_ext` and `shade_light_path_ext`. Each holds every kind and must meet 0002's gate; a kind that breaks it first shrinks its live state (tables, recomputation). One split is named, on measurement only: HAIR into its own identity (`shade_hair` and `shade_light_path_hair`, 0002 D8), since it has its own primitive anyway. Any further kernel carrying extension code needs a superseding record. Names and the kernel list are 0002's (D8, ruling 6).
19. **No masking.** An extension material's node tree supplies only the fields of item 15; a Mix Shader cannot combine an extension with an OpenPBR branch inside one material (use material slots).
20. **Queues.** Materials add the identities of item 18 to 0002's list. They trigger other stages: the random walk of item 4a (kernels in 0002 D8), the light-tracing pass (0004), the medium stack (0006).

### D. Diffraction grating

21. **Model**: 1D periodic grating with delta diffraction orders, unpolarised (mean of s and p). Directions come from the grating equation in direction-cosine space (Harvey and Vernold 1998). With grooves along the record tangent T and grating vector ĝ = N × T, the tangential projection t of a unit direction obeys, for order m: reflection `t_o = −t_i + m(λ/d) ĝ`; transmission `n_o t_o = −n_i t_i + m(λ/d) ĝ`; an order with |t_o| > 1 is evanescent and absent. Order efficiencies η_m(λ, cosθ_i) come from a table.
22. **Sampling**: order m is chosen with probability p_m = η̄_m / Σ_prop η̄, where η̄_m is η_m averaged over the four transport wavelengths (0 where evanescent), a permutation-invariant reduction (0003 decision 6). Order 0 in reflection, and in transmission over a non-dispersive substrate, has a wavelength-independent direction: all four lanes continue with throughput η_0(λ_j)/p_0. Any other order has a wavelength-dependent direction: secondaries are terminated (0003's `terminate_secondaries`, pbrt-v4 `TerminateSecondary`) and lane 0, the lane `terminate_secondaries` keeps (0003 decision 5, ruling 24), continues with η_m(λt[0])/p_m. The estimate is unbiased because p_m > 0 wherever η_m(λt[0]) > 0. Transmission in Radiance mode also carries (n_i/n_o)². Eval and pdf are zero (delta); no NEE. On a CD most energy is in order 0, which therefore keeps full colour sampling.
23. **Parameters** (`ExtParams`): `pitch_nm f32`, `mode u8` (reflect, transmit), `m_min, m_max i8` (|m| ≤ 8), `table u32` (TableArena handle), substrate IOR `SpectrumRef` for transmission. Groove direction is `geometry_tangent`, so the node tree can drive it (a radial Tangent gives a CD). Table: η at 5 nm over 360-830 nm (95 samples) × 16 bins of cosθ_i × ≤ 17 orders, f32, ≤ 103 KB per grating, linearly interpolated. Layout (ruling 87): words w[0] `pitch_nm`, w[1] `mode | m_min << 8 | m_max << 16` (bytes, top byte 0), w[2] `table`, w[3..8] the substrate `SpectrumRef` (CONSTANT or CAUCHY_ABBE, IOR semantic; read in transmission only), w[9..15] unread; the compiler refuses a non-finite or non-positive pitch, |m| > 8, m_min > m_max, a mode other than 0 or 1, and a transmissive grating without such a substrate. The table is `[order][cos bin][wavelength]` with order index m − m_min, wavelengths 360 + 5k nm, cos nodes k/15 (k = 0..15, so normal and grazing incidence are nodes), 17 × 16 × 95 × 4 B = 103 360 B at most; lookup is bilinear in λ and cosθ_i, clamped at both ends of both axes. The table is indexed by |cos| of ωo: on a camera path the light arrives along ωi, and the reciprocity theorem (Palmer, Diffraction Grating Handbook 7th ed. §9.10) makes the efficiency of order m the same with incidence and diffraction exchanged. Sample: `grating_sample(GratingParams, GratingTable, Frame, ωo, TransportMode, λ, u)` with u the extension-choice dimension (0003), the frame from (N, T) so local x runs along the grooves and y along ĝ; ambient index 1, substrate on the −z side; delta convention as the lobe stack (pdf = p_m, f = η/|cosθ|, so f|cos|/pdf = η/p_m); a non-zero order, or order 0 into a CAUCHY_ABBE substrate, sets `WL_DEPENDENT_DIR` with only lane 0 non-zero; pdf 0 when every order is evanescent or of zero efficiency or the chosen order is evanescent at λt[0].
24. **Efficiency tables are generated on the host only**, from generator inputs that never reach the device: sinusoidal phase profile with peak-to-peak groove depth `depth_nm`, by scalar thin-phase theory, η_m = J_m²(φ/2) with φ the peak-to-peak phase modulation (Goodman 2005); blazed sawtooth with blaze angle `blaze_deg`, by the scalar sinc² form (Palmer and Loewen 2005); both times the coating reflectance from its complex IOR (reflective) or the substrate transmittance (transmissive); or a user CSV from a rigorous solver or measurement (RCWA, Moharam and Gaylord 1981; not shipped). Scalar theory holds only for d ≫ λ; generating a DVD-class pitch reports "scalar theory out of range". Presets (PROVISIONAL): CD, 1.6 µm, sinusoidal, depth 120 nm (about a quarter wave at 780 nm in polycarbonate); 600 and 1200 lines/mm, blazed for 500 nm in first-order Littrow (8.6° and 17.5°). Every cell satisfies Σ η ≤ 1; clipping is reported. The two scalar formulas, including the phase-depth expression, are re-read from the cited books before coding. Sinusoidal phase depth (ruling 87; PROVISIONAL, lead ruling on task 169): reflection φ = 4πh cosθ_i/λ, the Rayleigh roughness phase of two rays reflected at heights h apart (Zhao, arXiv:1704.03783 §2 eqs. 1-2, with the grazing angle α = 90° − θ_i), which at normal incidence reproduces Palmer's scalar-domain peaks (first order at λ = 3.41h, second at 2.05h; Diffraction Grating Handbook 7th ed. §9.3, §9.5); transmission φ = 2πh|n_s − 1|/λ, independent of angle, the thin-element phase t = exp[ik(n − 1)h] (MIT 2.71 2014 lecture 14 eq. 9; Goodman 2005 §5.1) with ambient index 1. The order-dependent non-paraxial form (Harvey and Pfisterer 2020) is not used. Scalar range (PROVISIONAL): the builder refuses, with "scalar theory out of range", a profile whose groove modulation h/d is not below 0.10, Palmer 7th ed. §9.4's scalar domain for sinusoidal grooves (after Loewen, Nevière and Maystre 1978). It is a modulation-depth rule, not a d/λ rule: the CD preset (120 nm over 1.6 µm, 0.075) is in; a DVD-class pitch at that depth (120 nm over 0.74 µm, 0.16) is out. The clip bounds the sum over every order in the table, which bounds the propagating orders at any azimuth and, by the convex lookup, between nodes; it acts only when the coating factor exceeds 1.
25. **Reachability and the light-tracing pass.** Area, sphere and sun-disc lights and the environment are reached through a grating by BSDF sampling. Zero-area emitters (point, spot, laser) through a grating onto a diffuse receiver are reached only by the light-tracing pass (0004). Materials give that pass: `sample` in Importance mode for every lobe and kind; delta and `WL_DEPENDENT_DIR` flags; eval at non-delta vertices for the camera connection, except at FLUORESCENT surfaces (item 26); emission evaluation for emissive surfaces. Light paths carry wavelengths drawn from the same sensor wavelength table as camera paths, recomputed from their key (ruling 7, 0003 decision 2); after a non-zero order only lane 0 continues (ruling 24). A point light seen directly in a grating is a delta-delta configuration of zero measure, unrenderable by any method, as with a mirror. Roughness-broadened orders are not designed: no citable model with a usable licence was found (`research/17`; PLTFalcor is CC BY-NC).

### E. Hair, fluorescence and later kinds

26. **FLUORESCENT**: EON diffuse with base_color as elastic albedo, plus reradiation M(λi→λo) = Q · a(λi) · e(λo) (separable form, Glassner 1994; Wilkie et al. 2006), or a measured bispectral matrix (Hullin et al. 2010) as a 2D table. Parameters: quantum yield Q, excitation table a, emission table e; concentration is a per-point field (item 16). On a camera path the kind picks the elastic or inelastic event with the extension sampler dimension (0003's dimension map), and for the inelastic event calls `terminate_secondaries`, draws λi from the excitation distribution for λt[0], the lane it keeps (ruling 24), and calls `rewrite_wavelength` with M/p (0003 decision 5); NEE and BSDF sampling of the Lambertian reradiation lobe then proceed at the single rewritten wavelength with 0004's MIS (ruling 5) under 0003 decision 7's convention after a rewrite. The film keeps its film wavelength (SPINE §3). The light-tracing pass never connects at a FLUORESCENT surface, and a light path that reaches one ends there: camera paths own those contributions (ruling 44, 0004 D19). Sampling follows Mojzík, Fichet, Wilkie 2018. The reradiation function is one file, shared with 0006 D15's volumetric fluorescence. Brighteners, minerals and pigments are covered by this kind.
27. **HAIR**: Chiang et al. 2016 far-field model with per-wavelength σa from melanin concentrations or from colour (pbrt-v4 `HairBxDF` and `SigmaAFromReflectance`, Apache-2.0). Inputs: base_color (direct colour) and the declared per-point fields (melanin, redness, roughness, random). Principled Hair (Chiang) maps exactly; Principled Hair (Huang) and Hair BSDF map to it and are reported `approximated`. Needs curve primitives (0002's curve closest-hit program, 0007's hair `Curves`) and self-intersection avoidance on curves, which no record specifies yet (0002 Risk 13).
28. **MULTILAYER and MEASURED** keep enum values 4 and 5 (item 14) and this line; their designs (transfer-matrix thin-film stack; RGL measured BSDF) stay in `research/17` (ruling 36).

### F. Shader-node evaluation

29. **Pipeline.** (1) The addon (Python, GPL) calls `inline_shader_nodes()` on the evaluated Material, World or Light, walks the inlined tree and translates each Blender node into engine ops; the Blender-to-engine mapping lives in the addon, so the core knows nothing of Blender (SPINE §1). It sends a host-neutral graph (typed op nodes with constant or linked inputs) through 0007's scene-edit functions. (2) The core compiler (C++) does type inference, constant folding, segment splitting (item 38), dead-code elimination per entry, linear-scan register allocation, bytecode emission, constant-block and `SpectrumRef` packing, and returns its errors as entries of 0001's per-render report. A material edit is a recompile and an upload; no kernel is compiled. (3) **Translation cache**: the addon keeps each material's translated graph keyed by the original datablock's `session_uid` and re-translates only materials (or node groups) that 0007's update classification marks changed; materials with animated node values are therefore re-translated once per frame change, and nothing else is. Its time budget is 0009 B-24 (M-8).
30. **One opcode table**, `ops.def` (X-macro), generates the core enum, the interpreter's `switch`, compiler metadata (arity, operand types, cost class, and the interval rule 0006 D7 requires of every opcode reachable from a volume program), the addon's Python op schema (build step, never hand-mirrored), and the node coverage matrix. Op implementations are kernel-library functions compiled for CPU and GPU; constant folding calls the CPU build of the same functions, so folding cannot disagree with evaluation. The interval rules named in the table are pure functions in `src/kernel/vm/interval.h` and opsgen refuses a row whose rule is not defined there (ruling 87); each rule widens sums and products one ulp outward (Moore 1966; IEEE 754-2008 4.3), a NaN endpoint gives `{NaN, NaN}` from every rule (the majorant builder reports `!(lo <= hi)` as unsupported, 0006 D7), and `lo > hi` is a caller error with no defined result.
31. **Encoding, registers and control flow.** 32-bit words; an instruction word is `opcode u8 | a u8 | b u8 | c u8` (register operands), immediates follow. Register file: 32 × f32 per thread (item 3); value types `f32`, `f32x3` (colour, vector; colours stay RGB until a `STORE_SLOT` lifts them into a slot), `spec` (N floats, only for spectral-typed values such as Blackbody). A program needing more registers fails to compile: magenta and a report entry, no fallback. Control flow is forward-only, so every program terminates and its length bounds its time:
   - `JMP off`: unconditional forward jump.
   - `BRANCH_MIX rf, off`: with f = clamp(r[rf], 0, 1) and u the entry's **selection uniform**: if u < 1 − f, set u ← u/(1 − f) and fall through to the first child; else set u ← (u − (1 − f))/f and jump to the second child, `off` words from the `BRANCH_MIX` word (positive). The rescaled u is kept below 1 (pbrt-v4 `SampleDiscrete`); a NaN factor or a u outside [0, 1) stops the run (`BAD_OPERAND`). The selection uniform is a scalar in the interpreter state (`VmState::select_u`, passed to `run_entry` by pointer), not a register: a surface kernel sets it to the event's lobe-choice uniform before the `surface` entry, only `BRANCH_MIX` rewrites it, and the kernel's lobe choice reads it after the entry, so the Mix selection and the lobe choice share one uniform (0004 D14). An entry run without one stops at a `BRANCH_MIX` (`NULL_POINTER`). A register carrier (r31 written before and read after the entry) was measured: it raised `k_shade_surface`'s stack from 384 to 688 B.
   - `BRANCH_ADD off`: as `BRANCH_MIX` with f = 0.5 on the same selection uniform, and `closure_weight *= 2`.
   - `END`: ends the current entry.
   Heavy ops (Voronoi, Gabor, Sky) are called `__noinline__` with the register file by pointer, the form spike A measured cheaper than noinline by value.
32. **Entry points and the kernels that run them.** Each material program begins with an entry table of four `u32` offsets (`surface`, `opacity`, `emission`, `volume`; 0 = absent or constant); World and Light trees compile to programs with their own single entry. All kernels named here are in 0002's list (ruling 6).

| Entry | Evaluates | Run by | Produces |
|---|---|---|---|
| `surface` | emission segment, selection, the selected child's BSDF block (item 38) | `shade_surface`, `shade_surface_ext`, `shade_light_path`, `shade_light_path_ext` | record, Le, holdout |
| `opacity` | opacity subgraph of every child | `shade_shadow` (0002 D8, D11), including light-pass camera connections | T(λ) |
| `emission` | emission segment only | NEE on an emissive triangle in the surface kernels; `generate_light` (0004) | Le |
| `light` | Light node tree and IES, emission only | `shade_light` lamp hits (0004 D8); lamp NEE in the surface kernels; `generate_light` | Le |
| `world` | World node tree | `shade_background`; environment NEE in the surface kernels; `generate_light` | Le |
| `volume` | Volume socket (item 39) | `shade_volume` and the marcher in `advance_geodesic` (0006 D9) | medium sample |

   A constant entry (flag in item 43) runs no interpreter. Every kernel in the table is a VM kernel in 0002 D10's stack classes and holds one register file. No VM code runs in an OptiX program (ruling 18, 0002 D11).
   The `opacity` entry convention (ruling 87): the entry writes `rec.geometry_opacity` = a and nothing else, and the caller takes T = 1 − a (grey); a Mix writes the effective a = 1 − Σ w_i (1 − a_i) (item 38). It exists only when the `geometry_opacity` store is per point; a constant opacity has no entry (word 1 = 0) and the kernel reads the constant block, where a constant outside [0, 1] is clamped and reported `approximated` and NaN rejects the program; a per-point value is not clamped. A per-point scalar comes from `CHANNEL_F32X3 a, b, imm`: r[a] = r[b + channel], channel 0-2 in the immediate (else BAD_OPERAND); it reads no context, so it folds (item 35).
33. **Context**: evaluation is hit-time only, with no texture-time pre-pass. The context holds P, Ng, N, front-face, wo (for an emission entry inside NEE, the direction toward the shading point), UV sets by index, tangents, dP/dx and dP/dy from the ray cone (0003 path state), object and instance ids, random_id, attribute accessors, ray-type flags and depths (Light Path), ray length and the transport wavelengths. Layer Weight, Fresnel, Backfacing, Light Path and Ray Length read it. In `shade_shadow` the `opacity` entry runs on a shadow item, which carries no ray cone: textures there are sampled at mip level 0, Light Path reports a shadow ray with the item's transparent depth, and the transport wavelengths come from the item (path-state requirements, returned to 0003).
34. **Texture lookups.** `TEX_IMAGE` covers Closest, Linear, Cubic (uniform B-spline, as Blender) and Smart (= Cubic); Repeat, Extend, Clip, Mirror; Flat, Box, Sphere, Tube projection; UDIM; per-image alpha mode (0007). Filtering is software in kernel code, identical on CPU and GPU. Texels are filtered in their stored encoding and decoded afterwards, as Cycles does for 8-bit sRGB images, so node values match Blender (owner decision 14); half and float images are linear. Storage keeps the authored bit depth (8-bit, half, float). Linear is trilinear over a mip pyramid with LOD from the ray cone (Akenine-Möller et al. 2021); Cubic samples the ray-cone LOD level; Closest uses level 0. Mips are part of the design (ruling 22), an antialiasing prefilter that Cycles lacks; at LOD 0 the filters equal Blender's. Hardware filtering only if a measurement shows a win and CPU/GPU agreement holds. A missing image gives magenta texels and a report entry. Environment Texture uses the same op.
35. **Constant folding**: a node folds only if all its inputs are constants and it reads nothing from the context, so folding never crosses a texture or context read. A surface program that folds to constant stores becomes length 0: the interpreter loop is skipped and only the slot-resolution pass runs (scalars copied from the constant block, each `SpectrumRef` evaluated at the 4 transport wavelengths).
36. **Procedurals and colour nodes** are ported from Cycles `kernel/svm/` (Apache-2.0; `noise.h` BSD-3) into the kernel library with their licence headers. Sky Texture lowers to a `SKY` op whose model is 0004's (D12). Blackbody produces a `spec` value (`BLACKBODY`) and Wavelength a line source when every consumer is spectral-capable; the line enters the scene's wavelength table as a `lines` component (0003 decision 3). The spectral type propagates only through linear colour ops (Mix in Mix/Add/Multiply modes, Multiply, Add) into record slots; any other consumer receives Blender's RGB result.
37. **Bump, normal maps, displacement.** Bump: the compiler emits the Height subgraph three times under `BUMP_ENTER k` (centre, +dx, +dy), which offsets context P and UVs by the ray-cone footprint times Filter Width (Blender default 0.1); the normal comes from the surface-gradient formula (Mikkelsen 2008, as Cycles `svm/bump.h`). Normal Map: tangent, object and world space, tangent space with MikkTSpace per-corner tangents and sign computed natively at sync (0007). The Displacement output, Displacement node and Vector Displacement become bump from finite differences of the displaced position (as Cycles `svm/displace.h`). True displacement is geometry (0007) and not part of this record; materials set to "Displacement Only" or "Displacement and Bump" are reported `approximated`.
38. **Closures and segments.** Lowering turns the closure tree into BSDF-carrying children with weights w_i (products of mix factors along the tree) and three per-point outputs. The compiler lays out the `surface` entry as: (a) the **emission segment**: every node feeding any child's emission, holdout and mix factors, plus the coat and fuzz inputs of emissive children; it accumulates `Le = Σ_i w_i · Le_i · A_i(ωo)` and `holdout = Σ_i w_i h_i` over all children, deterministically, where A_i is the child's coat-and-fuzz attenuation computed by the same layer function the lobe stack uses (A = 1 for Emission shaders and extension kinds); (b) the **selection**: a `BRANCH_MIX`/`BRANCH_ADD` tree over the BSDF-carrying children with one sampler dimension per shading point (0003's dimension map), nested mixes reusing the uniform by rescaling (pbrt-v4 `SampleDiscrete`; `MixMaterial`); (c) one **BSDF block** per child, writing its record slots and ending in `JMP` to `END`. A value used by both (a) and (c) is computed in (a) and kept live. The `emission` entry is (a) alone; the `opacity` entry is the dead-code-eliminated graph of `T(λ) = Σ_i w_i (1 − a_i)`, with a_i each child's geometry_opacity. Rules:
   - **Graph encoding** (ruling 87; 0007 appendix `ar_graph_desc`): every `STORE_SLOT` and `EMIT_LE` belongs to the child its optional `child` parameter names (absent = 0, so a graph without a Mix has one implicit child and compiles to the words it always did); a Mix Shader is a `BRANCH_MIX` graph node with the factor as its input and `{tag, a, b}` naming its two subtrees; the mixes must form one tree that names each child once. The selection lays the tree out in preorder (first subtree falls through, second is the jump target); each child's constant stores become `CONST` and `STORE_SLOT` code in its block, because the one constant block cannot hold two children's inputs, so the block of a Mix material keeps the OpenPBR defaults and the record a block leaves is its child's alone; the last block falls into `END` instead of jumping to it. A value read by the mix factors or by two children is computed once before the selection. `MAY_BE_DELTA` is the OR over the children, each from its own constants (item 43). Weights are by socket, as Cycles `svm_node_mix_closure`: the first closure input of a Mix with factor f has weight 1 − f, the second f, and a child's w_i is the product along its path. For a Mix of BSDF children only, each child is selected with probability equal to its weight, so `closure_weight` stays 1.
   - NEE and BSDF sampling at the vertex use the same selected child. A camera path takes the null event with the selected child's 1 − a_i, an unbiased estimate of T; the shadow stage multiplies by T exactly.
   - A child without a BSDF (Emission, Holdout) is pruned from the selection, and the surviving child's closure_weight is multiplied by its weight. A Transparent child folds into geometry_opacity (Mix(Transparent, S, a) is S with opacity a × S's opacity, OpenPBR's top-level mix); a non-white Transparent colour folds by its mean and is reported `approximated`.
   - **Add Shader** (spine amendment accepted, ruling 23): `BRANCH_ADD`, an unbiased estimator of the sum; emission and holdout are summed exactly; reported as not energy-conserving when the BSDF weights can sum above 1.
   - Mix(Principled, Principled) is selected, never lerped (v1: lerping averages sharp and blurred highlights).
39. **Volume shader hand-off.** The Volume socket compiles to the `volume` entry, with a volume context (P, object coordinates, attributes; reading a surface-only input is a compile error). How the medium stage runs it, majorants, interval bounds, grids and the linear Mix of volume shaders are 0006's (D1, D6-D7; rulings 11, 23). Semantics follow item 10: scattering and absorption colours REFLECTANCE, emission ILLUMINANT, Blackbody analytic.
40. **Unsupported-node policy** (owner default). Any node, setting or linked socket without a lowering makes the whole material diffuse magenta (base_color (1,0,1) as reflectance, nothing else), and the compiler adds a per-render report entry naming material, node name, node type, socket or setting, and reason. Three dispositions: unsupported (magenta), approximated (rendered with the documented approximation in item 42), ignored (no effect by design, such as EEVEE-only settings). Entry schema, codes, deduplication and polling are 0001's. The coverage matrix is generated from `ops.def` plus the addon's lowering table and has a row for every `ShaderNode` type, so nothing drops silently. Its columns are `node_type`, `disposition`, `ops` (the `ops.def` opcodes the lowering emits) and `note`; a node in neither the lowering table nor its planned list is `unsupported`, and a test compares the row set with the `ShaderNode` types of the pinned bpy wheel (hosted ci) and of Blender 5.3 (check full).
41. **Coverage target**: every node in `research/07`'s W1 set; Principled Volume, Volume Absorption, Scatter, Coefficients, Info; Subsurface Scattering, Sheen BSDF, Metallic BSDF; Principled Hair, Hair BSDF, Hair Info (HAIR); IES, Magic, Brick, Gabor, Radial Tiling textures; Light Falloff, Wireframe, Combine/Separate Cylindrical and Spherical, Vector Displacement (as bump), AOV Output (0008). **No-ops in 2.0, reported `approximated`** (owner decision 26): Ambient Occlusion (outputs the unoccluded result: Color passed through, AO = 1) and Bevel (passes the input normal through, as Blender's own MaterialX export does, `research/07` F2). They need ray queries from inside shading; in Cycles they run in `shade_surface_raytrace`, an OptiX raygen kernel (`__SHADER_RAYTRACE__`, `research/07` F2), and ruling 18 / 0002 D11 forbid VM code in OptiX programs. Magenta: Raycast (it needs the same ray queries and no owner decision makes it a no-op), Toon, Ray Portal, Script (OSL), and the EEVEE-only Specular BSDF and Shader to RGB. The IES Texture node's profile (internal text or file) crosses as a string in `ar_graph_desc`'s pool (0007 decision 8); the core compiler parses it (IES LM-63, ported from Cycles `util/ies.cpp`, Apache-2.0) into an angular table for the `light` entry, with 0004 D6's photometric scale. Metric over the 0009 asset corpus, frequency-weighted as in v1: at least 95% of node uses supported, the rest approximated or unsupported, zero silent.

Evidence: v1's 116x emitter error from a wrong lift; k up to about 7 is not a bounded colour (`research/17` review).

- **SPINE §3, path state**: the ray cone (0003) is needed by texture LOD and bump (items 34, 37).

## Alternatives considered

- **General closure graph** (Cycles SVM closures, v1). Rejected: v1's lobe-count spills (254 registers) and unbounded per-hit state; OpenPBR's fixed nine lobes cover Principled, and stochastic Mix/Add covers the closure combinations Blender files use.
- **Per-material code generation** (runtime compilation, EEVEE-style). Rejected: every edit becomes a compile (spike A's edit-to-launch per kernel, 0009 B-04's basis, spans many viewport frames at B-14's rate), a CPU JIT would be needed for the one-source rule, plus a cache layer, and nvcc is the only GPU compiler (ruling 16). Re-examined only if Measurement M-3 shows the VM is the bottleneck.
- **Separate parameter-evaluation kernel** writing the record to memory. Rejected on spike A: 2.256 ms versus 1.59 ms fused.
- **64-entry register file** (v1; Cycles uses 255). Rejected: with the record it exceeds 0002's shade stack limit; 32 entries is the measured configuration (item 3).
- **A second register file for emission programs inside NEE.** Rejected: programs run one after another, so one kernel-owned file serves both (item 3).
- **MaterialX or OSL runtime.** Rejected: Blender's MaterialX export has no hook for about 30 of 100 node files, OSL on GPU is OptiX-only with documented limits, large dependencies against the build budget (`research/07` F3).
- **Per-lobe replacement by extension kinds** (`research/17`). Rejected: the extension stage would carry all OpenPBR lobes plus every kind, and layering needs E(ωo) that several kinds cannot define.
- **Complex IOR in the base/specular colour slots** (`research/17`). Rejected: colour slots are bounded and filtered.
- **Thin film by Airy summation truncated at m = 3** (Belcour and Barla 2017, v1). Rejected: truncation exists for spectral-sensitivity integration; per wavelength the closed form is exact and no more expensive, while the truncation residual over conductors is of order (r12 r23)^4.
- **Stochastic emission per selected child.** Rejected: Mix(Emission, Diffuse) seen directly would carry selection noise; the deterministic emission segment costs only the emission subgraphs.
- **Linear-space filtering of 8-bit sRGB textures.** Rejected: it departs from Blender's node values (owner decision 14).
- **Ray-query shading variant as an OptiX raygen kernel** (Cycles `shade_surface_raytrace`). Not adopted: it conflicts with ruling 18 and 0002 D11, and AO and Bevel may be no-ops in 2.0 (owner decision 26).
- **Heitz random walk for rough dielectrics in the engine.** Rejected for the device path: CPU-only in v1, register risk; Turquin albedo scaling meets the furnace target; the walk stays a test oracle.
- **Hardware texture filtering.** Deferred: 8-bit fixed-point weights break CPU/GPU agreement; adopted only with a measured win.
- **Spectral and extension authoring by custom nodes.** Deferred until the inliner question is answered (Measurement M-7); the Material panel works either way.

## Consequences

- Easy: adding an opcode is one `ops.def` line, one kernel function and one test; adding a node lowering is one addon table entry and a test; adding a spectrum is data; an extension kind's inputs are one `ext_fields.def` entry. These are small task specs.
- Easy: a material edit is a compile in the core plus an upload of words; constant materials skip the interpreter.
- Easy: correctness tests run on the CPU build of the same lobe and op functions in seconds (spike A: 0.35 µs per BSDF evaluation).
- Hard: 32 VM registers is tight for the heaviest procedural graphs; those fail to compile (magenta, reported) until M-4 decides.
- Hard: per-material extension masking, coated gratings and glossy fluorescent plastics are not expressible.
- Hard: AO and Bevel are no-ops and Raycast is magenta until in-shader ray queries exist.
- Cost when unused: an empty extension segment is not launched; `metal_ior` and `closure_weight` are 8 B of thread-local stack; the upsampling table (0003) is resident in every scene; mips add a third to texture memory (both in 0007's budget table); an opaque material never runs the `opacity` entry.

## What must exist from the first milestone, and what can wait

**Must exist from the first milestone, because retrofitting is expensive:**
- `MaterialHeader`, constant block and `OpenPBRParams` with the item 3 stack split, measured by M-1: every lobe, op and kernel is written against them.
- `ops.def` as the single generator of enum, interpreter, compiler metadata, Python schema and coverage matrix: v1's hand-mirrored enums are the failure it prevents, and retrofitting it touches every op.
- The VM in-kernel with one kernel-owned register file, the forward-only control flow, the four-entry table and the three-segment `surface` layout (items 31-32, 38): the bytecode format and every VM call site depend on them.
- `SpectrumRef` (24 B) and the per-slot semantics (items 9-10): they fix the constant-block layout and the graph crossing the ABI.
- `TransportMode` in every lobe and kind interface (item 8): adding a parameter later changes every lobe signature.
- The extension mechanism with one real kind (GRATING): header `ext` field, `EXTENSION` routing flag, `shade_surface_ext` and `shade_light_path_ext` with their gate rows, and the kind interface with its sample flags (item 17).
- The compiler outputs `MAY_BE_DELTA`, `NON_OPAQUE` and the emission estimate (item 43): 0002's routing and any-hit rule and 0004's partition and light selection read them.
- Magenta plus report entries and the generated coverage matrix (item 40): silent drops were v1's largest failure and are invisible once materials pile up.

**Can be added later without redesign:**
- `SpectrumRef` kinds beyond CONST, RGB, TABLE, BLACKBODY, CAUCHY_ABBE; complex IOR (item 12).
- Subsurface hand-off, the random walk and the translucent interior medium (items 4, 4a).
- Image filter modes beyond Closest and Linear, mips, UDIM, projections; procedural ops; bump and displacement-as-bump; Add Shader; the `SKY` op.
- `opacity`, `volume` and `light` entries (their table slots exist).
- HAIR and FLUORESCENT kinds; the grating's blazed generator and CSV loader.
- AO and Bevel pass-throughs; Filter Glossy; the rest of item 41.
- Implementations of the MULTILAYER and MEASURED kinds (designs in `research/17`, item 28).
- Masked extensions, by forwarding from `shade_surface` to `shade_surface_ext` after the VM's branch selection (amendment).
- Huang near-field hair; Blender 5.4's OpenPBR node; OpenPBR 1.2 slots once released; roughness-broadened grating orders, given a published model; custom Astroray nodes, if M-7 passes.
- True ray-query nodes, only if the owner and a 0002 amendment allow them.

## Verification

1. **White furnace per lobe and per spec configuration** (`research/05` B5), at each of the 4 wavelengths, linear unclamped float, 2^20 importance-sampled directions at cosθ_o ∈ {0.05, 0.25, 0.5, 0.75, 1}. Transmission is tested as flux (× η²) and on a closed sphere (v1 lesson); opacity pass-through counts as transmitted. Expectations (PROVISIONAL):

| Configuration | Pass |
|---|---|
| Lossless isotropic: metal, dielectric with diffuse, subsurface, translucent, mixes with coat and fuzz, smooth thin film, opacity | 0.99 ≤ E ≤ 1.002 |
| Anisotropic (E tables indexed by r = (αx αy)^(1/4)) | 0.97 ≤ E ≤ 1.002 |
| Rough thin film (approximate base attenuation, item 5) | E ≤ 1.002; deficit reported |
| Bump and normal map (the Conty term darkens grazing angles by design) | E ≤ 1.002; deficit reported |

2. **Sampling**: chi-squared per lobe and per kind (Mitsuba `chi2.py` method, integration resolution at least 8, significance 0.01 with Šidák correction) plus peak-position checks against the analytic direction (v1 VNDF lesson); ∫pdf equals 1 minus the measured dead fraction within 1e-3.
3. **Analytic**: conductor Fresnel at normal incidence equals ((n−1)²+k²)/((n+1)²+k²) to 1e-6; smooth thin-film reflectance, s and p, against an independent double-precision characteristic-matrix computation (Born and Wolf §1.6) at three thicknesses over dielectric and conductor substrates, to 1e-4; rough thin film against the microfacet integral computed with the oracle Fresnel, within 3σ; Cauchy n(λ) reproduces the Abbe number from C, d, F lines; rough-dielectric albedo against the Heitz 2016 walk oracle within 1% (PROVISIONAL).
4. **Spectral**: white REFLECTANCE returns white under the working-space illuminant to 1e-3 in all three spaces; spectral-versus-RGB OpenPBR on 20 parameter sets reported as a tolerance table; complex-IOR fit residual (MC albedo of the exact lobe versus the F82 fit) at most 2% (PROVISIONAL); a TABLE reflectance reproduces itself in a one-bounce render.
5. **CPU/GPU**: throughput weight f·cos/pdf per lobe and kind on 1e6 inputs, p99.9 relative error ≤ 1e-4 against a double reference (spike A).
6. **VM**: per opcode, folded (host) versus interpreted on the CPU build is bit-exact, GPU no-FMA within 1e-6 relative, on 1e4 random inputs; node values against Blender's own evaluation (emission-plane bake at 1 spp, v1 method) within 1e-4 absolute, with mips off (LOD 0) because Cycles has none; 8-bit images are filtered in encoded space as Blender does, so all filter modes are in the check. This checks node semantics per owner decision 14, not light-transport parity. Control flow: `BRANCH_MIX`/`BRANCH_ADD` selection frequencies equal the weights within 3σ; Le of Mix(Emission, Diffuse) has zero selection variance; the `opacity` entry equals Σ w(1 − a) exactly; an emission program run inside NEE after a surface program gives bit-identical Le to the same program run alone (register-file reuse).
7. **Registers, stack and time** (merge gate): every kernel in item 32's table meets 0002 D10's gate as amended by ruling 17; record ≤ 304 B and register file = 128 B are `static_assert`s; material compile time meets 0009 B-24.
8. **Grating**: 600 lines/mm, 632.8 nm laser at normal incidence onto a screen (light-tracing pass): spots at ±22.31° and ±49.41°, none at |m| = 3, centroid error ≤ 0.1°; white light gives ordered spectra; a lossless table gives furnace 1 ± 0.002; Σ η ≤ 1 in every generated cell; lane-mean order selection agrees in mean with a lane-0-only selection reference within 3σ, with lower colour variance in order 0; CD scene inspected by eye.
9. **Blender mapping**: every "verify" row of item 42 is checked by rendering Principled 5.3 and the mapped record on the CPU engine over a parameter grid; per-parameter deltas recorded; a row ships only after its delta is explained.
10. **Coverage and policy**: the generated matrix has a row for every `ShaderNode` type; a test material per unsupported or approximated node renders as specified and produces exactly one report entry; corpus coverage at least 95%.
11. **Interfaces**: `MAY_BE_DELTA` is never false on 1e4 generated graphs whose BSDF can sample a delta lobe (plus 0004's D19 test); the emission estimate is zero only when emission folds to 0; Filter Glossy off leaves the record bit-identical.
12. **HAIR and FLUORESCENT**: hair furnace within 1% (Mitsuba `test_hair.py` method); fluorescence: UV-only light on a brightener emits only at longer wavelengths, energy bounded by Q, no-UV control dark (0003 check 22).

## Risks and open items

- **M-1, registers and stack (ratifies items 2-3)**: the 304 B record, a 32-entry register file, all lobes, NEE with an emission-program call site sharing the file, and an interpreter with about 100 opcodes, fused in `shade_surface` at N=4: spills and stack within 0002 D10's allowances in the shipping capped build, uncapped count reported by `check full`. Spike A measured only a 44-float record and 16 opcodes. If the stack fails: fp16 record scalars (−48 B). If spills fail: 0002 D10's ladder.
- **M-2**: `shade_surface_ext` and `shade_light_path_ext` with GRATING, HAIR and FLUORESCENT under the gate; HAIR's split if needed.
- **M-3, VM overhead**: constant Principled versus Principled + image versus noise → ramp → bump, single and 8 interleaved materials, against 0009 B-30 (textured case relative to constant case).
- **M-4, corpus**: register-file use (99% of materials within 24 of 32 registers), node frequencies, compile time. If more than 1% exceed 32, the remedy is 16 more registers paid for by fp16 record scalars (stays within 0002's stack limit); anything more needs a 0002 change.
- **M-5**: software versus hardware texture filtering cost.
- **M-6**: complex-IOR F82-fit residual (Verification 4).
- **M-7**: do custom nodes survive `inline_shader_nodes()`, and which Material Output does the Python inliner pick (`research/07` unverified)?
- **M-8, translation cost**: `inline_shader_nodes()` plus the Python walk and serialisation plus the native compile over 1000 corpus materials (`research/07` measurement 4), and on S2's 300 materials, against 0009 B-24 and inside 0007's first-frame gate (ruling 21); a material with animated values re-translates once per frame. Spike B's 1.42 s first frame excluded shaders. If over budget: move per-node lowering from Python into the native compiler, then a value-only patch path.
- **In-shader ray queries**: AO, Bevel, Raycast need the VM inside an OptiX raygen kernel, which ruling 18 and 0002 D11 forbid. AO and Bevel are reported no-ops in 2.0 (owner decision 26), Raycast magenta (item 41).
- **Random walk** (item 4a): the entry and exit lobes and the step limit are taken from Cycles and are re-read before coding; the walk's local rays need 0002 Risk 13's self-intersection rule.
- Thin-film base attenuation (item 5) is an approximation awaiting a cross-check with Adobe's reference.
- The four "verify" Principled rows may change the mapping; Adobe's library targets 1.1.1, so 1.1.2 deltas have no external cross-check.
- Grating efficiency formulas and preset depths are from books not yet re-read; no licence-compatible grating reference implementation exists.
- Blender 5.4's OpenPBR socket names are unknown.
