# 0008 — Film, outputs, denoising, DLSS and viewport image quality

Status: proposed (2026-11-14), revised after review (2026-11-14)

## Context

The film is where the engine's physical quantities become something a person or an instrument reads. The spine fixes the frame: transport is in physical units and conversion to display RGB, sensor bands or photon counts happens only at the film (SPINE 3); each path carries film wavelengths separate from its rewritable transport wavelengths, and the wavelength distribution is data (SPINE 3); one observer everywhere (SPINE 3); the film keeps first and second moments, the full denoiser buffer set and statistics buffers from the first milestone (SPINE 4, CHECKPOINT-1 "Added after the owner's answers"); OIDN is the default denoiser and DLSS Ray Reconstruction (DLSS-RR) is an optional NVIDIA viewport mode loaded from the driver, never bundled, never applied to final or science output (SPINE 8).

Owner constraints that bind this record: 60 updates/s desirable, 24 the floor, first frame comparable to Cycles, near-full resolution with dynamic reduction only below the floor (0000 items 9-10); DLSS in the viewport if it can be built (item 11); heat maps of sample count, bounce count and similar statistics (item 15); scientific accuracy; short builds and fast tests; full breadth in the first release (item 7).

**Frame budget** (spike B, `spikes/B-blender-end-to-end/RESULTS.md` 1.1-1.3). Blender's main loop adds about 6 ms of CPU time to every redraw (cause inferred as an idle sleep), which caps redraws at 1/(6 ms + `view_draw`), about 150/s at 1080p with half-float uploads. The engine renders on its own thread and stream, decoupled from that loop (spike B 1.3, Present recommendation 4), so the 6 ms adds latency (uniform 0-6 ms) but does not come out of the engine's GPU time. The engine's per-frame budget is therefore **B(rate) = 1/rate − t_present**, where t_present is the present work that shares the GPU or the PCIe link (resolve to half floats, device-to-host copy, Blender's upload and compute unpack; the upload alone is 0.74 ms at 1080p, more at 4K depending on 0007's format). At 60/s, B is about 15-16 ms at 1080p; at the 24/s floor about 40 ms. Render, resolve, denoise or DLSS, and pack must fit in B. t_present is measured in M1 (Risks 9).

**Challenges to the spine: none.** This record departs from research, not from the spine. It overrides `research/04-integrator-architecture.md` R2 and R12 (film fed by per-contribution atomic adds into a float32 running sum), because neither gives exact per-pixel second moments (decision 3). It keeps R9's A/B-split adaptive metric, which record 0004 D16 adopts; the film supplies its class-A sum (decision 2).

Three things have to be settled together. (1) Tests need exact per-pixel moments (Welch/Z tests, 1x1 analytic films, `research/09-test-validation.md` design requirement 4; record 0003's requirement of under 1e-6 relative accumulation error at 2²⁴ samples per pixel). (2) Every denoiser consumes RGB and wants guides free of avoidable noise (`research/10-denoise-upscale.md` 3, 9), while the engine samples four wavelengths per path. (3) Science outputs (bands, photon counts, data cubes, FITS) must stay raw and traceable while display products are denoised, upscaled and exposure-adjusted.

## Decision

### Film core

1. **One film, many channels, one write path.** The film is a set of device-resident planes described by a `FilmLayout` built once per render from the requested outputs. Each channel has a name, a kind and an offset. A channel nobody requested gets offset -1 and no memory. Kernels write only through `film_*` functions in one source file (`film_write.h`), compiled for CPU and GPU. Planes are structure-of-arrays, one plane per component, rows bottom-up (Blender's pixel order and FITS' order, so no flips on output). The film is allocated once at the largest size the session can use (the region size for the viewport, the output size for final renders). Lower render resolutions use a sub-rectangle, so a resolution change costs a clear, not an allocation.

2. **Channel kinds.**
   - `MOMENT`: fp64 sum S1 and fp64 sum of squares S2 per component, plus a shared u32 sample count n per pixel. When adaptive sampling is on, the channels its metric reads also get an fp64 class-A sum S1A per component (Cycles' parity split, record 0004 D16). Used for display colour and every science channel.
   - `ADD`: fp32 sum per component, mean only. Used for light-path passes, light groups, guides, deterministic AOVs and statistics.
   - `COUNT`: u32 per pixel (counters, histograms, max values).
   - `CRYPTO`: fixed (id, weight) slots per pixel (decision 11).
   - `SPLAT`: an fp32 per-pass plane folded into fp64 S1/S2 (and S1A) over passes, allocated only when record 0004's light-tracing pass runs (decision 4).

3. **Per-sample totals, one writer per pixel, no atomics.** Contract: a pass writes at most one camera sample per pixel (record 0004 D25: a pass is one sample index for every active pixel), and only the stage that ends that pixel's path writes it. Each camera path accumulates its own radiance `L_film[4]` (one value per film wavelength) in the path state (0004 D5; 16 B, already in the state estimate of `research/04-integrator-architecture.md` finding 3). At termination, `film_write_sample(pixel, L_film, wavelengths)` converts the sample to every `MOMENT` channel and adds x to S1, x² to S2 and, on passes with an even sample index, x to S1A, with plain fp64 read-add-write on both targets. No atomics are needed, so the camera-path film is bit-reproducible for identical inputs. Mean = S1/n. Variance of the mean = (S2 − S1²/n) / (n(n−1)) for n ≥ 2, evaluated in double at resolve (cancellation analysis: Chan, Golub and LeVeque 1983). All three Blender pixel filters are non-negative (decision 5), so every sample carries weight 1 and no weight plane exists. Under Owen-scrambled Sobol the per-pixel samples are not independent and this variance is conservative; statistical tests that need its exact value run the independent sampler mode. fp64 meets record 0003's 2²⁴-sample requirement, which float32 does not (V2). The cost is measured in M1 (Risks 1).

4. **Light-tracing splats.** Contributions that land on an arbitrary pixel (record 0004's light-tracing pass for gratings and caustics) go to the `SPLAT` per-pass plane by fp32 atomic add; many photons can hit one pixel, so these are the film's only atomics. Each splat is weighted by the same pixel filter as camera samples, normalised to unit integral and evaluated over its footprint (0004 D23, pbrt-v4 `RGBFilm::AddSplat`), so the camera film and the light image estimate the same filtered image; with Box at 1 px a splat lands in exactly one pixel. The photon weight already contains 1/P (0004 D20), so the per-pass plane is one independent estimate of the light image. At the end of each pass the resolve kernel adds it and its square to fp64 S1/S2 over passes, adds it to S1A on even passes, and clears the plane. Combined mean = camera mean + light-image mean; combined variance = camera variance + light-image variance (independent estimators). Nothing is counted twice only because record 0004 D19 partitions path space between the two estimators; that is 0004's obligation and its D19 test checks it. Unlike the camera film, the light image correlates neighbouring pixels within the filter radius; its per-pixel batch variance over passes stays valid.

5. **Filter by importance sampling, not splatting.** Each camera sample draws its sub-pixel offset from the pixel filter and contributes to exactly one pixel with weight 1 (Ernst, Stamminger and Greiner 2006; pbrt-v4 `FilterSampler`). Filters: Box, Gaussian and Blackman-Harris, all non-negative; default Blackman-Harris at 1.5 px, matching Blender. One filter applies to the whole render, every channel of a sample included. The width-to-kernel mapping is copied from Cycles `intern/cycles/scene/film.cpp` (Apache-2.0) and checked against it by a test. Camera-film pixels stay statistically independent, which both the moment tests and every denoiser assume.

6. **Invalid samples are counted and fail loudly.** A sample with a NaN or Inf, or a negative spectral radiance at any film wavelength, is not written to any channel and does not increment n. It increments the `invalid` counter, the per-render report shows the count, and a nonzero count fails every test. Clamping (Blender's direct and indirect clamp, applied by 0004) biases the result. When any clamp is non-zero, science channels refuse to write and say why.

### Sensor model

7. **The film is a list of response channels (one mechanism for display, bands, instruments and cubes).** A response channel is a tabulated curve R_k(λ) (piecewise linear, nm, vacuum wavelengths) plus a unit, `ENERGY` or `PHOTON`. At write time a sample converts as x_k = (1/N) Σ_i L(λ_i) R_k(λ_i) w_u(λ_i) / p(λ_i), with N = 4. w_u = 1 for energy and λ/(hc) for photons. p is the per-wavelength pdf after any secondary-wavelength termination (pbrt-v4 `SampledWavelengths` convention). The conversion is linear in L. Channel groups:
   - **Display** (always present): the CIE 1931 2° colour-matching functions (CIE 15:2004), then the 3x3 XYZ-to-working-space matrix for the file's working space (Rec.709, Rec.2020 or ACEScg). These are generated together with the white point and upsampling tables, as SPINE 3 requires. Display values are relative: they are divided by Y_w, the luminance of the spectrum that record 0003 assigns to a white Blender emitter of strength 1, so that emitter shows as working-space (1,1,1). The `film_exposure` multiplier (default 1.0) scales display and light-pass channels only, like Cycles' film exposure. Blender's colour-management exposure stays Blender's. Adaptive sampling's X, Y, Z means (0004 D16) are an exact linear map of the RGB means.
   - **Band**: any user curve (filter × QE × optics throughput), named, in energy or photon units, absolute SI. Presets ship as data files: Johnson-Cousins and SDSS-like bands taken from the SVO Filter Profile Service, plus NIR and UV boxes.
   - **Cube**: B box responses over uniform bins [e_b, e_b+1) of equal width Δλ, each divided by Δλ, so each bin reports bin-averaged spectral radiance (W m⁻² sr⁻¹ nm⁻¹) or photon radiance. Non-uniform bins are refused with a message pointing to band channels (decision 13). A cube is just a set of channels; no separate code path exists.

8. **Wavelength sampling coverage is checked at render start.** The film hands its active channels to record 0003's wavelength-CDF builder. The default is the visible pdf when only display is active. When band or cube channels are active, the CDF is a mixture of the visible pdf and the normalised sum of band responses. The mixture weight is PROVISIONAL and set by spike E (0003's scope). If any active channel has R_k(λ) > 0 where p(λ) = 0, rendering fails before the first sample.

9. **Photon counts and absolute calibration.** Photon channels report expected counts per pixel: N_k = t · G_pix · ⟨L_k,ph⟩, where t is the exposure time [s] and G_pix = A · ∫_pix cos θ dω is the pixel étendue [m² sr]. G_pix is computed exactly on the host: the pixel rectangle is split into two triangles and each triangle's solid angle comes from Van Oosterom and Strackee 1983, plus the cos θ factor. A is the collecting area: π(f/2N)² from the Blender camera when depth of field is on, otherwise an explicit `instrument.area_m2`. If photon channels are requested with no area, rendering fails. Photon channels require the Box filter at width 1 px, because counts must partition the flux. The filter is per render (decision 5), so display and every other channel are then Box 1 px too; a render with any other filter fails with that explanation rather than switching the filter. Within one pixel the film averages over the image-plane footprint rather than over cos θ dω. That error is second order in the pixel's angular size and is checked by the wide-angle S5 test (Verification). Science channels are never multiplied by `film_exposure`.

### Passes and AOVs for Blender

10. **Pass list and how each pass is produced.** Blender's standard pass names are used where they exist, so the compositor's Denoise, Cryptomatte and Vector Blur nodes work unchanged. Engine-only passes are prefixed `AR `. Every pass lands together with the feature that produces it (What lands when).
    - **Primary-hit AOVs** (`ADD`), written by the surface stage when depth = 0: Depth (linear view-space z), Position, Normal, UV, IndexOB, IndexMA, Mist (from the World mist settings), Vector, Alpha. Which of these accumulate over samples and which keep only sample 0 follows Cycles `intern/cycles/kernel/film/data_passes.h`, to be read before implementation and quoted in the code.
    - **Light-path passes** (`ADD`, display RGB): DiffDir, DiffInd, DiffCol, GlossDir, GlossInd, GlossCol, TransDir, TransInd, TransCol, VolumeDir, VolumeInd, Emit, Env, AO, Shadow Catcher. Classification follows Cycles: the category is fixed at the first scattering vertex; direct and indirect are separated by bounce count (`docs/v1-lessons/research/blender.md`, "Render passes"). Demodulation is defined in RGB, never per wavelength:
      - the film stores the raw contributions RGB(L_cat,dir) and RGB(L_cat,ind), where RGB() is the display conversion of decision 7;
      - `<cat>Col` accumulates the path's RGB guide tint (decision 15) times the category's albedo at the first scattering vertex, computed exactly like the decision-15 albedo (each colour slot's exact RGB projection);
      - at resolve, `<cat>Dir` = mean raw / mean Col per RGB component (likewise Ind), Cycles' film-side division. Where a Col component is below 1e-8 (PROVISIONAL), that Dir/Ind component is 0 and the pixel is counted in the report as light that Dir·Col recombination cannot restore.
      - Because RGB() is linear in L, Combined = Σ raw light-path contributions + Emit + Env + Volume + light image holds exactly per sample, before clamping; Dir·Col + Ind·Col = raw wherever Col is non-zero.
      - Direct light at the first vertex needs the BSDF evaluation split into diffuse, glossy and remainder parts, as Cycles' `BsdfEval` (sum, diffuse, glossy) does: a requirement on record 0005, placed and gated by decision 22. Per-category state members are feature-tagged and exist only when light passes are enabled.
    - **Light groups** (`ADD`, display RGB, one plane per Blender `lightgroup`). Every emitter carries a u8 group id (0 = none): lights, emissive meshes, world, and later volume emission and astrophysical emitters (emission-mechanism groups, `docs/v1-lessons/research/survey.md`). Shadow items carry the id of the light that produced them; emission hits use the id of the emitter hit. Σ groups + ungrouped = Combined, per sample. Limit: 255 groups, subject to the memory check in decision 21.
    - **Shader AOV** (`ADD`): written by the material VM's AOV-output opcode at the primary hit (record 0005).
    - **Cryptomatte** (decision 11).
    - **Denoising passes**: `Denoising Albedo`, `Denoising Normal`, `Denoising Depth` and `Noisy Image`, as defined in decision 15. `Noisy Image` is always written when a denoiser ran.
    - **Statistics passes** (decision 12): `AR Sample Count`, `AR Bounces`, `AR Rel Error`, `AR Invalid`, `AR Time`, `AR Rays`, and `AR Term <reason>` on request.
    - **Band passes**: one single-channel pass per band channel, so they also reach Blender's multilayer EXR. Cubes go only to FITS (decision 13).

11. **Cryptomatte**, following the Psyop spec v1.2.0 (Friedman and Jones 2015, BSD-3). The id is MurmurHash3_x86_32 with seed 0 of the object, material or asset name, converted with `hash_to_float` (alShaders2, Apache-2.0); the smhasher test vector "hello" gives 0x248bfa47. Each pixel has `levels` slots per type (Blender's setting, default 6, rounded up to even), written as levels/2 RGBA passes of two (id, weight) pairs each, as Cycles does: `CryptoObject00..02` at the default. At depth 0 the surface stage adds sample weight to a slot, claimed by atomic compare-and-swap on the id word followed by an atomic add on the weight. This is v1's race-free wavefront scheme. A sample that finds every slot taken increments an overflow counter, which is reported, never dropped silently. The host sorts slots by weight, normalises them and writes the `CryptoObject`, `CryptoMaterial` and `CryptoAsset` passes as RGBA (id0, w0, id1, w1). The manifest is written through `RenderResult.stamp_data_add_field` under `cryptomatte/<7 hex digits of MurmurHash3(layer name)>/{name, hash, conversion, manifest}`, Cycles' layout (`research/07-blender-feature-surface.md` F6).

12. **Statistics and heat-map buffers** (owner item 15). The per-path counters live in the path state (SPINE 3, record 0003). At termination the film adds them to these channels:

    | Channel | Kind | Definition | Default |
    |---|---|---|---|
    | sample count | `COUNT` | n per pixel (shared with `MOMENT`) | on |
    | bounces | `ADD` + `COUNT` max | mean and max scattering events per path (surface or real volume scatter, delta included, null collisions excluded) | on |
    | rel error | derived | for n ≥ 2: max over display channels c of sqrt(Var[mean_c]) / max(\|mean_c\|, 1e-6); the floor is PROVISIONAL. For n < 2 the pass stores -1 and the heat map shows a fixed "no data" colour | on |
    | invalid | `COUNT` | decision 6 | always |
    | time | `ADD` | per-path sum of per-stage `clock64()` deltas (CPU: `__rdtsc`), normalised to the image mean. A relative cost map, not wall time | on request |
    | rays | `ADD` | camera, bounce and shadow rays traced per sample | on request |
    | termination | `COUNT` × reasons | per-pixel histogram over 0003's enum (escaped, Russian roulette, max depth, zero throughput, invalid, GR captured, GR step limit, GR numerical failure) | on request |

    - **Reset rule.** Statistics channels clear on an epoch change (record 0004 D25: an image-affecting edit), not on DLSS mode's per-frame colour reset. In DLSS mode they therefore count over all frames since the last edit. The colour film holds n = 1 in DLSS mode, so the rel-error view is unavailable there and the UI says so.
    - **Display.** The engine maps a statistic through viridis (Smith and van der Walt 2015, CC0), or a fixed categorical palette for termination reasons, into a display-referred sRGB RGBA8 frame. Record 0007 (decision 40) draws that frame with its legend in a POST_PIXEL handler outside `bind_display_space_shader`, so the view transform never touches it. A scene-linear heat map would be distorted: the default transform is AgX-like (spike B 1.4: 0.066 shows as 99/255). Default ranges: sample count [0, max spp], bounces [0, max depth], rel error on a log scale [1e-3, 1] (PROVISIONAL).
    - Final renders write the raw statistic values (not colour-mapped) as passes and into the FITS dump.

### Science outputs and files

13. **FITS is the engine's only file format; Blender writes everything else.** Combined, passes and band passes go to Blender's `RenderResult`, so Blender writes the PNG or multilayer EXR. The engine adds no EXR dependency (v1: an EXR library update broke a test runner, `docs/v1-lessons/research/testing.md`). A hand-written FITS 4.0 writer in the host library writes a primary HDU and IMAGE extensions only, with no table HDUs:
    - **Science file** (final renders with band or cube channels): an empty primary HDU with provenance keywords (engine version and commit, seed, spp, sampler, observer, working space, filter, wavelength-pdf name, clamp settings, `DENOISED = F`). Then one IMAGE extension per band (`EXTNAME`, `BUNIT` such as `W m-2 sr-1` or `ph`, plus `EXPTIME` and `AREA` for counts). Then a cube extension of NAXIS3 = B with a linear spectral WCS (`CTYPE3 = 'WAVE'`, `CUNIT3 = 'nm'`, `CRPIX3/CRVAL3/CDELT3`; Greisen et al. 2006). Cubes have uniform bins only, because the `WAVE-TAB` form needs a binary-table HDU (decision 7). Each data extension has `VAR` (variance of the mean) and `NSAMP` companions. BITPIX -32 by default, -64 on request (tests). Spatial axes carry pixel coordinates plus camera intrinsics as keywords; celestial WCS is not written (Risks 8).
    - **Film dump** (command-line host, tests, benchmarks): every allocated channel's mean, variance and counters in the same layout. Test images, golden files and benchmark artefacts are FITS; PNG conversion for reports is a script.
    - The writer accepts only `FilmView` (decision 17); there is no overload for a denoised image.

14. **PSF convolution and detector noise are deferred** until after the first release; nothing is reserved for them now.

### Denoising

15. **Guide buffers and their exact definitions** (`ADD`, render resolution, linear, before tone mapping). There is one definition for every denoiser, as in Cycles, which feeds the same denoising passes to OIDN and DLSS (`research/10-denoise-upscale.md` 2). Guides are free of wavelength noise, not of Monte Carlo noise: like any `ADD` channel they average per-sample values, which vary with the sub-pixel offset (decision 5), the Mix Shader branch (selected stochastically, SPINE 5; a guide takes the selected branch's values, so its mean converges to the mix-weighted guide) and the delta lobe chosen at a smooth dielectric (reflection or transmission).
    - **Denoising surface**: the first hit at which the path samples a non-delta lobe. Delta reflections and transmissions before it are followed (OIDN's recommendation). The path state keeps an RGB guide tint (12 B, feature-tagged: present only when a denoiser or light passes are on), initialised to 1 and multiplied at each delta vertex before the denoising surface by the sampled delta lobe's RGB weight, computed by the albedo rule below. Albedo guides and `<cat>Col` are multiplied by it. Depth, motion and hit distance refer to the **primary** surface, because reprojection needs it.
    - **colour**: the `MOMENT` display mean (viewport DLSS mode: the current frame's single sample), working-space RGB. In the copy handed to a denoiser, negative components are clamped to 0, because neither OIDN nor DLSS documents negative input. The film and `Noisy Image` keep the negatives.
    - **diffuse albedo**: the layering-weighted reflectance of the diffuse and subsurface lobes. **specular albedo**: the directional albedo E(wo) of the specular, metal and coat lobes, taken from the same albedo tables that OpenPBR albedo scaling uses (record 0005), not from a separate approximation. **OIDN albedo** = diffuse + specular, clamped to [0,1]. All are computed in working-space RGB from each colour slot's exact RGB projection (the RGB input, or the scene-build projection of a spectral table under the working-space white), never by Monte Carlo over the four wavelengths. That keeps chromatic noise out of the guides and keeps them in the colour image's observer.
    - **normal**: world-space shading normal after bump and normal mapping, front-facing to the incoming ray, averaged and not renormalised.
    - **roughness**: OpenPBR `specular_roughness` (linear, 0-1) at the denoising surface; packed into the normal's w for DLSS.
    - **depth**: linear view-space z of the primary hit; the sky stores 65504.
    - **motion**: one internal backward motion buffer in pixels at render resolution (current position to previous-frame position of the primary surface point), camera plus rigid object motion, with jitter removed. Deformation motion is added when record 0007 supplies previous-frame vertices. Blender's 4-channel `Vector` pass and DLSS's motion input are both views of this buffer; each API's sign convention is fixed in code with a test.
    - **specular hit distance** (DLSS only): world-space distance from the primary hit to the next hit along a first bounce that sampled a specular, metal or coat lobe; 65504 if it escaped. Behaviour for diffuse first bounces is taken from the DLSS-RR Integration Guide.
    - **matrices and metadata** (host side): per-frame world-to-view and view-to-clip matrices, jitter offset, frame index and a history-reset flag.

16. **One denoiser interface.** The host function is `denoise(DenoiserState&, const DenoiseInputs&, DisplayImage& out, DenoiseMode)`. `DenoiseInputs` holds read-only views of colour, the guides and the metadata. `DenoiseMode` is `FINAL` or `VIEWPORT`. Backends: `OIDN`, and `DLSS_RR` (`VIEWPORT` only). Rules:
    - **Off the first-frame path.** The `DenoiserState` is created on a host worker thread when the session starts (OIDN device creation, filter commit and weight loading; in DLSS mode NGX init and feature creation). Until it is ready the viewport presents undenoised frames and the status line says "denoiser loading"; the first frame never waits for it. A final render waits for it only before its denoise step. The state then persists across resets and resolution changes (v1 measured a cold re-initialisation cost on every frame, `docs/v1-lessons/research/testing.md`).
    - **DLSS failure.** If DLSS is unavailable or fails, the UI and the per-render report say why, and the viewport uses OIDN with a visible notice.
    - **OIDN failure.** If OIDN cannot be created or fails (for example no sm_120 support, Risks 3), the noisy image is shown or written with `denoised = false`, and the error appears in the UI and the report. There is no CPU-OIDN fallback for a GPU render.
    - The OptiX denoiser, NRD, FSR Ray Regeneration and XeSS are not built (Alternatives).

17. **Science data is never denoised, and the type system enforces it.** Film planes are reachable only through `FilmView` (read-only) or the `film_*` write functions; denoisers write only `DisplayImage`. No function converts a `DisplayImage` into a film channel or passes one to the FITS writer. A negative-compile test proves both. A denoised Combined is written to Blender with the raw result in `Noisy Image`, and every output that went through a denoiser carries `denoised = true` in its metadata. Band, cube, photon and statistics channels are never denoiser inputs or outputs.

18. **OIDN defaults.** Pin OIDN 2.5.x to the version Blender 5.3 ships, 2.5.0 (`research/08-build-toolchain.md`). It runs on a CUDA device created on the engine's stream (`oidnNewCUDADevice`, buffers shared with no copy) for GPU renders, and on the CPU device for CPU renders.
    - **Final**: filter `RT`, `hdr = true`, `quality = high`, albedo and normal prefiltered with the `RT` filter in auxiliary mode, then `cleanAux = true`. `inputScale` is left to OIDN's automatic estimate.
    - **Viewport**: filter `RT`, `hdr = true`, `quality = balanced`, no prefilter, `cleanAux = false`, applied to the accumulated progressive mean from `start_sample` (default 1) on every presented frame once the state is ready. Denoise time counts in the frame time used by the resolution controller (decision 20). If balanced exceeds half of B(rate) at the current target rate (PROVISIONAL; the same share as DLSS in V12), quality drops to `fast`. If `fast` still exceeds it, the viewport denoises only frames presented after 0.25 s without scene or camera change (PROVISIONAL), and the UI says so.
    - Alpha is not denoised: it is copied from the film.

### DLSS Ray Reconstruction

19. **DLSS-RR route.**
    - **Loading.** NGX SDK headers (`nvsdk_ngx*.h` only) are fetched at configure time by the dependency script with a pinned SHA-256, never committed. The build uses the SDK's header-only loader (`NVSDK_NGX_HEADER_ONLY`); nothing is linked. No NVIDIA DLL ships in any artefact. At runtime the engine calls `NVSDK_NGX_CUDA_Init` through the project-ID path with Astroray's own project ID and a custom engine type, never Blender's application ID. It then queries `NVSDK_NGX_CUDA_GetFeatureRequirements` and the `SuperSamplingDenoising` availability parameter, and creates and evaluates the feature with `NGX_CUDA_CREATE_DLSSD_EXT` and `NGX_CUDA_EVALUATE_DLSSD_EXT` on the engine's CUDA context and stream (`research/10-denoise-upscale.md` 1-3). Requires an NVIDIA GPU and driver ≥ 620 (driver-bundled DLSS, Blender PR #165500). Anything else shows the reason and keeps OIDN.
    - **Inputs.** Feature flags `IsHDR | MVLowRes`, plus `AlphaUpscaling` when the film is transparent (Cycles `denoiser_dlss.cpp`). The guides are those of decision 15, packed from film planes into `CUtexObject`s by one pack kernel. Minimum input 128×96. The optional depth-of-field guide (presets E/F), which Blender never connected (research 10, PR #153077 comment 49), is not built unless the depth-of-field scene of V12 part B fails; if it fails and the guide cannot be supplied, DLSS mode with depth of field on shows a visible notice.
    - **Sampling contract in DLSS mode.** One independent sample per pixel per frame, with the colour film reset every frame (statistics follow decision 12). Sub-pixel jitter from Halton(2,3) with 64 phases (the guide asks for at least 32). The sampler runs its counter-based independent mode, because blue-noise dithering and per-pixel Sobol correlate samples, which the guide forbids. Adaptive sampling is off.
    - **Licence constraints** (NVIDIA RTX SDKs licence, 2024-03-14). No redistribution of SDK material, so headers are fetched rather than shipped (4(b), 4(e)). NVIDIA GPUs only (Supplement 1). NVIDIA attribution in the addon's About panel (7.1(b)). The commercial-release notice (Supplement 4) does not apply to a non-commercial release (0000 item 5). The GPL addon neither contains nor links DLSS; the Apache-2.0 engine calls a driver component, as Blender's Apache-2.0 `denoiser_dlss.cpp` does. This is an interpretation, not legal advice (owner question 1).
    - **At rest.** In DLSS mode a still view keeps receiving single-sample DLSS frames (Blender's behaviour). There is no automatic switch to progressive accumulation plus OIDN (owner question 2).

20. **Dynamic resolution and upscaling.** The controller belongs to record 0007. Its obligations toward this record:
    - **OIDN mode**: the render resolution steps down only when the measured update interval exceeds the floor (SPINE 6). The film runs at a sub-rectangle (decision 1) and resets. OIDN runs at render resolution, and the presenter upscales bilinearly (OIDN does not upscale, Blender PR #151133).
    - **DLSS mode**: DLSS-RR does not support dynamic resolution, so the controller steps through the presets DLAA → Quality (0.66) → Balanced (0.58) → Performance (0.5) → Ultra Performance (0.33). Each step recreates the feature and resets history, with hysteresis so that a change is followed by at least 1 s at the new setting (PROVISIONAL, revisited with the recreate time measured in V12 part A). DLSS output is at viewport resolution.
    - Denoise and pack time are part of the measured frame time in both modes.

21. **Memory is checked before rendering.** The `FilmLayout` reports its bytes. At 1080p: display `MOMENT` about 110 MB (160 MB with the class-A sum); each fp32 RGB pass 25 MB; an RGB `SPLAT` about 125 MB; a 64-bin cube with variance 2.1 GB. If the film plus scene exceeds 80% of free device memory (PROVISIONAL), rendering fails with the per-channel breakdown. The engine never silently degrades a channel.

22. **Where film work runs, and its register budget.** Guide writes, denoising-surface tracking, the guide-tint update and the light-pass category split run inside `shade_surface` (and `shade_background` for sky values), where record 0002's stage table and front-load rule already place first-hit denoiser buffers. There is no separate guide stage: it would re-run the material VM at the primary hit, and spike A measured a separate parameter pass at about the cost of the whole fused shade (1.18 vs 1.27 ms per 2²⁰ paths). Values go to the film as soon as they are known; only the RGB tint and two flag bits (denoising surface reached, first-vertex category) carry across bounces, in path-state memory. The SPINE 2 register gate is measured with every film runtime flag on, because a runtime flag frees no registers (0002's probe build). M1 measures the guide set and the fp64 film write; the category split is measured when light passes land. If the gate fails, record 0002's fallback ladder applies in order (attribute, fix locally, own queue, split); never a variant kernel.

## Alternatives considered

- **Atomic per-contribution film adds** (`research/04-integrator-architecture.md` R2; Cycles). No per-pixel second moment, so no Welch or Z tests (`research/09-test-validation.md` 1.4), at a saving of only 16 B per path. Rejected for moments, kept for passes that need only a mean. The A/B split of R9 is kept as 0004 D16's adaptive metric.
- **fp64 atomic adds for moments** (this record's draft). Unneeded with one writer per pixel per pass, and record 0002 provides no fp64 atomic.
- **A float32 running sum** (04 R12). It fails record 0003's 2²⁴-sample accuracy requirement, and S2 − S1²/n cancels badly in float (Chan et al. 1983). Kahan-compensated float uses the same memory as fp64 with more operations.
- **Splatting each camera sample through the filter footprint.** This correlates neighbouring pixels, which invalidates per-pixel variance and the independence that OIDN and DLSS assume. Filter importance sampling gives the same expected image (Ernst et al. 2006).
- **A full spectrum per pixel, converted at the end.** 64 bins at 1080p is 531 MB in fp32 (`docs/v1-lessons/research/survey.md`), and it still bins the spectrum. Converting at write time is exact for any response (pbrt-v4 `RGBFilm::AddSample`). The cube remains as an opt-in set of box responses.
- **Per-wavelength demodulation of light-path passes.** The RGB projection of L/a times the RGB projection of a is not the RGB projection of L, so Dir·Col would not recombine to Combined. Division happens in RGB at resolve (decision 10).
- **A separate primary-hit guide stage.** Re-runs the VM at the primary hit (spike A: a separate parameter pass costs about as much as the whole fused shade). Rejected unless 0002's fallback ladder reaches it by measurement.
- **An engine-side EXR writer, or CFITSIO.** Blender already writes EXR from passes, and an EXR dependency is the failure v1 recorded. CFITSIO is rejected for build cost and dependency count, given that the writer emits only IMAGE HDUs; its licence is not the reason (permissive by its own text, to be confirmed in research 11 if it is ever adopted).
- **Non-uniform cube bins through `WAVE-TAB`.** Needs a binary-table HDU in the writer. Arbitrary spectral sampling is already served by band channels.
- **The OptiX denoiser as a second backend now.** Not measured to beat OIDN on this card (10, recommendation 5). v1's backend selector produced byte-identical output (`docs/v1-lessons/research/misc.md`), the classic failure of an untested second backend. It is added only if a measurement shows a win.
- **NRD, FSR Ray Regeneration, XeSS, or our own temporal accumulator.** NRD needs a D3D12 or Vulkan host and split radiance with hit-distance packing. FSR RR is DX12 and RDNA 4 only. XeSS is an upscaler, not a denoiser. An in-house temporal filter would be tuned by us and lose to trained models (10, sections 7-8 and options 5-6).
- **Bundling `nvngx_dlssd.dll`.** Licence 4(e), conflicting NDA wording in the Ray Reconstruction guide, and Blender's own resolution, driver-bundled DLSS from driver 620 (10, section 4).
- **Monte Carlo projection of the albedo guide over the four hero wavelengths.** It puts chromatic noise into the guides; the DLSS guide warns that noisy guides cause grain and ghosting.
- **Engine-side tonemapping for display.** Blender applies the view transform after `view_draw` (spike B 1.4), so the transform would be applied twice. Heat maps are the exception, drawn outside the transform (decision 12).
- **A CPU-OIDN fallback when the GPU OIDN device fails.** Hides a broken install behind a frame-rate collapse. The noisy image plus an error is shown instead (decision 16).
- **A hybrid viewport: DLSS while moving, OIDN progressive at rest.** It converges, but the image changes character under the user, and a Blender maintainer rejected it for that reason (10, section 2). Not built by default; left to the owner.

## Consequences

- **Easy.** A new band, instrument or cube is a data table, not code. A new pass is a channel descriptor plus one `film_*` call. Tests get exact means and variances from any render, CPU or GPU, and the camera film is bit-reproducible. Denoised data cannot reach a science file by construction. Light groups by emission mechanism cost nothing extra for astrophysics.
- **Hard.** Moments cost fp64 planes (about 110 MB at 1080p) and fp64 adds at path end (Risks 1). Light-path passes require the BSDF evaluation at the first vertex to return category parts, which adds register pressure in `shade_surface` (decision 22). DLSS mode constrains the sampler (independent mode, per-frame reset), so the viewport has two sampling regimes to test. Photon counts restrict the whole render to Box at 1 px. The light image is spatially correlated within the filter radius. Guides at 1 spp carry Mix Shader and sub-pixel noise.
- **Cost when unused.** An unrequested channel has no memory, and its write is one branch on a constant offset. Light-pass state members and the guide tint exist only when needed. With DLSS off, NGX is never loaded and the pack kernel never launched. With no splats there is no `SPLAT` plane and no atomics. With no science channels, the FITS writer is never called. The always-on cost is the display `MOMENT` channel, the 16 B per-path `L_film`, the sample count and the invalid counter.

## Verification

- **V1 Film normalisation.** Analytic scenes S1 (Lambertian sphere in a constant environment) and S5 (uniform emitter filling the view, pinhole and thin lens, wide field of view) from `research/09-test-validation.md`. Pass: |mean − truth| < 3 SE + 1e-4 per channel, CPU and GPU.
- **V2 Moments.** Through `film_write_sample` on a 1x1 film, CPU and GPU: 3e7 samples of 1.0 give S1 = 3e7 exactly (float32 stalls at 2²⁴ = 16,777,216), and 2²⁴ samples of 0.1 give S1 within 1e-6 relative of 2²⁴·0.1 (record 0003's requirement; float32 misses it by orders of magnitude). Synthetic iid samples with known variance (uniform, exponential) give a variance estimate inside its 99.9% interval. Two GPU runs of the same seeded render give bitwise-identical camera film; CPU and GPU dumps agree bitwise in n and to float tolerance in S1 (FMA-off test build, as in spike A).
- **V3 Filter.** A χ² test of importance-sampled offsets against each filter, plus the width mapping compared with Cycles' filter table. A point splat's normalised footprint weights sum to 1 for each filter.
- **V4 Observer.** For each working space, a white reflector under the working-space illuminant resolves to (1,1,1) within 1e-4, and the CMFs integrate to Y (09 pure-function family).
- **V5 Sensor and science** (lands with science outputs). S10 blackbody: band radiance against Planck and photon counts against the analytic count, which fails on a 1e9 unit slip. Cube bins summed over Δλ equal the band integral within 3 SE. Astropy (BSD-3, test-only) reads the FITS file, and the WCS gives bin centres to 1e-9 nm. Photon-count requests with a non-Box filter or no area, and cubes with non-uniform bins, are refused.
- **V6 Passes.** At 1 spp with a fixed seed, per pixel to float tolerance: Combined = Σ raw light-path contributions + Emit + Env + Volume + light image; Dir·Col + Ind·Col = raw wherever Col is non-zero, and the zero-Col count in the report matches a scene built to contain such pixels; Combined = Σ light groups + ungrouped. Deterministic AOVs (Depth, Normal, UV, IndexOB) match between CPU and GPU (09 agreement ladder step 3).
- **V7 Cryptomatte.** Headless Blender 5.3: the compositor Cryptomatte node, given our manifest and levels/2 layers, extracts a known object's matte with mean coverage error ≤ 1e-3, and the overflow count is 0 on the test scene.
- **V8 Statistics.** With adaptive sampling off, the sample-count map equals the spp exactly. On a closed furnace with albedo ρ, no Russian roulette and max depth D, the mean bounce count equals the geometric expectation within 3 SE. A test material that injects a NaN makes `invalid` > 0 and fails the render report. Rel error is -1 where n < 2. In DLSS mode the sample-count map counts frames since the last edit.
- **V9 Science isolation.** A negative-compile test shows `DisplayImage` cannot be passed to `film_*` or the FITS writer. Every FITS file has `DENOISED = F`. A render with clamping and a band channel errors.
- **V10 Guides.** On a fronto-parallel constant-colour plane at 1 spp, the albedo and normal guides are bitwise identical between two seeds (no wavelength noise). On a mirror in front of a diffuse wall, the albedo follows the mirror, tinted by the guide tint. Per-pixel guide variance on a textured plane, a fractional Mix Shader and smooth glass is reported (not gated) and feeds V12 part B.
- **V11 OIDN.** Final: denoised relMSE against a 16k-spp reference is lower than the raw relMSE at 64 spp on three scenes. Viewport: the timing of balanced and fast at 1080p and 4K on the 5070 Ti feeds the PROVISIONAL half-of-B rule. Cold init (device creation, filter commit, weights) is timed; time to first frame with the denoiser on equals denoiser off within run-to-run noise, against Cycles' 125 ms viewport sync-to-first-sample on S1 (spike B 3). A forced device-creation failure shows the noisy image, the error and `denoised = false`. The OIDN CUDA device runs on sm_120 (Risks 3).

## Risks and open items

1. **fp64 write cost.** Measure film-write and resolve time at 1080p, 1 spp per pass, in M1, and the registers the fp64 adds take at path end (decision 22). If they break the gate or exceed 5% of frame time (PROVISIONAL), the one write path becomes decision 4's pattern: path end writes x into an fp32 per-pass plane and resolve folds x and x² into fp64. It replaces the direct write rather than adding a second path, and viewport variance stays.
2. **Register cost of guides and the light-pass split** in `shade_surface`, unmeasured (spike A excluded denoiser buffers). Decision 22 places and gates it.
3. **OIDN on Blackwell and inside Blender.** OIDN's CUDA support for sm_120 is listed but its pull request is unconfirmed (10, finding 6); failure handling is decision 16. Blender loads its own OIDN 2.5.0 in-process, which can collide with ours by DLL name (`research/01-blender-boundary.md` K3). Mitigation: pin the same version; if 5.4 changes it, build OIDN with a renamed library. Settle in the in-process spike of record 0007.
4. **DLSS availability to a third-party process** without a local DLL on driver 620 is unverified (10, Unverified); V12 part A decides it now. Hero-wavelength chroma noise, gravitational-lensing reprojection and depth of field under DLSS are hypotheses, tested in part B.
5. **Cryptomatte acceptance** of a Python engine's manifest by Blender's compositor is unverified (07); V7 decides.
6. **Denoising-surface definition.** Pure "first non-delta lobe" may smear near-mirror roughness. If V11 or V12 shows it, add a roughness threshold as Cycles does, measured.
7. **Data-cube memory** (2.1 GB for 64 bins at 1080p with variance) limits cube size on 16 GB. Tiling is not designed now.
8. **Celestial WCS** (RA/Dec) needs a camera-to-sky convention that no record yet owns.
9. **Frame-budget terms not yet measured.** t_present (the engine's device-to-host copy and Blender's unpack on the GPU) and Blender's own GPU drawing with overlays on (spike B ran with overlays off, Present recommendation 5) are measured in M1. The redraw cap 1/(6 ms + `view_draw`) is a separate ceiling owned by 0007: about 150/s at 1080p, but about 58/s at 4K with half-float uploads (spike B 1.1).
10. **Mix Shader guides at 1 spp.** Stochastic selection (SPINE 5) makes guides noisy where a mix factor is fractional, where Cycles mixes closures deterministically. V10 reports it and V12 part B tests it; if it causes ghosting, evaluating both branches' albedo is a question for record 0005.
11. **Conflicts with other records** (the lead resolves):
    - Record 0002 (determinism rules and its assumption on 0008) says film accumulation uses float atomics and that 0008 provides `film_add` with atomics. This record and 0004 D5 write camera samples with one writer and no atomics; fp32 atomics remain only for splats and Cryptomatte.
    - Record 0009's moment test uses 1e7 samples of 1.0, which float32 also passes (V2 fixes this record's test), and it expects a `.npy` mean/variance dump where this record writes FITS dumps.
    - Record 0004 D25's DLSS "reset after every frame" must clear the colour film only, not statistics (decision 12).
    - CHECKPOINT-1 requires spike F before the architecture is written; part A is scheduled now, so `docs/ARCHITECTURE.md` sign-off waits for it.
    - The heat-map display depends on record 0007's probe P4 (does a POST_PIXEL handler draw outside the view transform?).
12. **Owner questions.**
    1. Is the DLSS licence interpretation in decision 19 acceptable for a public Apache-2.0/GPL-3 release (an Apache-2.0 engine calling the driver-resident DLSS, fetched headers, NVIDIA attribution in the About panel), or should it be checked by someone qualified first?
    2. In DLSS mode, should a still view keep showing single-sample DLSS frames (Blender's behaviour, decided here) or switch to progressive accumulation plus OIDN at rest, which converges but changes the image's character under the user?

## Review and resolution

Independent review, 2026-11-14 (17 objections, no blockers).

1. Frame budget misread spike B: ACCEPTED. Context now uses B(rate) = 1/rate − t_present (the ~6 ms is Blender's CPU loop, decoupled from the producer); V12 part A(c) is re-derived as B(rate)/2 instead of fixed 4 ms / 10 ms; the OIDN rule uses the same share.
2. Spectral demodulation identity: ACCEPTED. Col is the exact RGB projection (decision-15 rule); Dir = mean RGB(L_cat) / mean Col at resolve; Col = 0 gives 0 and a report count; V6 tests the exact raw identity.
3. Spike F moved to end of M1: ACCEPTED. Part A runs now on synthetic inputs, as CHECKPOINT-1 requires; part B stays at the end of M1; DLSS-only M1 items depend on part A.
4. Heat maps under AgX: ACCEPTED. The engine emits display-referred sRGB RGBA8, which 0007 decision 40 draws outside `bind_display_space_shader`; depends on probe P4.
5. Guides not noise-free, V10 unpassable: ACCEPTED. Decision 15 says the guides are free of wavelength noise only and states Mix Shader and glass behaviour; V10 uses a constant-colour plane and reports guide variance elsewhere.
6. Register cost unbudgeted, variant fallback: ACCEPTED. New decision 22 places the work in `shade_surface` (no separate VM pass), gates it with all flags on, and uses 0002's fallback ladder instead of a variant stage.
7. Denoiser init on first-frame path, OIDN failure unhandled: ACCEPTED. Creation is asynchronous with undenoised frames meanwhile; OIDN failure shows the noisy image and an error with no CPU fallback; V11 times cold init.
8. Precision test non-discriminating: ACCEPTED. V2 uses 3e7 samples of 1.0 and 2²⁴ samples of 0.1 (0003's requirement); the 0009 error is listed in Risks 11.
9. Atomics unnecessary, second write path: ACCEPTED. Samples-per-pass contract stated, plain fp64 writes with no atomics (consistent with 0004 D5); the Risk 1 fallback is now decision 4's fold pattern, replacing the direct write, not adding a path.
10. Filters disagree, double counting: ACCEPTED. Splats use the same normalised pixel filter (0004 D23); the D19 partition is stated as 0004's obligation.
11. Photon channels force Box on everything: ACCEPTED. Decisions 5 and 9 say the filter is per render, display included, and the render refuses rather than switching.
12. Statistics undefined at n < 2 and in DLSS mode: ACCEPTED. Rel error is -1 / "no data" for n < 2; statistics reset on epoch change, not on DLSS's per-frame reset; the rel-error view is unavailable in DLSS mode.
13. Cryptomatte slot count: ACCEPTED. `levels` slots stored as levels/2 RGBA layers.
14. FITS writer under-scoped: ACCEPTED. Cubes are uniform-bin only, the writer emits IMAGE HDUs only, the unsourced line count is removed, and CFITSIO is rejected on build cost, not licence.
15. Reserved PSF and noise interfaces: ACCEPTED. Decision 14 is a one-line deferral.
16. R9 override undeclared: ACCEPTED IN PART. The record does not override R9: 0004 D16 keeps the A/B metric. The draft's error was assuming adaptive reads only `MOMENT` and n; `MOMENT` now carries the class-A sum, and Context says R9 is kept.
