# 0007 appendix — C ABI descriptor field lists

Part of record 0007 (decision 7; ruling 33). It gives the field list of every descriptor in 0007 decision 5's function list. Conventions, types, annotations and the header grammar are 0001 D2; `ar_context_desc` and the report structs are 0001's (D2.1, D2.11); what the readback functions return is 0008 decision 13a. Widths and field order are fixed in `astroray.h` (task 031, ruling 63) within 0001 D2.2; the rows for `ar_mesh_desc`, `ar_mesh_buffers`, `ar_positions_buffers`, `ar_instances_desc`, `ar_light_desc` and `ar_spectrum_ref` below are those decided lists, and the header is the authority for the other rows' order and widths.

Host-filled arrays are in brackets. Each `ar_*_buffers` struct holds one `AR_STAGED` pointer per bracketed array of its descriptor, in the same order (0001 D2.3). Matrices are 3x4 row-major float32 object-to-world. Keys are `ar_key` (0001 D2.2).

**Conventions decided with the header (task 031).** Every count is an integer field or parameter of the same struct or call (0001 D2.10). Staged arrays: `ar_*_buffers` holds one `uint64_t <array>_count` per array, written by the engine, and one `AR_STAGED(<array>_count, T) T**` field per array, because the grammar gives staged pointers the `T**` form; the engine points each field at an engine-owned slot whose value is the array pointer (the host reads `*field`), and both stay valid until the key's `ar_edit_item_commit` or `ar_edit_abort`. `ar_edit_set_instances` has no buffers call, so the instance arrays are copy-in. Enum values and flag words are `uint32_t` (a `u8` or `u16` in a field list below is stored as `uint32_t` or, in a per-instance array, as `uint8_t`). Shared structs: `ar_xform {float m[12]}`, `ar_rgba {float v[4]}`, `ar_name {uint8_t text[64]}` (pass and shader AOV names), `ar_attribute_desc {name u8[32], domain, width}`. `ar_progress.ledger_bytes` has 16 slots in the host ledger's category order (0007 decision 14). `ar_display_frame.data` is `AR_OUT uint8_t*`, engine-owned and read-only for the host until release.

## Scene, session, progress, settings

| Descriptor | Fields |
|---|---|
| `ar_scene_desc` | cache_dir (UTF-8, OptiX disk cache, decision 45); worker_threads (0 = min(8, logical cores / 2), decision 23). The device is the context's (0001 D2.1, ruling 33). |
| `ar_session_desc` | mode VIEWPORT/FINAL/PREVIEW; max width and height (the largest film the session can use, 0008 decision 1); denoiser NONE/OIDN/DLSS_RR (0008 decision 16) |
| `ar_progress` | state (INITIALIZING, RENDERING, PAUSED, CONVERGED, TRIMMED, CLOSED, FAILED); active, pending and failed generation and the current epoch (decision 25); samples per pixel; last pass time; ledger bytes per category and device free/total bytes (decision 14) |
| `ar_settings` | output size, resolution percentage and border (final); samples and viewport sample limit (0004 D25); adaptive threshold and min samples (0004 D16); bounce limits total/diffuse/glossy/transparent/transmission/volume and min bounces (0004 D2-D3); seed and animated-seed flag (0003 decision 23); direct and indirect clamp, Filter Glossy, reflective and refractive caustics toggles (0004 D17); pixel filter type and width (0008 decision 5); film exposure and film transparent (0008 decisions 7, 19); working-space interop id (0003 decision 15); requested passes, light-group count, shader AOV names, Cryptomatte levels and types (0008 decisions 10-11); response channels as copy-in curves with unit ENERGY/PHOTON, cube bins, exposure time and collecting area (0008 decisions 7, 9); denoise start sample (0008 decision 18); allow_spill (decision 14) |

## Geometry, images, volumes

| Descriptor | Fields |
|---|---|
| `ar_mesh_desc` | key u64, vertex_count V, corner_count C, face_count F, uv_layer_count U, motion_steps S (1 unless deformation blur), flags u32 (`AR_MESH_HAS_MATERIAL_INDEX`, `AR_MESH_HAS_ATTRIBUTES`), attribute_count A, pad, name u8[64], `attributes` (copy-in `ar_attribute_desc[A]`: name u8[32], domain `AR_DOMAIN_POINT`/`CORNER`/`FACE`, width 1-4). `ar_mesh_buffers` (engine-written counts, then staged arrays in this order): positions f32 S×V×3, corner_vert i32 C, face_start i32 F, corner_normals f32 C×3, uv f32 U×C×2, material_index i32 F (count 0 without `HAS_MATERIAL_INDEX`), attributes f32 (one concatenated array in attribute-list order, each attribute V, C or F entries of its width by domain) |
| `ar_positions_buffers` | for `ar_edit_positions_begin` (decision 22), written by the engine for the key's existing V, C and S: positions_count u64 and corner_normals_count u64, then staged positions f32 S×V×3 and corner_normals f32 C×3 |
| `ar_instances_desc` | instance_count N, motion_steps S, transform_count (must equal N×S), material_key_count; copy-in arrays: geom_keys `ar_key[N]`, xf `ar_xform[N×S]` (instance-major), object_keys `ar_key[N]`, random_ids u32[N], pass_indices u32[N], crypto_objects u32[N], crypto_assets u32[N] (MurmurHash3 of the object and asset names, computed by the addon, which also writes the manifest; 0008 decision 11), colors `ar_rgba[N]`, visibility u32[N], flags u32[N], light_groups u8[N] (0008 decision 10), material_offsets u32[N] and material_counts u32[N] (instance i uses material_keys[material_offsets[i] .. +material_counts[i]); instances may share a table, i.e. the same offset; count 0 means the default material; a face's material_index must be < material_counts[i] for every instance using that mesh, else the commit fails loudly), material_keys `ar_key[material_key_count]` (the pool). Visibility bits (`AR_VISIBILITY_*`, mapped onto 0002 D11's instance mask): camera, diffuse, glossy, transmission, shadow, volume. Instance flag bits (`AR_INSTANCE_*`, a separate `flags` word, read in shading or by the light pass, never mask bits): holdout, shadow catcher, caustic-caster opt-out (0004 D19). No light or shadow linking sets (ruling 45). |
| `ar_curves_desc` | key, P points, K curves, type (linear/Catmull-Rom/B-spline); [positions f32 P×3, radius f32 P, curve_start i32 K, attributes] |
| `ar_points_desc` | key, P; [positions f32 P×3, radius f32 P, attributes] |
| `ar_grid_desc` | key, grid name, channels 1/3, background value, index-to-object 3×4, object-to-world 3×4 (ruling 43), leaf count n; [leaf origins i32 n×3, voxels f32 n×512×channels]; one call per batch, batches of one grid append (leaf format and engine representation: 0006 D5) |
| `ar_image_desc` | key, source FILE (UTF-8 path) / MEMORY (packed bytes, copy-in) / PIXELS (f32 RGBA, staged), colour interop id, alpha mode, UDIM tile number, width, height |

## Shading, lights, world, camera, astrophysics

| Descriptor | Fields |
|---|---|
| `ar_graph_desc` | node count, [op nodes {op u16, param range}], [param pools f32, i32, UTF-8 strings], [links {from node, socket, to node, socket}] (decision 8; ops 0005 item 30); the target SURFACE/VOLUME/DISPLACEMENT/LIGHT/WORLD is the call's argument |
| `ar_material_desc` | graph keys for SURFACE, VOLUME, DISPLACEMENT (0 = none); ext_kind and its 64 B constant block (0005 items 14, 16); medium_priority u8 (0005 item 2a); pass_index u32 (IndexMA) and crypto_material u32 (MurmurHash3 of the material name, as for objects) (0008 decisions 10-11); emission sampling setting (0005 item 43); bump-correction setting (0005 item 8); displacement method (0005 item 37) |
| `ar_light_desc` | color `ar_spectrum_ref`, graph key u64 (0 = none), xf `ar_xform`, type u32 (`AR_LIGHT_POINT`/`SPOT`/`SUN`/`AREA_RECT`/`AREA_ELLIPSE`), visibility u32 (`AR_VISIBILITY_*`), size_x, size_y, spot_size, spot_blend, sun_angle, spread, power (all f32), normalize u32, cast_shadow u32, light_group u32 (0008 decision 10). Size meaning by type: POINT radius = `size_x` (`size_y` ignored); SPOT radius = `size_x`; SUN none (`sun_angle` is the disc); AREA_RECT `size_x` × `size_y` metres; AREA_ELLIPSE `size_x` × `size_y` are full extents (diameters), like AREA_RECT and Blender's lamp size, and the engine halves them into the ellipse record's radii; equal sizes are a disk (no separate disk type). Power is in W, or W/m² for the sun, exposure applied, passed through unscaled (0003 decision 11). |
| `ar_spectrum_ref` | kind u32 (`AR_SPECTRUM_RGB`/`BLACKBODY`/`TABLE`, the host-authored kinds of 0005 item 9), table_count n, rgb f32[3], temperature K f32, scale f32, pad, copy-in table_wavelength_nm f32[n] and table_value f32[n] (used only for TABLE, otherwise n must be 0); the core packs it into 0005's 24 B `SpectrumRef` with the slot's semantic (ILLUMINANT for lights, 0005 item 10). IES profiles cross in the light's graph (0005 item 41) |
| `ar_world_desc` | graph keys for WORLD and VOLUME; light_group u8; mist start, depth and falloff (0008 decision 10) |
| `ar_camera_desc` / `ar_view_desc` | type PERSP/ORTHO/PANO, cam_to_world, projection_inverse 4×4 (NDC to camera space, taken from Blender), near/far, DOF (fstop, focus distance, blades, rotation, ratio), panorama params, shutter open/close + motion steps; view adds region w/h, render scale, border |
| `ar_astro_desc` | astro_kind (BLACK_HOLE), xf (spin axis = local +z), mass, spin a, meters_per_rg (0006 D25); θ_tol and ε_NEE overrides for science renders, 0 = default (0006 D25, D28). No camera velocity exists anywhere in the ABI, so the camera is at rest in the hole's static frame (decision 41, 0006 D24) |
