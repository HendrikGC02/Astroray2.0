# Setting up a machine

Reader: the owner and the lead on a PC that has only a fresh clone. Versions are the ones the scripts
check; where a script enforces one, it is named. Rules for machines that are not the reference machine:
owner decision 47.

## 1. Install, in this order
1. Git, GitHub CLI (`gh auth login`; `land.ps1` and `status.ps1` use it), PowerShell 7 (`pwsh`).
2. Visual Studio 2022 Build Tools 17.14 with "Desktop development with C++" **and the MSVC v14.44 toolset
   component** (`tools/lib/msvc.ps1` calls vcvarsall with `-vcvars_ver=14.44`; `cmake/toolchain.cmake`
   requires `cl` 19.44). A newer toolset alone does not satisfy it.
3. CUDA Toolkit 12.8 (`find_package(CUDAToolkit 12.8 REQUIRED)`, `cmake/kernels.cmake`). The default preset
   `dev` builds the GPU side, so even `check fast` needs it.
4. CMake 3.31 or newer and Ninja 1.13.x on PATH (`cmake/toolchain.cmake` refuses another Ninja).
5. NVIDIA driver R590 or newer (OptiX 9.1; `src/host/device_probe.cpp` refuses the GPU below it).
6. Blender 5.3, then the user variable the tools read (its bundled Python runs every tool; no other
   Python and no pip packages are needed locally):
   `[Environment]::SetEnvironmentVariable('ASTRORAY_BLENDER', '<folder that holds blender.exe>', 'User')`
7. Optional: Nsight Systems (only `perf.ps1 -Shares`).
Disk: allow 60 GB (build trees, Blender profiles, the scenes cache under `%LOCALAPPDATA%\astroray2`).
OptiX needs no SDK install: `fetch.ps1 deps` downloads the headers.

## 2. From a clone to a green fast check
Clone to the same path as the reference machine if possible (`C:\Astroray2.0`); nothing tracked depends
on it, but old notes quote it. In a new shell:
```
pwsh tools/fetch.ps1 deps
pwsh tools/fetch.ps1 assets
pwsh tools/fetch.ps1 refs
pwsh tools/build.ps1
pwsh tools/check.ps1 fast
```
`deps` (Embree, OIDN, OptiX headers; SHA-256 pinned) must run before the first build. `assets` fetches
the Cornell box and the HDRI the gallery and `check full` use (owner decision 43). `refs` fetches the
read-only reference sources lobe tasks cite (pbrt-v4, Cycles, OpenPBR; owner decisions 43, 46).

## 3. What a machine other than the reference machine must know
The reference machine is the desktop, id `rtx5070ti-8c16t`. Until task 268 lands:
- **GPU architecture:** `build.ps1` reads the GPU's compute capability from `nvidia-smi` and builds the kernels
  for it (`ASTRORAY_CUDA_ARCH`: 75, 86, 89 or 120; task 267). On a GPU that is not sm_120 it also builds an sm_120
  set, compile-only, that the resource gate checks; the native rows are printed as recorded. A build made for
  another architecture is refused at device creation with "built for sm_X, device is sm_Y: rebuild". Below sm_120
  the kernels compile with far larger stacks and spills (0001 V13's note), so expect slower passes than the ratio
  of the GPUs suggests.
- **Timing budgets were measured on the reference machine** (B-05, B-08, B-09, B-10, B-12 and the bench
  rows). A red B-08 or B-12 in `check fast` on a slower machine is expected until task 268 lands; say so,
  never edit a limit (decision 47 f). Correctness failures mean what they always mean.
- **Bench lines:** `bench/history/2026.jsonl` is keyed by machine id; `check perf` prints "no baseline" on
  a new id until the lead records one on a quiet machine (`perf.ps1 -Record`). Four tools write the
  reference id as a literal (`hero_variance.py`, `light_build_bench.py`, `region_bias.py`,
  `welch_tiles.py`): do not commit a history line they write on another machine before 268.
- **VRAM:** allocation needs 2 GiB of free reserve (0007 d14). B-5M and 4K viewport work may be refused on
  the laptop's 8 GB card; report it, it is not a defect.
- **Landings:** `land.ps1` runs from the task's worktree, so 268 lands through its own machine-aware tools. Hosted `ci` and the `astroray/gate` status stay required.

## 4. What is not in the clone
Regenerated by scripts: `third_party/_cache` (`fetch.ps1 deps`, `refs`), `assets/_cache` (`fetch.ps1
assets`), `out/build` and `out/bin` (`build.ps1`), `out/scenes` (`tools/scenes.py`, run by the gate),
`out/gallery` (`tools/gallery.py --milestone M`), `out/report` (`tools/report.py`), the scenes cache and
denoise references (first use; about 15 s to minutes each).
Left on the reference machine: its agent worktrees and scratch branches; `out/evidence` and
`out/land-evidence` (images the leads viewed); the eighth lead's side-session notes (their rulings R1-R12
are in the task files). Carried in the repository instead: the landing history to the M1b close
(`docs/retro/land-history-rtx5070ti-8c16t.jsonl`; a new machine starts its own `out/land/history.jsonl`),
branch `task/235-d2-cpu-cuda-colour-mismatch` (the coincident-pair finding), `keep/120-graphs-B`.
A worktree has no `assets/_cache`: until task 245 lands, copy the main checkout's `assets/_cache` into
any worktree that renders assets, or the HDRI renders magenta without a failure (BACKLOG).

## 5. Starting the lead session
Open the clone in Claude Code and say: "You are the lead. Read CLAUDE.md, docs/LEAD.md (the latest
handover), docs/STATUS.md and tasks/README.md, then continue." Agent definitions, the `land` skill and
the permission rules are tracked under `.claude/`; nothing else carries over between machines.
