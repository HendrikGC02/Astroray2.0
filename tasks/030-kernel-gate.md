# 030 Kernel resource gate, compile timing and `tools/check.ps1 gate`
Goal: GPU work has no merge gate -> `check gate` builds dev and nofma, checks every capped cubin's spills, stack and launch bounds against `budget.toml`, times the changed device TUs serially, runs the ABI, dependents, CPU-gate and GPU-gate tests, and fails above B-09.
Read first: 0002 D10 (budgets, what the gate measures, growth rule), D8 verification (every kernel in both tables), D9 (launch bounds (256,2)); 0009 d11 (`gate` contents), d18 (resource gate, compile timing), B-05, B-06, B-09; 0001 V5 (dependents, first part).
Scope: src/kernel/launch_config.h, src/kernel/budget.toml, tools/kernelgate.py, tools/check.ps1 (tiers `gate` and `ci`), tests/budgets/kernelgate_cases/, tools/README.md.
Out of scope: work counters and the timing tripwire (B-16, added by 045 and 076 when the scheduler and scenes exist); the Blender smoke (084); `full` (later tasks add their steps; the probe build warning is added here as a `full` step).
Reference: CUDA binary utilities documentation (`cuobjdump -res-usage`) and ptxas `-v` output format.
Do:
1. launch_config.h: one row per CUDA kernel and OptiX program: name, threads T, min blocks B (0 = none), shadow items per item k, stack class (`VM` or `OTHER`); the `AR_LAUNCH_BOUNDS(T,B)` macro compiles out when `AR_LAUNCH_BOUNDS=0`. budget.toml: per kernel `regs`, `stack`, `spill_store`, `spill_load`, `compile_s`, `gated` (`merge` or `full`); defaults from 0002 D10 (spills 0, VM kernels <= 128/192 B, stack VM 512 B / other 128 B).
2. tools/kernelgate.py: reads each capped cubin's `cuobjdump -res-usage` and its .ptxas.txt; fails when a kernel exceeds 65536/(T*B) registers (B set), its spill allowance or its stack class, when growth exceeds +5% registers (no B) or +10% stack against budget.toml unless the same diff edits that row, or when any `k_*` kernel in a cubin, or any OptiX program, lacks a row in launch_config.h or budget.toml. Prints each kernel's delta next to the task's declared delta (passed with `--declared`).
3. Compile timing (B-05): changed TUs = TUs whose source or depfile headers (`ninja -t deps`) differ from origin/main; time at most the three with the largest `compile_s`, each one serial nvcc call with no cache; a result within 10% of 3.0 s is re-timed and the minimum of three kept; never read `.ninja_log`.
4. check.ps1 `gate` (machine lock): `fast`; `build.ps1` (dev, all, plus `astroray_kernels_gpu_nofma`); kernelgate; compile timing; `tests/abi` unittest discovery; `dumpbin /dependents` on astroray_core.dll and astroray_cli.exe must list only system DLLs (fail on vcruntime*, msvcp*, tbb*, nvcuda*, cudart*); `astroray_tests_cpu --tier=gate`; `astroray_tests_gpu --tier=gate`; totals against B-09 (180 s) and the kernel part against 120 s. Add a `full` tier that runs `gate` plus the probe build with uncapped register warnings at 150 (loud above 168), never failing on them. Every gate step is declared with a tag, `cpu` (needs neither a GPU nor Blender) or `local`; tier `ci` now runs `fast`, the cpu-preset build and gate's `cpu` steps, replacing 009's explicit list, so each CPU gate step a later task adds (tests, analytic scenes on CPU) reaches hosted CI; later tasks tag every step they add.
5. tests/budgets/kernelgate_cases/: recorded ptxas and cuobjdump text for a kernel within budget, one with an extra live array that adds spills under (256,2), one missing from budget.toml; `kernelgate.py --self-test` expects pass, fail, fail (0009 Verification row 18, first part).
Acceptance: `pwsh tools/check.ps1 gate` prints `PASS gate <s> s (budget 180 s, ...)`; `<python> tools/kernelgate.py --self-test` prints 3 cases with the expected results; a local edit raising selftest's stack beyond its row makes `check gate` FAIL naming the kernel; `pwsh tools/check.ps1 ci` with `$env:CI='true'` lists the `cpu` steps it ran.
