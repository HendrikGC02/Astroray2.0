# Task files for M2 (lobes, shadows and media)

Scope: docs/ROADMAP.md, M2; plan, slices and lanes: docs/PLAN-M2.md; items without a task: docs/BACKLOG.md; a new machine: docs/SETUP.md. M1b closed (owner decision 47); its batches, collision lists and gate ledger are docs/history/M1b-task-ledger.md. One file per task, `tasks/NNN-slug.md`, <= 60 lines, fields in this order (lint section `taskfile`): Goal, Read first, Scope, Out of scope, Reference, Do, Acceptance, Look at, Canary, Budget, Depends on, Size, Progress. `land` deletes a task file when it lands. Numbers are ids, not order.
The lead writes the next batch at each slice review, from what the slice measured, with a scope pre-flight per task: grep the call sites, registration lists, budget rows and tests the change forces, and name them in Scope.
Scope lines name what a change forces (its budget and counter rows, registration lists, existing tests it breaks). CMake globs sources: a new file under a globbed directory edits no CMake; a new target does. Gate steps are tagged `cpu` or `local`; hosted `ci` runs the `cpu` ones.
Measurement tasks follow docs/PLAN-M1b.md section 5 (kept by docs/PLAN-M2.md section 6): metric and command, quiet machine, a decision table written before measuring, their own bench/history line, limits changed listed for the owner. At most two remedy tasks per budget row, then the owner decides.
Size counts source lines without tests: S under 150, M 150-500, L 500-1000. Canary line: `tasks/NNN.canary.patch must turn red: astroray_tests_cpu "suite/case", tests/x/test_y.py "Class.method"`.
