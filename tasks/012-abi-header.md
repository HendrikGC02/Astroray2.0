# 012 astroray.h, its grammar checker and the ABI hash
Goal: there is no C ABI -> `include/astroray/astroray.h` holds the identity, context, device, last-error and report declarations in 0001's restricted grammar, and `tools/abigen.py` rejects anything outside the grammar with file and line and computes `AR_ABI_HASH`.
Read first: 0001 D2.1 (handles, context and device structs), D2.2-D2.4 (types, arrays, no callbacks), D2.7 (hash, identity functions), D2.10 (grammar, annotations), D2.11 (report structs, levels, codes table), R10, R33.
Scope: include/astroray/astroray.h, tools/abigen.py, tests/abi/bad_headers/, tests/abi/test_abigen.py, CMakeLists.txt (custom command running abigen at build).
Out of scope: generated bindings, layout table and exports (013); scene, session and edit functions (031); recorder (033).
Reference: none (grammar from 0001; SHA-256 from Python's hashlib).
Do:
1. Header forms exactly as D2.10, with two clarifications applied by this task: (a) one fixed prelude block defining `AR_API` (dllexport when `AR_BUILDING_CORE` is defined, else dllimport), `AR_QUERY`, `AR_IN`, `AR_OUT`, `AR_IN_ARRAY(n,T)`, `AR_OUT_ARRAY(n,T)`, `AR_STAGED(n,T)` as empty macros; abigen holds this block as a constant `PRELUDE` and accepts it only byte-identical; (b) `typedef uint32_t ar_status;` is allowed beside `typedef uint64_t ar_key;` because D2.10's prototype form returns `ar_status`.
2. Declarations now: status codes `AR_OK 0`, `AR_ERR_INVALID_ARGUMENT 1`, `AR_ERR_UNSUPPORTED 2`, `AR_ERR_DEVICE 3`, `AR_ERR_OUT_OF_MEMORY 4`, `AR_ERR_ABI_MISMATCH 5`, `AR_ERR_INTERNAL 6`; handles `ar_context`, `ar_scene`, `ar_session`, `ar_edit`; `AR_DEVICE_CPU`, `AR_DEVICE_CUDA`; structs `ar_context_desc`, `ar_device_info` (fields of D2.1), `ar_build_record` {version u8[32], git_sha u8[48], dirty u32, pad, cuda u8[16], optix u8[16], embree u8[16], oidn u8[16], build_type u8[16], kernel_source u8[264]}, `ar_struct_layout` {name u8[64], size u32, align u32, field_count u32, field_offset u32[128]} (abigen fails if a struct has more than 128 fields), `ar_report_entry`, `ar_report_info` (exactly D2.11); levels `AR_LEVEL_*`; every report code of D2.11's table as `AR_REPORT_<NAME>` numbered from 1 in table order.
3. Functions now: `ar_abi_hash(AR_OUT uint64_t*)`, `ar_abi_layout_count(AR_OUT uint32_t*)`, `ar_abi_layout(uint32_t index, AR_OUT ar_struct_layout*)`, `ar_build_info(AR_OUT ar_build_record*)`, `ar_device_count`, `ar_device_get_info`, `ar_context_create`, `ar_context_destroy`, `ar_context_last_error(ar_context, uint32_t capacity, AR_OUT_ARRAY(capacity, uint8_t) uint8_t* text)`; identity, device and last-error functions are `AR_QUERY`.
4. tools/abigen.py (stdlib): parses the header, enforces D2.10 (forms, one annotation per pointer, array counts naming an integer parameter or field of the same call or struct, `ar_status` returns, `uint8_t` only as fixed arrays, naming `ar_<object>_<verb>` / `ar_<name>` / `AR_<NAME>`, no bool, enum types, unions, bitfields or function pointers) and prints `file:line: message`; `--hash` prints AR_ABI_HASH = first 8 bytes (big-endian) of SHA-256 over the header with comments removed and whitespace runs collapsed to one space.
5. CMake runs `abigen.py --check include/astroray/astroray.h` as a build step whose failure fails the build.
6. tests/abi/bad_headers/: one fixture per rule above (at least 10); tests/abi/test_abigen.py (unittest): each fixture fails with its expected message; the real header passes; changing only one parameter type changes the hash (0001 V1, generator part).
Acceptance: `pwsh tools/build.ps1` passes; `<python> -m unittest discover -s tests/abi -p "test_abigen.py"` passes with one test per fixture; `<python> tools/abigen.py --hash include/astroray/astroray.h` prints 16 hex digits; `pwsh tools/check.ps1 fast` passes.
