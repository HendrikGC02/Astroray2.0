# 018 Kernel dialect: portability.h, Real, CPU kernel flags and the kernel lints
Goal: nothing constrains kernel code -> `src/kernel/portability.h` is the only target-aware file, `Real` switches between float and double, CPU kernel code compiles with the dialect's flags, and lint enforces banned constructs, the include allow-list and the vendor seam.
Read first: 0002 D1 (allowed and forbidden constructs, passing rules), D2 (portability header contents), D3 (Real), D12 (production CPU flags); 0001 D5.2 and V3 (vendor seam, include rule); R39.
Scope: src/kernel/portability.h, src/kernel/core/real.h, cmake/kernels.cmake (CPU part: `astroray_kernel` INTERFACE target, CPU stage libraries and f64 test copies below), cmake/sources.cmake, tools/lint.py (sections `kernel`, `seam`), tests/cpu/lint_cases/kernel/, tests/cpu/lint_cases/seam/, tests/cpu/test_portability.cpp.
Out of scope: GPU compile rules (027); any stage (043 onward); spectral types (019).
Reference: Cycles `kernel/device/cuda/compat.h` (Apache-2.0) and pbrt-v4 `src/pbrt/pbrt.h` `PBRT_CPU_GPU` (Apache-2.0) as patterns only.
Do:
1. portability.h exactly per 0002 D2: `AR_FN`, `AR_GPU`, `AR_ASSERT` (compiled out unless `AR_DEBUG`), `ar::load_ro`, `ar::atomic_add` (float, uint32_t), `ar::atomic_max` and `ar::atomic_cas` (uint32_t), `ar::clock`, `ar::ballot`, `ar::lane_id` (single-lane CPU fallbacks), `ar::bit_cast`, math wrappers overloaded on float and double (`sqrt`, `exp`, `expm1`, `log`, `sin`, `cos`, `tan`, `atan2`, `acos`, `asin`, `pow`, `fma`, `abs`, `min`, `max`, `floor`, `ceil`, `cosh`). CPU side uses `<cmath>` and `<intrin.h>` only inside this file; the GPU side uses nvcc built-ins without includes.
2. src/kernel/core/real.h: `using Real = double` when `AR_REAL_DOUBLE` is defined, else float; `AR_REAL_NS` is `f64` or `f32`, and `AR_NS_BEGIN`/`AR_NS_END` open and close `namespace ar { inline namespace AR_REAL_NS {`. Every kernel header wraps its declarations in them, so the float and double builds of one header link into one executable as distinct symbols instead of being silently merged (one-definition rule). `AR_RT_CASE("name")` is a doctest case named `name`, or `name f64` in the double copy.
3. cmake/kernels.cmake: `astroray_kernel` INTERFACE (include dir src/kernel); `ar_kernel_cpu_flags(target)` adds `/EHs-c- /GR- /fp:precise /arch:AVX2 /O2` (no `/fp:contract`); by 003's source rule src/kernel_cpu/*.cpp go into STATIC `astroray_kernels_cpu` and `astroray_kernels_cpu_f64` (the latter with `AR_REAL_DOUBLE`), both created when the first file exists (task 043); a test file whose first 5 lines contain `// ar-f64` is compiled a second time with `AR_REAL_DOUBLE` into the same test executable.
4. lint section `kernel` over src/kernel/**: banned tokens (virtual, throw, try, catch, new, delete, malloc, free, `std::` containers and algorithms, `#include` other than `<cstdint>`, `<cfloat>` and quoted kernel headers, `__noinline__`, `long double`, `thread_local`, `static` non-const variables at namespace scope, `printf` outside `#ifdef AR_DEBUG`, `asm`), direct `<cmath>`/`std::` math calls outside portability.h, and unsuffixed floating literals not written as `Real(...)`, `float(...)` or `double(...)` arguments; every header except portability.h and real.h opens `AR_NS_BEGIN`.
5. lint section `seam` (0001 V3): includes matching `cuda`, `optix`, `nvrtc` or `embree` only under src/device/, src/kernel_gpu/ (and NGX only under src/denoise/dlss/); `nvrtc` nowhere.
6. Lint cases: one violation per banned item and a clean case, per section. tests/cpu/test_portability.cpp (suite fast, marked `// ar-f64`) checks the CPU wrappers for float and double, `ar::atomic_max` semantics, and `portability/f32 f64 distinct`: an inline `ar::real_bytes()` called from both copies returns 4 and 8 in one executable (without the inline namespace the linker keeps one copy and the case fails).
Acceptance: `pwsh tools/check.ps1 fast` passes; `<python> tools/lint.py --self-test` covers `kernel` and `seam` with at least 12 cases; adding `#include <vector>` to portability.h makes lint fail naming the file and line.
